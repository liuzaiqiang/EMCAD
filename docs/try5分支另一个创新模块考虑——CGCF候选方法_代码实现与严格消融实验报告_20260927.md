# CGCF 候选方法：代码实现、启动参数与严格消融实验报告

日期：2026-09-27  
当前分支：`base_cgc_try5AnotherModule`  
候选方法：Correlation-Gated Complementary Fusion（CGCF，相关性门控互补跳连融合）

> 本文档描述的是“待验证方法”。当前只完成代码接入和静态检查，没有完成 Synapse 或 ACDC 正式训练，因此不能声称 Dice 已提升。

## 1. 已完成什么

本次改动把 CGCF 接入现有 EMCAD decoder 的三处跳连融合点：`LGAG -> CGCF -> CAB/SAB/MSCB`。

原始 EMCAD 在三处使用：

```text
d3 = d3 + x3
d2 = d2 + x2
d1 = d1 + x1
```

其中：

- `d3/d2/d1` 是 decoder 特征；
- `x3/x2/x1` 是经过 LGAG 空间门控后的 encoder skip 特征；
- 两者形状相同，均为 `[B,C,H,W]`；
- 相加后继续进入原有 CAB、SAB、MSCB 和四个输出头。

CGCF 只替换上面三处相加，不改变 EMCAD encoder、decoder 的其他模块、四个 segmentation head、loss、metric、数据划分或 checkpoint 选择流程。

Synapse 训练入口原本还有一个实验目录 tuple 传给 `os.path.join` 的错误。本次做了最小路径构造修复，使 baseline 和所有 CGCF 对照使用相同的新路径逻辑。使用旧路径命名产生的历史结果不能未经核对就与新目录结果直接比较；正式比较必须重新运行或明确证明训练协议完全相同。

## 2. 用一个直观例子理解 CGCF

### 2.1 原始跳连的问题

在同一个像素位置，decoder 已经表达了某个结构方向，skip 也可能重复表达同一个方向。原始相加是：

```text
f_original = d + x
```

如果 `x` 与 `d` 很相似，相加会放大重复响应；如果 `x` 与 `d` 互相补充，直接相加是有益的。问题在于普通相加无法区分这两种情况。

### 2.2 CGCF 的三个步骤

对每个像素位置，沿通道维度计算两个特征的关系。

**第一步：通道方向归一化**

```text
d_hat = d / sqrt(sum_c(d*d) + eps)
x_hat = x / sqrt(sum_c(x*x) + eps)
```

**第二步：计算像素级相关性**

```text
c = sum_c(d_hat * x_hat)       # [B,1,H,W]，范围约为 [-1,1]
r = sigmoid(T * (c - tau))      # [B,1,H,W]
```

`c` 越大，说明该像素的 skip 和 decoder 越同向；`r` 越大，说明越应该抑制重复内容。`T` 是可学习温度，`tau` 是可学习阈值。三处尺度共享这两个标量，避免把同一种机制重复计为三个独立模块。

**第三步：只扣除 skip 中与 decoder 平行的部分**

```text
p = sum_c(x * d_hat) * d_hat    # skip 在 decoder 方向上的投影
x_comp = x - r * p
f_cgcf = d + x_comp
```

CGCF 保留 `x` 的互补方向，只减少与 `d` 平行且相关性较高的部分。

### 2.3 数值例子

把某个像素的通道特征简化成二维向量：

```text
d = [1, 0]
```

情况 A：skip 与 decoder 几乎同向。

```text
x = [0.9, 0.1]
c ≈ 0.994
```

使用初始 `T=4`、`tau=0.5` 时，`r≈0.88`。CGCF 会扣掉 `x` 中约 88% 的 decoder 平行分量，避免重复响应被直接放大。

情况 B：skip 提供互补方向。

```text
x = [0, 1]
c = 0
```

此时投影 `p=0`，即使门控值较低，`x` 的垂直互补信息仍然完整保留，输出仍接近 `d+x`。

这只是解释模块行为的数值例子，不是实验结果，也不代表 Dice 一定提升。

## 3. EMCAD 中的实际张量路径

以 PVTv2-B2、输入 `224×224` 为例：

| 融合点 | decoder `d` | LGAG 输出 `x` | CGCF 输出 |
|---|---|---|---|
| `d3` 与 `x3` | `[B,320,14,14]` | `[B,320,14,14]` | `[B,320,14,14]` |
| `d2` 与 `x2` | `[B,128,28,28]` | `[B,128,28,28]` | `[B,128,28,28]` |
| `d1` 与 `x1` | `[B,64,56,56]` | `[B,64,56,56]` | `[B,64,56,56]` |

CGCF 不改变通道数和空间尺寸，所以后续 `CAB -> SAB -> MSCB`、四个输出头和原有监督接口不需要重写。

完整调用顺序是：

```text
EMCAD encoder
  -> EUCB
  -> LGAG
  -> CGCF（可关闭）
  -> CAB/SAB/MSCB
  -> 四个 segmentation heads
  -> 原有 supervision/loss/metric
```

## 4. 与 try5 像素级可靠性多头融合的关系

try5 的像素级可靠性多头融合处理四个全分辨率 logits；CGCF 处理 decoder 内部的 `[B,C,H,W]` 特征。两者的作用对象和执行位置不同：

```text
encoder -> decoder(LGAG -> CGCF) -> 四个输出头 -> logits
                                               -> try5 像素级可靠性融合
```

本分支当前没有复制 try5 的 `fusion_mode`、可靠性头或融合辅助损失，因此没有改动 `fuse_outputs()`、四头组合、可靠性图或推理取头逻辑。未来合并两个模块时，保留两组独立开关：

```text
--cgcf_mode {off,gate_only,parallel_only,cgcf}
--fusion_mode {p1,fixed_sum,global_scalar,pixel_reliability}
```

应先分别完成单模块实验，再做组合实验。若 CGCF 和可靠性融合同时打开，整体变化不能直接归因给其中任意一个模块。

## 5. 模式和参数

| `cgcf_mode` | 实际融合 | 用途 |
|---|---|---|
| `off` | `d+x` | 原始 EMCAD baseline；不开启 CGCF 参数 |
| `gate_only` | `d+(x-r*x)` | 只检验相关性门控是否有用 |
| `parallel_only` | `d+(x-p)` | 只检验平行分量扣除是否有用 |
| `cgcf` | `d+(x-r*p)` | 完整候选方法 |

新增参数：

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `--cgcf_mode` | `off` | 选择 baseline、机制消融或完整 CGCF |
| `--cgcf_temperature` | `4.0` | `T` 的初始值；训练中以 `exp(log_temperature)` 保证为正 |
| `--cgcf_threshold` | `0.5` | `tau` 的初始值；训练中可学习 |

`d3/d2/d1` 共享一个 `CorrelationGatedComplementaryFusion` 实例，完整 CGCF 只新增两个可学习标量。`parallel_only` 不使用门控分支；`gate_only` 不使用方向投影分支。

## 7. 如何把参数加入现有 `.sh`

所有脚本都应使用 `"${VAR:-default}"`，这样可以在命令前临时覆盖参数。加入参数后，训练和测试必须使用相同的 `mode/temperature/threshold`。

### 7.1 Synapse 训练：`sh/start_train_synapse.sh`

在 `SUPERVISION`、`BASE_LR` 定义附近加入：

```bash
CGCF_MODE="${CGCF_MODE:-off}"
CGCF_TEMPERATURE="${CGCF_TEMPERATURE:-4.0}"
CGCF_THRESHOLD="${CGCF_THRESHOLD:-0.5}"
```

在现有 `python -u train_synapse.py` 命令中，放在 `--supervision "${SUPERVISION}" \` 后面、日志重定向前面：

```bash
  --cgcf_mode "${CGCF_MODE}" \
  --cgcf_temperature "${CGCF_TEMPERATURE}" \
  --cgcf_threshold "${CGCF_THRESHOLD}" \
```

如果命令最后一项是 `--supervision ... \`，三个新参数必须紧接在后面；最后一个参数后再接 `>> "${LOG_FILE}" 2>&1 < /dev/null &`。

当前工作区中的 `start_train_synapse.sh` 在 `set -u` 下还把 `LIST_DIR`、`ROOT_PATH`、`VOLUME_PATH` 和旧的 `FUSION_MODE/FUSION_LOSS_WEIGHT/RELIABILITY_LOSS_WEIGHT` 放进了 `PARAM_NAMES`，但这些变量没有全部定义。远程启动前应删除未使用的名字，或给它们定义默认值；否则脚本可能在打印参数阶段退出，尚未进入 Python。

运行示例：

```bash
# baseline
CGCF_MODE=off bash sh/start_train_synapse.sh

# 完整 CGCF
CGCF_MODE=cgcf CGCF_TEMPERATURE=4.0 CGCF_THRESHOLD=0.5 bash sh/start_train_synapse.sh
```

### 7.2 Synapse 测试：`sh/start_test_synapse.sh`

在 `IMG_SIZE`、`DATASET` 附近加入同样三行：

```bash
CGCF_MODE="${CGCF_MODE:-off}"
CGCF_TEMPERATURE="${CGCF_TEMPERATURE:-4.0}"
CGCF_THRESHOLD="${CGCF_THRESHOLD:-0.5}"
```

在 `python test_synapse.py` 命令中加入：

```bash
  --cgcf_mode "${CGCF_MODE}" \
  --cgcf_temperature "${CGCF_TEMPERATURE}" \
  --cgcf_threshold "${CGCF_THRESHOLD}" \
```

这些值必须和训练 checkpoint 的目录后缀及模型结构一致。为了让 `test_synapse.py` 找到与训练完全相同的目录，测试脚本还应传入训练时的 `supervision`、`batch_size`、`max_epochs` 和 `base_lr`。

建议在测试脚本的变量区明确写出：

```bash
SEED="${SEED:-2222}"
SUPERVISION="${SUPERVISION:-mutation}"
BATCH_SIZE="${BATCH_SIZE:-16}"   # 必须与训练脚本相同
MAX_EPOCHS="${MAX_EPOCHS:-300}"  # 必须与训练脚本相同
BASE_LR="${BASE_LR:-1e-4}"       # 必须与训练脚本相同
```

并在测试命令中加入已有目录参数：

```bash
  --supervision "${SUPERVISION}" \
  --batch_size "${BATCH_SIZE}" \
  --max_epochs "${MAX_EPOCHS}" \
  --base_lr "${BASE_LR}" \
```

当前测试脚本的 `RUN_ID` 还写成了小写 `${seed}`，在 `set -u` 下会直接报未定义变量；应改成 `${SEED}`，或删去只用于 RUN_ID 的那一段。上述问题属于现有脚本启动和 checkpoint 路径问题，不是 CGCF 代码逻辑。

```bash
CGCF_MODE="${CGCF_MODE:-off}"
```


当前仓库文件名是小写 `test_acdc.py`，而现有脚本调用的是 `test_ACDC.py`。Linux 区分大小写，远程脚本应调用：

```bash
"${PYTHON_BIN}" -u test_acdc.py \
```

现有脚本还引用了未定义的 `${PYTHON_BIN}`；请在远程脚本中定义 `PYTHON_BIN="${PYTHON_BIN:-python}"`，或直接使用已激活环境中的 `python`。测试时必须显式传入训练所得的：

```bash

CGCF_MODE=cgcf bash sh/start_test_acdc.sh
```

`CKPT` 决定加载哪个 checkpoint，`CGCF_MODE` 决定如何重建 decoder；二者必须对应。

## 8. 严格消融方案

### 8.1 第一阶段：只检验完整 CGCF

先在 Synapse 和 ACDC 各运行：

| 组 | `cgcf_mode` | 只改变的因素 | 可回答的问题 |
|---|---|---|---|
| A0 | `off` | 原始 EMCAD | baseline 参考值 |
| A3 | `cgcf` | 只开启完整 CGCF | 完整 CGCF 相对 baseline 是否改善总体 Dice |

两组必须使用相同病例清单、预处理、输入尺寸、batch size、epoch、优化器、学习率、监督策略、seed、checkpoint 选择规则和评估实现。

### 8.2 第二阶段：机制消融

只有 A3 出现值得复核的改善后，再运行：

| 组 | `cgcf_mode` | 保留的机制 |
|---|---|---|
| A1 | `gate_only` | 相关性门控 |
| A2 | `parallel_only` | 平行分量扣除 |
| A3 | `cgcf` | 门控与互补投影组合 |

如果 A1 或 A2 已经达到 A3 的效果，论文主张应缩小到实际必要机制；不能把组合结果的全部收益都写成完整 CGCF 的必要性。如果 A3 没有稳定优于 A0，应报告负结果并停止继续堆叠。

### 8.3 seed 和结果记录

预先固定 seed，例如 `2222、3333、4444`，先完成 A0/A3 配对，再完成 A1/A2。不能根据测试结果挑选 seed。

每个 seed 至少记录：

```text
dataset, group, seed, cgcf_mode
cgcf_temperature_init, cgcf_threshold_init
cgcf_temperature_final, cgcf_threshold_final
best_epoch, checkpoint_absolute_path
patient_level_mean_dice
per_case_dice
per_organ_dice
HD95, ASD, Jaccard
```

Synapse 当前代码使用 `test_vol` 进行训练过程中的病例级评估并选择 checkpoint。由于这是现有 EMCAD 流程，baseline 和候选方法必须共同遵守；论文中应如实说明该评估口径，不能把它改称为独立 validation 集。

ACDC 使用现有 train/valid/test 流程：checkpoint 只由 valid 选择，最终 test 只在参数冻结后运行。
