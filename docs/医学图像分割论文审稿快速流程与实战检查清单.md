
# 医学图像分割论文审稿快速流程与实战检查清单

适用对象：医学图像分割相关会议审稿人，覆盖 U-Net、CNN、Transformer、Mamba、SAM、扩散模型、2D/2.5D/3D 分割论文。

本文回答三个问题：

1. 一篇论文应该先看哪里、再看哪里；
2. 如何在有限时间内发现真正影响结论的风险；
3. 如何写出具体、专业、对作者有帮助的审稿意见。

会议模板、评分项、利益冲突、双盲、保密和 rebuttal 规则以具体会议系统的最新要求为准。本文是通用工作流。

---

## 1. 审稿的核心目标

审稿不是判断网络名字是否新，也不是寻找越多问题越好。核心是判断：

- 论文是否提出了清楚且有意义的分割问题；
- 方法是否真正对应这个问题；
- 实验是否公平、充分、可复核；
- 结果是否在患者、类别和随机种子层面稳定；
- 结论是否没有超过证据。

把问题分成三层：

### 1.1 致命可信度问题

这些问题可能直接推翻论文结论：

- 训练、验证、测试存在患者级泄漏；
- 用测试集选择 best checkpoint、阈值或后处理；
- baseline 和 proposed 使用不同数据划分、输入尺寸或预训练；
- 指标计算口径无法复核；
- 论文和代码的实际模型不一致；
- 只运行一个 seed，却声称稳定提升；
- 关键强基线缺失。

### 1.2 主要科学问题

这些问题通常需要 major revision 或降低接收倾向：

- 创新点只是已有模块改名；
- 只有完整模型，没有必要消融；
- 只提升平均 Dice，没有解释小器官、边界和失败病例；
- 结论从单数据集推广到所有医学分割；
- 没有说明患者级划分、spacing 或评价粒度；
- 大幅增加参数和计算，却没有效率对照。

### 1.3 次要问题

包括图注、术语、格式、公式符号、表格单位、引用和语言。先处理前两层，再处理这些问题。

---

## 2. 推荐的审稿顺序

| 步骤 | 建议时间 | 先看什么 | 目的 |
|---|---:|---|---|
| 0 | 1 分钟 | 利益冲突、保密和审稿范围 | 确认可以审 |
| 1 | 3 分钟 | 标题、摘要、贡献、结论 | 抓住论文主张 |
| 2 | 5 分钟 | 方法总图、主结果表、可视化 | 判断贡献是否可能成立 |
| 3 | 8—12 分钟 | 核心模块、公式、输入输出 | 判断机制是否清楚且真正新 |
| 4 | 10—15 分钟 | 数据、划分、训练、baseline、消融 | 判断证据是否可信 |
| 5 | 5—10 分钟 | 指标、统计、失败案例、复杂度 | 判断结果是否完整 |
| 6 | 3—5 分钟 | 相关工作、局限、附录、代码 | 判断定位和可复现性 |
| 7 | 5 分钟 | summary、优点、主要问题、评分 | 完成审稿意见 |

第一次阅读不必逐行看公式。先做一遍全局判断，再只深入会改变结论的地方。

---

## 3. 第 0 步：利益冲突、保密和范围

先确认：

- 作者、单位或项目是否与你存在利益冲突；
- 论文是否属于你的审稿领域；
- 会议是否允许检查公开代码或外部文献；
- 是否有保密和禁止外传要求；
- 是否必须使用固定评分项。

不要把未公开论文内容带入公开讨论、社交平台、其他模型训练或自己的论文。审稿材料属于保密内容。

---

## 4. 第 1 步：只读标题、摘要和结论

读完后写一句话：

> 这篇论文针对 ______ 问题，提出 ______ 方法，在 ______ 数据集上通过 ______ 实验证明 ______。

如果写不出这句话，可能是贡献不清楚，也可能是你需要继续看方法图。此时不要急着判断创新。

先判断论文类型：

- 新网络结构；
- 新损失或监督策略；
- 2.5D、3D 或跨切片方法；
- 半监督、弱监督、自监督；
- 域适应或域泛化；
- 基础模型、提示分割或扩散模型；
- 数据集、标注或基准；
- 临床应用或部署。

不同类型需要不同证据。例如，新损失要看目标、梯度和损失权重；2.5D 要看相邻切片和患者级划分；临床论文要看外部验证和工作流。

---

## 5. 第 2 步：先看图和表

### 5.1 方法总图

方法图应回答：

- 输入是什么；
- encoder、decoder 和新增模块在哪里；
- 数据流方向是什么；
- 新模块作用于特征、logit、loss 还是后处理；
- 训练和推理是否使用同一路径；
- 模块位置是否真的对应论文所说的问题。

如果新增模块在输出之后，论文却声称它改善了特征提取，需要进一步核查。

### 5.2 主结果表

先看：

- 是否有原始 baseline；
- 是否有最接近的强基线；
- 是否使用多个数据集或任务；
- 提升是否跨类别、跨指标和跨 seed；
- 是否报告参数量、FLOPs 和时间。

不要只看最高 Dice。至少看 mean Dice、每类 Dice、HD95/ASD、失败病例和复杂度。

### 5.3 定性图

检查：

- 是否同时展示成功和失败案例；
- GT 与 prediction 的颜色是否清楚；
- 是否使用相同窗宽窗位和相同放大比例；
- 是否只挑选最有利的切片；
- 小器官、边界和细长结构是否真的改善；
- baseline 和 proposed 是否并列显示。

定性图不能替代定量指标，但能快速暴露“表中提升在视觉上并不存在”的情况。

---

## 6. 第 3 步：建立“问题—机制—证据”表

读方法时写三列：

| 论文问题 | 方法机制 | 应该提供的证据 |
|---|---|---|
| 小器官漏检 | 类别自适应监督 | 小器官 Dice、Recall、消融 |
| 边界模糊 | surface/boundary loss | HD95、ASD、Boundary F1 |
| 层间断裂 | 2.5D 或序列模块 | 体数据结果、连续性 |
| 多尺度冲突 | 跨尺度一致性 | 各阶段结果、特征分析 |
| 域偏移 | 域适应或归一化 | 未参与训练的外部域 |

如果问题、机制和证据无法对应，创新点可能只是模块堆叠。

### 6.1 检查新模块是否只是旧模块换名字

常见情况：

- SE、CBAM、空间注意力重新命名；
- 多尺度卷积分支加权被叫作动态路由；
- 普通 deep supervision 被叫作课程监督；
- logits 平均或求和被叫作不确定性建模；
- 边界损失或形态后处理被包装成全新几何推理；
- 仅改变模块位置就声称理论创新。

不要求每篇论文发明全新的数学运算，但要求作者说清：

- 新问题是什么；
- 与最接近工作哪里不同；
- 为什么该差异有效；
- 消融是否能证明收益来自该差异。

### 6.2 检查公式与实现逻辑

重点查：

- softmax、sigmoid、argmax 的维度；
- loss 作用于 logits、概率还是离散 mask；
- 插值发生在 logits 还是 argmax 后；
- 类别维和空间维是否混淆；
- 训练和推理是否走同一模块；
- 论文里的权重和阈值是否真的在代码中使用；
- 关键超参数是否被省略。

高频错误包括：

- 已经 softmax 后再次 softmax；
- 对离散标签使用双线性插值；
- logits 相加、概率相加和 mask 相加混为一谈；
- 二分类背景处理错误；
- 测试阶段使用训练标签生成的边界或 prompt。

---

## 7. 第 4 步：先查数据和划分

### 7.1 数据来源和预处理

确认：

- 数据集名称、版本、病例数和来源；
- 任务类别和标签定义；
- 标注者和标注方式；
- 是否使用公开预处理文件；
- 裁剪、重采样、归一化、窗宽窗位；
- 是否删除病例、类别或空切片；
- voxel spacing 是否保留。

### 7.2 患者级划分是第一要点

关键问题：

> 划分是在患者/病例级进行，还是在切片级随机进行？

如果同一患者的相邻切片出现在训练和测试中，结果可能严重高估。

检查：

- train、validation、test 清单；
- 同一病例名是否跨清单；
- 生成 2D 切片前是否先划分病例；
- 多模态图像是否同步划分；
- 交叉验证是否按患者分层。

论文只写“randomly split all images”而不说明病例级划分时，应提出主要问题。

### 7.3 测试集是否参与模型选择

检查是否存在：

- 每个 epoch 在 test 上评估；
- 用最高 test Dice 保存 best.pth；
- 在 test 上搜索阈值、后处理、输入尺寸或 loss 权重；
- 反复运行直到选出最好 seed；
- 看测试结果后再修改模型。

规范流程是：

- train：优化；
- validation：选 checkpoint、阈值和超参数；
- test：冻结方案后最终评估。

如果没有独立 validation，应说明如何从训练集划分，或承认结果是开发集评估。

### 7.4 统计单位

问清：

- 训练单位是切片、patch、体数据还是病例；
- 指标是在切片、patch 还是患者级计算；
- 是否先拼回 3D 体数据；
- 先平均切片还是先平均患者；
- 空切片如何处理；
- 多类 Dice 是否包含背景。

患者级宏平均通常比切片平均更能体现病例表现。切片数量多的患者不应无意中获得更大权重。

---

## 8. 第 5 步：检查实验公平性

### 8.1 baseline 是否足够强

确认：

- 有原始基础模型；
- 有最接近的已有方法；
- 有当前领域常见强基线；
- baseline 与 proposed 使用完整且可比的配置；
- 训练预算相同。

只和很老的方法比较，却声称 SOTA，通常需要补强基线或降低结论。

### 8.2 主要变量应尽量唯一

baseline 与 proposed 应保持一致：

- 病例划分；
- 输入尺寸；
- batch size；
- epoch；
- optimizer；
- learning rate；
- weight decay；
- 数据增强；
- 预训练权重；
- loss；
- 后处理；
- checkpoint 规则；
- 随机种子；
- 评价脚本。

同时改变网络、loss、输入尺寸、增强和训练时间，无法归因。

### 8.3 预训练、参数量和效率

检查：

- 是否都使用同样预训练；
- 新方法是否有更多参数；
- 是否只给新方法更大输入；
- 是否训练更久；
- 是否使用更强增强；
- Params、FLOPs、显存和时间是否报告；
- 是否有参数量匹配的替代基线。

准确率和计算代价必须一起看。大幅增大容量后的提升不能直接归因于结构思想。

### 8.4 消融是否回答因果问题

至少希望看到：

- baseline；
- proposed；
- 去掉核心组件；
- 替换成简单操作；
- 不同插入位置或配置；
- 参数量匹配对照。

好的消融回答：

- 核心模块是否有效；
- 每个关键部件是否必要；
- 位置是否重要；
- 是否只是容量增加；
- 是否与已有模块重复；
- 组合收益是否可叠加。

---

## 9. 第 6 步：检查指标与统计

### 9.1 Dice 不是全部

根据主张关注：

- Dice；
- HD95；
- ASD/ASSD；
- IoU/Jaccard；
- Sensitivity/Recall；
- Precision；
- Boundary F1；
- 体积误差；
- 连通性或拓扑指标。

论文声称边界改善却只报 Dice，应要求补边界指标或收窄结论。

### 9.2 HD95 和 ASD 的单位

确认：

- pixel、voxel 还是 millimetre；
- 是否传入真实 voxel spacing；
- 2D 轮廓还是 3D 表面；
- 空预测和空真值如何处理；
- 是否删掉异常病例；
- 是否把像素距离误写成毫米。

### 9.3 空掩膜处理

要求说明四种情况：

1. 预测空、真值空；
2. 预测空、真值非空；
3. 预测非空、真值空；
4. 双方非空。

预测非空、真实为空不能被记为完美结果。类别在病例中不存在时，也应说明是跳过、记零还是采用其他约定。

### 9.4 多 seed 和方差

看是否报告：

- 多个随机种子；
- mean ± standard deviation；
- 最好结果还是平均结果；
- 是否选择了最优 seed；
- 患者级配对差值；
- 置信区间或显著性。

单次运行提高一点可能只是随机波动，特别是小测试集和多次调参的论文。

### 9.5 统计检验的独立单位

如果使用显著性检验，检查：

- 统计单位是患者还是切片；
- 是否使用患者级配对检验；
- 是否处理多重比较；
- 是否报告效应量和置信区间。

把同一患者的很多切片当成独立样本，会夸大显著性。

---

## 10. 第 7 步：结果表和可视化的高频陷阱

检查：

- 验证结果和测试结果是否混在一起；
- 类别顺序是否一致；
- 背景是否有时包含、有时不包含；
- 平均值是否能由表格复算；
- Dice 小数和百分数是否混用；
- “提升 0.85 个百分点”是否被写成“提升 0.85%”；
- 是否只展示最好类别；
- 是否删除失败病例；
- 是否对 proposed 额外使用后处理；
- 图中颜色、窗宽窗位和放大倍数是否一致。

如果表格不能复算，应要求补充统计口径，而不是直接猜结果有误。

---

## 11. 第 8 步：复杂度和可复现性

### 11.1 复杂度

如果论文声称轻量、实时或适合部署，应要求：

- Params；
- FLOPs 或 MACs；
- 峰值显存；
- 单切片推理时间；
- 完整病例推理时间；
- GPU、CPU、PyTorch、CUDA；
- batch size 和 AMP；
- 是否包含数据加载和后处理。

单张 224×224 前向时间不能代表完整 3D 病例时间。

### 11.2 可复现信息

关注：

- 代码或伪代码；
- 数据划分；
- 训练命令或完整配置；
- seed；
- 框架和 CUDA 版本；
- 预训练权重来源；
- 输入尺寸、batch、epoch、学习率；
- 评价脚本；
- 后处理；
- checkpoint 选择规则。

不公开代码不自动等于拒稿，但自定义 loss、采样、后处理和数据划分缺失会明显降低可信度。

### 11.3 有代码时优先查关键路径

不需要逐行检查全部代码。优先查：

- 新模块是否真的被调用；
- 默认参数是否与论文一致；
- 测试脚本是否建立了同样的模型；
- checkpoint 是否加载正确结构；
- 是否存在测试集选择逻辑；
- 类别映射是否一致；
- baseline 是否真的使用了相同配置。

---

## 12. 按论文类型快速审查

### 12.1 新网络结构

重点问：

- 新结构解决了什么具体失败；
- 与已有 encoder/decoder/attention 哪里不同；
- 是否只是常见模块串联；
- 每个组件是否有独立消融；
- 参数增加能否解释提升；
- 是否跨骨干和数据集稳定。

### 12.2 新损失

重点问：

- loss 优化的目标是什么；
- 与已有 loss 的差异是否实质；
- 梯度是否稳定；
- 是否改变类别或边界权重；
- 相同网络上的公平比较；
- 权重敏感性；
- 每类和边界指标。

### 12.3 2.5D、3D、跨切片

重点问：

- 相邻切片是否来自同一病例；
- 训练和推理上下文数量是否一致；
- 边缘切片如何处理；
- 是否考虑 z-spacing；
- 2D baseline 是否获得同等输入信息；
- 显存和速度是否报告。

### 12.4 半监督、弱监督、自监督

重点问：

- 标签比例和无标签数据是否清楚；
- 预训练数据是否与测试数据重叠；
- 伪标签如何筛选；
- 是否使用了测试图像统计；
- 是否有 fully supervised upper bound；
- 不同标注率是否稳定。

### 12.5 域适应和域泛化

重点问：

- source、target 和 external domain 是否清楚；
- target 测试数据是否参与调参；
- 是否按医院、设备和患者拆分；
- 每个域结果是否报告；
- 是否真正存在未见域。

### 12.6 SAM、基础模型和提示分割

重点问：

- prompt 是人工、GT 生成还是模型预测；
- 测试时是否使用不可获得的 GT；
- baseline 是否得到同样 prompt；
- 是否报告 prompt 错误和交互次数；
- 基础模型容量增加是否被误写成方法创新。

### 12.7 临床应用和部署

重点问：

- 是否有真实临床数据；
- 是否有外部中心验证；
- 是否报告工作流时间和失败率；
- 是否说明设备、医生和中心差异；
- 是否过度使用“临床可用”“替代医生”等表述。

---

## 13. 快速判断创新是否足够

快速回答四个问题：

1. 删除新模块后，是否仍是标准网络；
2. 新模块是否对应一个真实、被数据支持的失败模式；
3. 与最接近工作是否有机制差异；
4. 消融是否证明提升来自该差异。

如果两项以上答不上来，创新证据通常不足。

### 13.1 弱创新

- 常见注意力、卷积和损失的无解释堆叠；
- 只改激活、核大小或归一化；
- 单数据集、单 seed、小幅提升；
- 没有机制消融。

### 13.2 中等创新

- 针对具体困难设计模块；
- 与已有模块功能不同；
- 多数据集或多 seed；
- 改善目标器官或边界指标；
- 复杂度增加可接受。

### 13.3 较强创新

- 新问题设定或真实临床约束；
- 跨中心、外部数据或跨域验证；
- 机制和实验互相支持；
- 充分消融、统计和失败分析；
- 对精度、鲁棒性、效率或可解释性形成完整贡献。

---

## 14. 30 分钟快速审稿法

### 0—3 分钟：抓主张

只读标题、摘要、贡献、结论，写一句话主张。

### 3—8 分钟：看图表

看方法图、主结果表、可视化，判断创新位置和结果是否可能支持主张。

### 8—15 分钟：查可信度

直接查：

- patient-level split；
- test 是否参与模型选择；
- 输入、预训练和预处理；
- baseline 是否公平；
- 是否多 seed；
- Dice、HD95 和统计口径。

### 15—23 分钟：查核心方法

只深入新增模块：

- 输入输出；
- 张量形状；
- loss；
- 训练/推理差异；
- 与已有工作的区别；
- 消融。

### 23—27 分钟：查反例

看最差类别、最差病例、失败图、复杂度和局限。

### 27—30 分钟：写决定

先写 summary、两条优点、三条主要问题、总体判断和 confidence，再补次要问题。

## 15. 如何提高速度而不降低质量

每篇论文固定回答 12 个问题：

1. 主问题是什么？
2. 新模块在哪里？
3. 为什么能解决问题？
4. 最接近工作是什么？
5. 是否患者级划分？
6. 测试集是否参与选择？
7. baseline 是否公平？
8. 消融能否证明因果？
9. Dice 统计单位是什么？
10. HD95/ASD 单位是什么？
11. 结果是否跨 seed、类别和病例稳定？
12. 结论是否超过证据？

优先查高风险路径：数据划分、checkpoint、指标实现、新模块公式、baseline、主表和消融。

不要写“请增加更多实验”。改成最小可执行要求：

- 增加相同患者划分下的 3 个 seed；
- 增加去掉核心组件的消融；
- 报告每类 Dice 和 HD95；
- 说明 test 是否选择 checkpoint；
- 提供 spacing 和空掩膜处理；
- 增加参数量匹配基线。

给每个问题标记：

- C：critical，可能推翻结论；
- M：major，需要补实验或重写；
- m：minor，表达或格式；
- Q：question，需要澄清。

## 16. 接收倾向怎么形成

### Accept

问题重要，创新清楚，方法正确，实验公平充分，结论和证据匹配，没有明显致命缺陷。

### Weak Accept / Borderline

方法有价值，证据基本可信，但创新幅度、实验广度或写作完整度一般，没有致命问题。

### Weak Reject / Major Revision 倾向

想法有潜力，但缺少关键消融、强基线、统计或公平比较，主要结论可能成立但证据不足。

### Reject

存在患者泄漏、测试集过度使用、核心创新高度重复、结果无法复核、对照明显不公平、关键方法缺失或结论严重超过证据。

拒稿意见应针对方法和证据，不攻击作者能力或动机。

## 17. 审稿意见模板

### 17.1 Summary

本文针对 ______ 问题，提出 ______ 方法，并在 ______ 数据集上验证。方法主要包含 ______。作者报告其在 ______ 指标上优于 ______。

### 17.2 Strengths

1. 问题具有 ______ 意义。
2. 方法中的 ______ 与目标问题有一定对应关系。
3. 实验包含 ______，结果呈现 ______。
4. 论文的 ______ 部分较清楚。

### 17.3 Major concerns

1. **数据划分与泄漏风险**  
   论文没有清楚说明训练、验证和测试是否按患者级划分。对于切片医学图像，这一点会直接影响结果可信度。请说明病例清单、切片生成顺序及跨划分情况。

2. **checkpoint 选择和测试集使用**  
   请明确最佳模型、阈值和后处理是否只由验证集决定。如果测试集参与选择，当前结果不能作为严格独立测试证据。

3. **消融不足**  
   当前只有 baseline 与完整模型，无法判断收益来自哪个组件或参数增加。建议加入去掉核心组件和参数量匹配的简单替代方案。

4. **指标口径不清楚**  
   请说明 Dice、HD95、ASD 的单位、空掩膜处理、背景是否包含，以及切片级还是患者级聚合。

5. **结论过强**  
   单数据集、单 seed 结果不足以支持通用医学分割结论。建议报告多 seed、每类结果、失败病例并收窄表述。

### 17.4 Minor concerns

- 统一类别名称和缩写；
- 图注说明颜色和显示窗口；
- 补充输入尺寸、预训练、训练轮数和学习率；
- 说明后处理是否对所有方法一致；
- 统一小数位和单位。

### 17.5 总体建议

论文的主要价值在于 ______。不过， ______ 影响核心结论的可信度。若作者补充 ______ 并修正 ______，判断会更清楚。

## 18. 常见风险清单

### 数据与评价

- [ ] 同一患者跨 train/val/test；
- [ ] 用 test 选 best checkpoint；
- [ ] 在 test 搜索阈值或后处理；
- [ ] 只报告切片平均；
- [ ] 背景处理不清；
- [ ] HD95/ASD 单位不清；
- [ ] 空掩膜规则可能奖励假阳性；
- [ ] 删除失败病例未说明；
- [ ] 代码与论文公式不一致。

### 方法与创新

- [ ] 模块只是改名；
- [ ] 与最近工作差异不清；
- [ ] 没有问题—机制对应；
- [ ] 训练和推理路径不一致；
- [ ] 只有完整模型，没有组件消融；
- [ ] 结果主要来自参数、输入或训练预算增加。

### 实验与统计

- [ ] 缺少强基线；
- [ ] 只报最好 seed；
- [ ] 没有方差；
- [ ] 只报总体 Dice；
- [ ] 小器官提升但总体下降；
- [ ] 没有失败案例；
- [ ] 没有复杂度；
- [ ] 将切片当独立样本做统计。

### 写作与结论

- [ ] 单数据集结论写成通用结论；
- [ ] 像素距离写成毫米；
- [ ] 百分点和百分比混用；
- [ ] loss 下降被写成泛化提升；
- [ ] 过度使用临床可用或替代医生；
- [ ] 不报告局限性。

## 19. 其他注意事项

### 19.1 结果低于 SOTA 不等于一定拒稿

问题重要、方法新、证据可信，即使数值略低也可能有价值。反过来，数值很高但存在泄漏或不公平比较，可信度更差。

### 19.2 方法简单不等于没有创新

简单、可解释、低成本且稳定的方法，可能比堆叠模块更有价值。审稿重点是机制和证据，而不是模块数量。

### 19.3 不要要求与主张无关的实验

新 decoder 不必无条件做临床试验；但声称临床可用，就必须提供外部验证、失败率和工作流证据。

### 19.4 关注重复投稿和增量工作

检查新旧论文的问题、数据、方法和表格是否大量重复。要求作者清楚引用和说明新增贡献，但不要仅凭文字相似就下结论。

### 19.5 关注基础模型的信息泄漏

区分：

- oracle prompt；
- GT 生成 prompt；
- 模型预测 prompt；
- fully automatic setting。

测试阶段使用不可获得的 GT 信息时，结果不能与自动方法直接比较。

### 19.6 结论必须收窄到证据覆盖范围

单一公开数据集只能支持有限范围的结论。跨域、临床可用、通用医学分割、替代医生等表述需要额外证据。

## 22. 最后的判断原则

一篇医学图像分割论文是否值得接收，通常由以下证据共同决定：

> 一个重要且清楚的问题  
> + 一个与问题对应的可信方法  
> + 公平且可复核的实验  
> + 患者级、类别级和边界级结果  
> + 对失败、复杂度和局限性的诚实说明。

建议始终坚持三条：

1. 先查可信度，再评价创新；
2. 先看患者级和类别级结果，再看平均 Dice；
3. 先判断证据是否支持主张，再判断结果是否漂亮。

坚持这三个顺序，就能较快识别医学图像分割论文中最关键的问题，并写出对作者有帮助、对会议决定有价值的审稿意见。
