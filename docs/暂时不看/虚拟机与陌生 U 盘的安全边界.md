# 虚拟机与陌生 U 盘的安全边界

## 核心结论

虚拟机磁盘确实只是宿主机上的一个文件，但“虚拟磁盘内部被感染”不等于“宿主机正在执行其中的恶意程序”。宿主机通常把 `.vdi`、`.vmdk` 或 `.vhdx` 当作普通数据文件；虚拟机操作系统才会把它解释成自己的文件系统和程序。

因此，普通文件型病毒通常会被限制在虚拟机内部。但虚拟机不是绝对安全边界，实际风险取决于 USB 连接方式、共享功能、网络模式、虚拟化软件漏洞和设备类型。

## 为什么虚拟磁盘感染通常不直接感染主机

虚拟化软件把磁盘镜像模拟成虚拟机的一块硬盘：

```text
宿主机文件 Ubuntu.vdi
        ↓
虚拟硬盘 /dev/sda
        ↓
虚拟机内部文件系统和程序
```

虚拟机中的恶意程序通常只能修改虚拟机内部文件、破坏虚拟机系统或访问虚拟机能够访问的网络资源。它不能直接调用宿主机的 Windows 文件 API，也不能直接把自己注册为宿主机的启动程序。

## 插入 U 盘时的几种情况

| 情况 | 宿主机风险 |
|---|---|
| U 盘被宿主机正常挂载并打开 | 高，病毒可能直接攻击主机 |
| U 盘独占直通给虚拟机 | 较低，但不是零 |
| U 盘内容通过共享文件夹给虚拟机 | 中到高 |
| 虚拟机能访问宿主机整个磁盘 | 很高 |
| 开启共享剪贴板或拖放 | 存在额外传播通道 |
| 使用桥接网络 | 可能攻击主机和局域网其他设备 |
| 虚拟化软件存在逃逸漏洞 | 可能影响宿主机 |

### U 盘被宿主机挂载

物理插入 U 盘后，首先处理它的是宿主机的 USB 控制器、驱动和操作系统。即使随后把设备连接给虚拟机，宿主机也可能已经枚举过这个设备。

风险包括自动播放、用户误点恶意文件、文件预览器解析漏洞、宿主机驱动漏洞，以及 U 盘伪装成键盘或其他 HID 设备。虚拟机无法阻止宿主机先接收键盘模拟输入。

真正陌生、明显可疑的 U 盘，不应仅因为有虚拟机就直接插入个人电脑。

### U 盘独占直通给虚拟机

如果虚拟化软件将 U 盘独占连接到虚拟机，宿主机不再挂载其中的文件系统，那么普通恶意文件主要会在虚拟机内运行。风险仍可能来自 USB 模拟、宿主机驱动、恶意固件、HID 伪装、虚拟机逃逸和网络连接。

## 会削弱隔离的功能

### 共享文件夹

虚拟机中的恶意程序如果对共享目录有写权限，就可能修改、加密或删除宿主机目录中的文件。这不一定是“虚拟机逃逸”，而是主动提供了宿主机文件访问通道。

### 共享剪贴板和拖放

它们可能造成文件、命令、密码、API Key 和代码在宿主机与虚拟机之间传播。

### 网络连接

桥接网络会让虚拟机像局域网中的另一台真实电脑，可能扫描宿主机、NAS、实验服务器和其他设备。NAT 通常更收敛，但不是绝对隔离。

### Guest Additions 或 VMware Tools

这些增强工具提供剪贴板、拖放、文件共享等集成功能。它们通常是正常软件，但会扩大攻击面，应及时更新。

## 虚拟机逃逸

虚拟机逃逸是恶意程序利用虚拟化软件、虚拟设备模拟器或增强工具漏洞，从虚拟机跳到宿主机执行代码。它通常需要特定版本和精心构造的输入，不是普通病毒的常规路径，但理论上不能排除。

## 更安全的配置

- 更新 VMware、VirtualBox、Hyper-V 和 Guest Tools。
- 关闭共享文件夹、共享剪贴板和拖放。
- 不要映射宿主机整个磁盘。
- 使用 NAT 或断网模式，避免桥接网络。
- U 盘只独占直通给虚拟机。
- 先建立干净快照，测试后回滚或删除虚拟机。
- 共享目录如确实需要，尽量设置为只读。
- 将 Colab、Jupyter、TensorBoard 等实验页面与共享目录隔离。
- 关闭宿主机自动播放和自动运行。
- 不要双击陌生的 `.exe`、`.lnk`、`.scr`、`.js` 或 `.vbs` 文件。
- 不要让虚拟机访问重要研究资料、NAS、服务器和 API 密钥。

## 最终判断

准确的说法不是“虚拟机能保证主机安全”，而是：

> 在关闭共享通道、正确直通设备、及时更新虚拟化软件并限制网络的条件下，普通文件型病毒通常会被限制在虚拟机内部；但对真正陌生的 USB 设备，虚拟机不能提供绝对保护。
