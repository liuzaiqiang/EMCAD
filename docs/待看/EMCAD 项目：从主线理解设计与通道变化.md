# EMCAD 项目：从主线理解设计与通道变化

> 这份笔记只做一件事：把 EMCAD 从一堆缩写还原成一条可以逐行追踪的计算流程。
>
> 核心结论：EMCAD 的整体骨架并不神秘。它是一个“编码器压缩特征 + 解码器逐级放大并融合跳跃连接 + 多尺度卷积和注意力修饰”的二维分割网络。MSCB、MSDC、EUCB、LGAG、CAB、SAB 是这条流水线上的局部零件，不是六个互相独立的大系统。

---

## 0. 先建立三个不会混淆的概念

### 0.1 这是一套二维切片分割流程

Synapse 原始数据是三维 CT。预处理脚本把体数据从 (H, W, D) 转成 (D, H, W)，训练时沿第 0 维取出一张张二维切片，保存为 .npz。

所以当前 EMCADNet 的一次前向输入不是完整三维体，而是：

~~~text
(B, 1, H, W)
~~~

其中：

- B：batch size；
- 1：CT 灰度图的单通道；
- H, W：切片的高和宽。

测试时虽然读取完整的 (D, H, W) volume，但 test_single_volume 仍然逐张取 image[ind, :, :]，再交给同一个二维网络。

### 0.2 通道数不是空间尺寸

张量通常写成：

~~~text
(B, C, H, W)
~~~

- C 是通道数，可以把它理解成“同一位置上有多少种特征地图”；
- H, W 是空间尺寸；
- C 增大，不代表图像变大，而是网络保存的特征种类变多。

例如：

~~~text
(B, 64, 56, 56)
~~~

表示每张图有 64 张特征图，每张特征图大小为 56 x 56。

### 0.3 训练输出和最终预测不是一回事

网络会产生四个预测：

~~~text
P = [p4, p3, p2, p1]
~~~

训练时可以选择监督一个、四个或四个输出的组合；验证/测试代码最终使用列表最后一个输出 p1。因此，深监督选项改变的是训练方式，不是测试时自动集成四张结果。

## 1. 先忘掉所有缩写：一条最小主线

把 EMCADNet.forward() 压缩成下面五步，就已经理解了 80%：

~~~text
CT 单通道输入
    ↓
1×1 卷积：1 通道 → 3 通道
    ↓
编码器：得到四级特征 x1, x2, x3, x4
    ↓
EMCAD 解码器：从 x4 开始，逐级上采样并融合 x3、x2、x1
    ↓
四个 1×1 输出头：各自把特征通道变成 9 类 logits
    ↓
上采样到输入尺寸，得到 p4、p3、p2、p1
~~~

对应的代码主线是：

~~~python
if x.size()[1] == 1:
    x = self.conv(x)

x1, x2, x3, x4 = self.backbone(x)
dec_outs = self.decoder(x4, [x3, x2, x1])

p4 = self.out_head4(dec_outs[0])
p3 = self.out_head3(dec_outs[1])
p2 = self.out_head2(dec_outs[2])
p1 = self.out_head1(dec_outs[3])
~~~

位置：lib/networks.py 的 EMCADNet.forward()。

工程思想很普通，也很实用：

1. 编码器逐步缩小空间尺寸，换取更大的感受野和更强的语义；
2. 解码器逐步放大空间尺寸，恢复器官边界；
3. 每次放大时，把编码器同尺度的浅层特征接回来，避免边界细节丢失；
4. 在每个解码阶段插入卷积和注意力，让特征更适合分割。

这就是一个带有多尺度卷积和注意力组件的 U-Net 风格结构。

train_synapse.py 的默认关键参数是：

~~~text
encoder          = pvt_v2_b2
num_classes      = 9
kernel_sizes     = [1, 3, 5]
expansion_factor = 2

add              = True
~~~

注意：仓库里的 start_train_synapse.sh 又把 img_size 改成了 256，并把 batch size 改成了 20。输入尺寸变化只改变 H、W，不改变 PVT-B2 的四级通道数。

Synapse 的 num_classes=9 表示 9 个类别通道，通常包括背景和 8 类器官。输出头的通道数因此是 9，而不是 1。

## 3. 输入端：为什么 1 通道变 3 通道

### 3.1 形状变化

假设一批 Synapse 切片大小为 224 x 224：

~~~text
输入 CT：        (B, 1, 224, 224)
1×1 Conv：       (B, 3, 224, 224)
BatchNorm/ReLU： (B, 3, 224, 224)
~~~

代码：

~~~python
self.conv = nn.Sequential(
    nn.Conv2d(1, 3, kernel_size=1),
    nn.BatchNorm2d(3),
    nn.ReLU(inplace=True)
)
~~~

### 3.2 为什么需要这一步

PVTv2 和 ImageNet 预训练 ResNet 的第一层通常按 RGB 三通道设计。Synapse CT 是灰度图，项目用一个可学习的 1×1 卷积把一个 CT 通道投影成三个特征通道，使后面的编码器接口保持一致。

这不是把 CT 变成真正的彩色图，也没有凭空增加信息。它只是一个可学习的通道映射：

~~~text
1 个输入通道 → 3 个可学习的特征通道
~~~

## 4. 编码器：PVTv2-B2 实际做了什么

编码器的任务只有一个：

> 用越来越小的空间网格，保存越来越丰富的语义特征。

### 4.1 PVT-B2 的四级通道和空间尺寸

对于默认 224 x 224 输入：

| 特征 | 来自 PVT 阶段 | 空间尺寸 | 通道数 | 相对输入 |
|---|---:|---:|---:|---:|
| x1 | stage 1 | 56 x 56 | 64 | 1/4 |
| x2 | stage 2 | 28 x 28 | 128 | 1/8 |
| x3 | stage 3 | 14 x 14 | 320 | 1/16 |
| x4 | stage 4 | 7 x 7 | 512 | 1/32 |

因此编码器输出可以写成：

~~~text
x1: (B,  64, 56, 56)
x2: (B, 128, 28, 28)
x3: (B, 320, 14, 14)
x4: (B, 512,  7,  7)
~~~

对于脚本常用的 256 x 256 输入，空间尺寸相应变成：

~~~text
x1: (B,  64, 64, 64)
x2: (B, 128, 32, 32)
x3: (B, 320, 16, 16)
x4: (B, 512,  8,  8)
~~~

通道仍然是：

~~~text
64 → 128 → 320 → 512
~~~

### 4.2 PVT 的每一级输入输出

以 224 x 224 为例：

~~~text
输入：(B, 3, 224, 224)

patch_embed1：3   → 64，空间 224 → 56
stage1：       64  → 64，空间不变

patch_embed2：64  → 128，空间 56 → 28
stage2：       128 → 128，空间不变

patch_embed3：128 → 320，空间 28 → 14
stage3：       320 → 320，空间不变

patch_embed4：320 → 512，空间 14 → 7
stage4：       512 → 512，空间不变
~~~

patch_embed 在这里本质上是带步幅的卷积投影；PVT 的注意力块和 MLP 块在一个 stage 内通常不改变该 stage 的 (C,H,W) 形状，只更新特征内容。

### 4.3 为什么要保留四个输出

只拿 x4，语义很强，但空间太粗，器官边缘已经丢掉不少。保留 x1、x2、x3，解码器才能在恢复分辨率时拿回浅层定位信息。

这就是 skip connection 的实际含义：

~~~text
x4：告诉网络“这里大概是什么器官”
x3：提供中等尺度结构
x2：提供更细的结构
x1：提供接近原图的边界细节
~~~

## 5. 解码器：先只看通道流，不看模块名字

PVT-B2 传给解码器的通道配置是：

~~~python
channels = [512, 320, 128, 64]
~~~

这个顺序是从最深层到最浅层：

~~~text
C4 = 512
C3 = 320
C2 = 128
C1 = 64
~~~

解码器的主通道流只有三次变化：

~~~text
512 → 320 → 128 → 64
~~~

空间尺寸则逐级放大：

~~~text
7×7 → 14×14 → 28×28 → 56×56
~~~

对 224 x 224 输入，完整的解码器形状如下：

| 阶段 | 输入/融合对象 | 主要操作 | 输出特征 |
|---|---|---|---|
| d4 | x4 | 注意力 + MSCB | (B,512,7,7) |
| d3 | d4 + x3 | 上采样、门控 skip、相加、注意力 + MSCB | (B,320,14,14) |
| d2 | d3 + x2 | 上采样、门控 skip、相加、注意力 + MSCB | (B,128,28,28) |
| d1 | d2 + x1 | 上采样、门控 skip、相加、注意力 + MSCB | (B,64,56,56) |

相加要求两边通道和空间都相同。因此 EUCB 的重要作用就是先把解码分支变成和 skip 分支相同的通道数。

---

## 6. 把花名词放回解码器的三个重复单元

解码器不是一堆随机模块，而是重复做下面的模板：

~~~text
当前深层特征
    ↓
上采样并调整通道（EUCB）
    ↓
用解码器特征控制 skip 特征（LGAG）
    ↓
两者相加
    ↓
通道注意力（CAB）
    ↓
空间注意力（SAB）
    ↓
多尺度卷积块（MSCB，内部包含 MSDC）
~~~

最深处的 d4 没有上一层需要上采样，也没有 x4 以外的 skip，因此只做：

~~~text
x4 → CAB → SAB → MSCB → d4
~~~

之后三个阶段分别把通道从 512、320、128 变成 320、128、64。

---

## 7. EUCB：它就是“上采样 + 改通道”

EUCB 的全名是 Efficient Up-Convolution Block。不要被名字吓到，它做的事情很清楚：

~~~text
1. Upsample：空间尺寸 ×2
2. depth-wise 3×3 卷积：通道数保持不变
3. 1×1 point-wise 卷积：把通道改成目标通道
~~~

### 7.1 d4 → d3

~~~text
输入 d4：        (B,512,7,7)
上采样：          (B,512,14,14)
depth-wise conv：  (B,512,14,14)
1×1 conv：        (B,320,14,14)
输出：            (B,320,14,14)
~~~

此时才能与编码器的 x3=(B,320,14,14) 融合。

### 7.2 d3 → d2

~~~text
(B,320,14,14)
    → 上采样
(B,320,28,28)
    → 1×1 改通道
(B,128,28,28)
~~~

然后与 x2=(B,128,28,28) 融合。

### 7.3 d2 → d1

~~~text
(B,128,28,28)
    → 上采样
(B,128,56,56)
    → 1×1 改通道
(B,64,56,56)
~~~

然后与 x1=(B,64,56,56) 融合。

EUCB 的工程取舍是：用 depth-wise 卷积降低计算量，再用 1×1 卷积完成通道投影。它不是改变网络目标的魔法，只是一个轻量的上采样实现。

---

## 8. LGAG：它就是“先筛选 skip，再相加”

LGAG 的全名是 Large-kernel Grouped Attention Gate。

在普通 U-Net 中，常见写法是：

~~~text
解码器特征 + skip 特征
~~~

本项目先用解码器特征 g 去生成一个空间门控图，再筛选 skip 特征 x：

~~~python
g1 = self.W_g(g)
x1 = self.W_x(x)
psi = self.activation(g1 + x1)
psi = self.psi(psi)
return x * psi
~~~

### 8.1 d3 处的通道变化

输入：

~~~text
g = d3 = (B,320,14,14)
x = x3 = (B,320,14,14)
~~~

内部：

~~~text
W_g：320 → 160
W_x：320 → 160
相加：160
psi：160 → 1
~~~

psi 只有 1 个通道，是一个空间位置权重图：

~~~text
psi = (B,1,14,14)
~~~

它广播乘到 x3 上，得到：

~~~text
筛选后的 x3 = (B,320,14,14)
~~~

最后：

~~~text
d3 = 上采样后的解码特征 + 筛选后的 x3
   = (B,320,14,14)
~~~

### 8.2 d2 和 d1

~~~text
d2 阶段：
g、x2：128 通道
中间通道：64
门控图：1 通道
门控后的 x2：128 通道
相加结果：128 通道

d1 阶段：
g、x1：64 通道
中间通道：32
门控图：1 通道
门控后的 x1：64 通道
相加结果：64 通道
~~~

LGAG 不负责改变主分支最终通道数；它主要负责“skip 的哪些空间位置值得传回来”。

## 9. skip connection、四个输出头与监督：不要把三件事混为一谈

这三个概念分别处在不同位置：

~~~text
skip connection：特征怎样在网络内部流动
四个输出头：每级解码特征怎样变成类别 logits
监督策略：训练时哪些 logits 参与 loss，并从哪些路径反向传梯度
~~~

其中只有监督策略在训练阶段可选；skip connection 和四个输出头都属于网络前向计算的一部分。

### 9.1 skip connection 到底做什么

编码器的下采样会损失精确位置和边缘。最深特征 `x4` 能较好地判断“这是哪个器官”，但其网格只有 `7×7`（以 `224×224` 输入为例），已经不足以画出清晰边界。因此解码器每上采样一级，就从编码器取回同尺度特征：

~~~text
x4 -> d4
d4 上采样后，与 x3 融合 -> d3
d3 上采样后，与 x2 融合 -> d2
d2 上采样后，与 x1 融合 -> d1
~~~

本项目不是直接把 skip 相加。以 `d3` 为例，先执行：

~~~text
候选解码特征 d3 作为“语义提示”
        +
编码器 x3 作为“细节来源”
        ↓
LGAG 生成 psi=(B,1,14,14)
        ↓
门控后的 x3 = x3 * psi
        ↓
d3 = d3 + 门控后的 x3
~~~

所以 skip 的作用不是再提供一张原图，也不是把预测结果复制过去；它是把浅层、较高分辨率的定位与边缘线索送回解码器。`LGAG` 让深层语义决定“这些细节的哪些位置应被保留”，以降低背景纹理被直接带回来的风险。

### 9.2 四个输出头究竟是什么

解码器得到的是内部特征，而不是类别图。四个 `1×1 Conv` 输出头分别把 `d4,d3,d2,d1` 的特征通道投影为 `K=num_classes` 个类别 logits：

~~~text
out_head4: 512 -> K
out_head3: 320 -> K
out_head2: 128 -> K
out_head1:  64 -> K
~~~

它们是四个独立的卷积层，参数不共享；“四个头”不等于“四类器官”，也不等于四次不同任务。它们都在预测同一份分割标签，只是来自由粗到细的四个解码阶段。

对默认 Synapse 配置，`K=9`（背景加 8 类器官），`224×224` 输入时形状如下：

| 预测 | 来自特征 | 经过 `1×1` 头后 | 上采样后返回的形状 |
|---|---|---|---|
| `p4` | `d4=(B,512,7,7)` | `(B,9,7,7)` | `(B,9,224,224)` |
| `p3` | `d3=(B,320,14,14)` | `(B,9,14,14)` | `(B,9,224,224)` |
| `p2` | `d2=(B,128,28,28)` | `(B,9,28,28)` | `(B,9,224,224)` |
| `p1` | `d1=(B,64,56,56)` | `(B,9,56,56)` | `(B,9,224,224)` |

代码通过固定倍率 `32/16/8/4` 的双线性插值，让四个头都回到输入分辨率，然后返回：

~~~python
[p4, p3, p2, p1]
~~~

这些值仍是 **logits**，没有做 `softmax`、`sigmoid` 或 `argmax`。多分类的 `CrossEntropyLoss` 和 Dice 损失在训练中负责概率化；推理时测试代码取 `outputs[-1]`，即 `p1`，再对类别维做 `softmax + argmax`。它不会默认把四个头平均或投票。

### 9.3 数据文件、样本和网络张量分别是什么格式

不要把磁盘上的数据文件格式和进入网络的 PyTorch 张量格式混为一谈。当前项目的三类任务分别如下。

| 任务 | 磁盘样本 | 单样本进入 DataLoader 后 | 一个 batch 的图像 | 一个 batch 的标签 |
|---|---|---|---|---|
| Synapse 多分类 CT | 训练 `.npz`，键为 `image`,`label` | 图像 `(1,H,W)`，标签 `(H,W)` | `(B,1,224,224)` | `(B,224,224)`，`long` 类别索引 |
| ACDC 多分类 MRI | `.npz`，键为 `img`,`label` | 图像 `(1,H,W)`，标签 `(H,W)` | `(B,1,H,W)` | `(B,H,W)`，`long` 类别索引 |
| Polyp 二分类 | 图像文件 + 同名 mask 文件 | 图像 `(3,S,S)`（默认彩色）或 `(1,S,S)`，mask `(1,S,S)` | `(B,3,S,S)` 或 `(B,1,S,S)` | `(B,1,S,S)`，取值为 0/1 |

Synapse 的训练 `image` 与 `label` 初始都是二维数组，空间尺寸会由 `RandomGenerator` 同步变换并缩放；图像被 `unsqueeze(0)` 加上单通道维，标签保持二维。DataLoader 再在最前面堆叠 batch 维。模型看到单通道 CT 后，会先经过可学习的 `1×1` 适配层：

~~~text
(B,1,224,224) -> (B,3,224,224) -> PVTv2-B2
~~~

标签不能写成 `(B,9,H,W)` 再直接喂给 `CrossEntropyLoss`。当前多分类训练器使用的是整数类别索引图：每个像素的值是 `0..8`，形状为 `(B,H,W)`；Dice 损失内部才把它转换成 one-hot `(B,9,H,W)`。与之匹配的每个预测头是 `(B,9,H,W)`。

二分类 Polyp 则不同：`num_classes=1`，输出是 `(B,1,H,W)` 的前景 logits，`sigmoid(logit)` 才是前景概率，背景概率隐含为 `1-sigmoid(logit)`。它不是“前景 + 背景所以必有两个输出通道”。

### 9.4 监督策略实际改变了什么

记 `L(z,y)` 为一份 logits 和标签算出的分割损失。Synapse/ACDC 的实现为 `0.3 * CE + 0.7 * Dice`。四个输出都已被上采样成相同 `(B,K,H,W)`，所以可以对任一个头、或者头的 logits 之和直接计算 `L`。

| 设置 | 实际损失 | 四个头时的组数 | 意义 |
|---|---|---:|---|
| `last_layer` | `L(p1,y)` | 1 | 只让最高分辨率的最终头直接对标签负责 |
| `deep_supervision` | `L(p4,y)+L(p3,y)+L(p2,y)+L(p1,y)` | 4 | 每一级解码器都收到直接分割梯度 |
| `mutation` | 对所有非空头集合 `S` 求和 `L(sum(i in S) p_i, y)` | 15 | 不仅约束单头，还约束任意多头 logits 相加后的组合 |

`mutation` 的 15 来自 `2^4 - 1`。例如它会监督 `p4`、`p1`、`p3+p1`、`p4+p3+p2+p1` 等所有非空组合。注意当前实现是**直接相加，不除以 4 或 15**，所以它的 loss 数值量级天然大于 `deep_supervision` 和 `last_layer`；不能只看三者的原始 loss 数字判断哪种训练得更好，应在相同划分下比较验证集/测试集指标。

深监督的核心不是“多得到四张最终分割图”，而是缩短梯度到早期解码阶段的路径。若只用 `p1`，`d4/d3/d2` 仍能通过后续上采样、融合和 `p1` 间接得到梯度；若对 `p4,p3,p2` 也计算损失，它们会额外收到“你自己也要能分割”的直接约束，通常有助于优化稳定性和小数据训练。

### 9.5 不监督可以吗

这里有两种含义，答案不同：

1. **不做深监督，但仍监督最终输出：可以。** 使用 `--supervision last_layer` 即可。网络仍有标签和损失 `L(p1,y)`，也仍会训练；测试本来就只使用 `p1`。此时 `out_head4/out_head3/out_head2` 虽会在前向中计算，但因为没有进入 loss，它们自身的参数没有梯度；`d4/d3/d2` 仍会因通向 `p1` 而间接获得梯度。
2. **完全不使用标签、也没有任何替代损失：不能按当前方式训练。** 反向传播需要一个可微的训练目标；loss 为零或根本不计算时，优化器没有有意义的梯度来把器官名称对应到图像区域。网络可以前向输出随机 logits，但不会学会分割。

无标签数据不是完全不能利用，但那已不是“把监督删掉”这么简单：可以先做自监督预训练，或采用半监督/弱监督/伪标签/一致性正则等方法；这些方法仍需某种学习信号，且通常要保留一部分可靠标注来把聚类结果对齐到真实的器官类别。

对当前 EMCAD 的基线实验，最干净的选择是：先固定数据划分和其余超参数，只把 `--supervision` 在 `last_layer`、`deep_supervision`、`mutation` 之间切换，记录验证集 Dice/HD95、训练耗时和显存。这样才能回答“深监督或 mutation 是否真的对你的数据有效”，而不是把它当作必然提升的开关。

## 10. 服务器运行时修改 `.py`，到底执行旧代码还是新代码

一句话规则：**Python 进程读取到哪一刻的代码，就执行哪一刻已经加载到内存中的代码。修改磁盘文件不会自动修改正在运行的 Python 进程。**

### 10.1 三种常见时序

#### 情况 A：程序还没有启动

~~~bash
sleep 600
python train_acdc.py
~~~

如果你在 `sleep` 期间修改了 `train_acdc.py`，那么 600 秒后 Python 才启动，通常读取的是更新后的文件。

#### 情况 B：Python 已经启动并正在运行

~~~bash
python train_acdc.py
~~~

此时 Python 启动时会读取主脚本，并在执行到 `import` 时读取依赖模块、编译成字节码并放入当前进程内存。你之后修改磁盘上的 `train_acdc.py`、`trainer.py` 或 `lib/networks.py`，当前训练进程不会自动切换到新代码；它会继续执行已经加载的旧版本。

即使训练暂时停在某个 batch、等待 GPU 或等待数据，也不等于它会重新读取源文件。只有程序显式使用 `importlib.reload()`、重新创建子进程，或结束后重新启动，才会重新加载。

#### 情况 C：启动命令已经提交，但进程尚未真正打开文件

例如：

~~~bash
nohup bash -c 'sleep 10; python train_acdc.py' &
~~~

这时如果在 10 秒内修改文件，Python 启动时会看到新文件。可是直接执行：

~~~bash
nohup python train_acdc.py > train.log 2>&1 &
~~~

主进程几乎立即启动，不能把“命令刚返回”理解成“源码还没读取”。这种情况下，若要确定修改生效，最可靠的方法是停止旧进程后重新启动，而不是依赖这段很短的竞态窗口。

### 10.2 `import` 文件与主脚本的关键区别

假设 `train_acdc.py` 中有：

~~~python
from lib.networks import EMCADNet
~~~

`lib/networks.py` 通常在程序启动阶段被导入。训练开始后再修改它，当前进程仍使用旧的 `EMCADNet` 类定义。即使后面又执行同样的 `import`，Python 也通常从 `sys.modules` 缓存中取已经导入的模块，不会自动重新读取磁盘文件。

因此：

| 修改时机 | 下一步是否重新启动 Python | 实际使用的代码 |
|---|---|---|
| 启动前修改 | 否，随后首次启动 | 更新后的代码 |
| 进程已启动，文件尚未被导入 | 否 | 首次导入时的更新代码 |
| 进程已启动，文件已经被导入 | 否 | 内存中的旧代码 |
| 进程已启动后修改，结束并重新启动 | 是 | 更新后的代码 |

### 10.3 对当前 EMCAD 启动脚本的具体判断

项目的 `start_train_synapse.sh` 和 `start_train_acdc.sh` 使用类似：

~~~bash
nohup env RUN_ID="..." python -u train_ACDC.py ... >> "${LOG_FILE}" 2>&1 < /dev/null &
~~~

一旦这个命令启动成功，`train_ACDC.py`、`lib/networks.py`、`lib/decoders.py` 和训练工具模块会在启动/导入阶段逐步加载。此后再改文件：

- 当前已经运行的训练：继续使用旧代码；
- 训练结束后直接再次运行启动脚本：新进程使用更新后的代码；
- 只修改文件、不重启进程：不会改变当前模型结构、损失实现或训练逻辑；
- 已经保存的 `.pth`：只包含参数，不包含你后来修改的 Python 逻辑。

项目的 ACDC 启动脚本默认 `NUM_WORKERS=0`，所以没有额外的数据加载 worker 进程需要考虑。若以后把 `num_workers` 改为大于 0，Linux 常见的 `fork` worker 通常继承父进程已经加载的模块，修改源码仍不会让正在运行的训练自动更新。

### 10.4 如何确认当前任务究竟用了哪一版代码

不要只看文件的当前内容。启动前把版本信息写入日志，例如：

~~~bash
git rev-parse HEAD
sha256sum train_acdc.py trainer.py lib/networks.py lib/decoders.py
python -u train_acdc.py ...
~~~

如果不使用 Git，也可以在脚本启动时打印：

~~~python
from pathlib import Path
import hashlib

def file_sha256(path):
    return hashlib.sha256(Path(path).read_bytes()).hexdigest()

print("train_acdc.py sha256:", file_sha256("train_acdc.py"), flush=True)
print("lib/networks.py sha256:", file_sha256("lib/networks.py"), flush=True)
~~~

更简单的开发期做法是在修改处临时输出一个明确版本标记，例如 `print("CODE_VERSION=2026-08-31-A")`，确认日志出现后再开始正式长时间训练。正式实验应把代码版本、启动命令、配置、随机种子和日志放在同一实验目录中。

### 10.5 实际操作建议

如果你修改的是即将运行的实验代码，推荐按下面顺序做：

1. 先确认旧训练进程是否存在：`ps -fu "$USER" | grep -E 'python|train_'`。
2. 如果旧进程已经在运行，不要直接覆盖理解为“它会更新”；需要按项目的停止脚本或明确 PID 停止后再启动。
3. 重新启动时记录新的日志文件、启动时间、命令行和代码哈希。
4. 从日志开头确认参数确实是本次修改后的值，再让训练长时间运行。

修改 `.py` 文件本身通常不会影响已经写入磁盘的 checkpoint，但如果新旧代码的模型结构、参数名、类别数或损失定义不兼容，恢复旧 checkpoint 可能报 `Missing key`、`Unexpected key` 或 shape mismatch；恢复实验前要检查代码和 checkpoint 的结构是否匹配。
