# 以 EMCAD 为基础模型做创新并形成论文成果的完整方法

> 本文回答一个硕士研究生最关键、也最容易被含糊带过的问题：选定 EMCAD 作为基础模型以后，究竟怎样从“能运行代码”走到“提出创新、完成实验、写成论文、形成成果”。
>
> 内容依据当前仓库实际代码组织。当前 Synapse 主链为 `train_synapse.py -> lib/networks.py::EMCADNet -> PVTv2/ResNet encoder -> lib/decoders.py::EMCAD -> trainer.py`。本文只给研究方案，不修改任何代码。

## 0. 最重要的结论

“选择一个基础模型，然后在上面做创新”不是指：

```text
找到 EMCAD
 -> 随便替换一个模块
 -> 指标提高 0.5%
 -> 给模块起一个新名字
 -> 写论文
```

真正可靠的过程是：

```text
固定并复现 EMCAD baseline
 -> 用实验定位 EMCAD 的具体失败模式
 -> 把失败模式表述成一个科学问题
 -> 提出可证伪的机制假设
 -> 只修改与假设直接相关的部分
 -> 用严格对照和消融判断假设是否成立
 -> 在更多数据、随机种子和指标上验证
 -> 把问题、方法和证据组织成论文
```

基础模型的作用不是给你一个“可随便装修的代码外壳”，而是提供一个稳定的实验参照系。你所有创新都必须回答：

1. 原 EMCAD 在什么条件下做得不好？
2. 这个问题为什么会发生？
3. 你的改动为什么有可能解决它？
4. 提升是否确实来自你提出的机制，而不是参数更多、训练更久、随机波动或数据泄漏？
5. 这个结论是否只在一个数据集、一个随机种子、一个类别上成立？

可以把一篇模型方法论文压缩为一个公式：

> **可信论文 = 明确问题 + 合理假设 + 对应方法 + 排除替代解释的实验 + 有边界的结论。**

模块数量不是核心。一项有充分证据的核心改动，通常比三个互不相关的“新模块”更像研究。

## 1. EMCAD 这个基础模型到底给了你什么

当前默认 EMCADNet 可以概括为：

```text
单通道医学图像
 -> 1x1 Conv 映射为 3 通道
 -> PVTv2-B2 四阶段 Transformer 编码器
 -> x1、x2、x3、x4 多尺度特征
 -> EMCAD 卷积解码器
 -> d4、d3、d2、d1
 -> p4、p3、p2、p1 四个分割头
 -> CE + Dice，多输出监督
```

EMCAD 已经替你解决了很多基础问题：

- 有可用的分层视觉编码器。
- 有多尺度特征。
- 有逐级上采样。
- 有 skip connection。
- 有通道和空间注意力。
- 有轻量多尺度深度卷积。
- 有四个输出头和监督策略。
- 有 Synapse、ACDC、Polyp、ISIC、BUSI 等任务路径。

这意味着你的研究通常不需要从零造一个完整分割网络，而是可以把 EMCAD 当成“实验平台”，研究其中某个明确问题。

当前最重要的可研究接口是：

| 研究层面 | 当前代码位置 | 可以研究的问题 | 硕士阶段难度 |
|---|---|---|---:|
| 输入与数据表达 | `utils/dataset_synapse.py` | 单切片是否缺少邻层上下文、增强是否适合小器官 | 中等 |
| 编码器 | `lib/pvtv2.py`、`lib/resnet.py` | 全局上下文、局部细节、计算效率 | 高，不建议作为第一刀 |
| 多尺度卷积 | `MSDC`、`MSCB` | 固定卷积核是否适合不同器官和不同位置 | 中等 |
| 上采样 | `EUCB` | 恢复分辨率时是否丢失边界 | 中等，但创新拥挤 |
| skip 筛选 | `LGAG` | 浅层噪声是否被错误传入解码器 | 中等，适合首篇论文 |
| 通道/空间重标定 | `CAB`、`SAB` | 注意力是否过于粗糙、是否缺少类别或边界意识 | 中等，但单纯替换很弱 |
| skip 融合 | `d_i + x_i` | 固定加法是否无法根据位置自适应选择两路信息 | 中等，适合首篇论文 |
| 四个输出头 | `lib/networks.py` | 不同尺度预测是否存在冲突 | 中等 |
| 监督策略 | `trainer.py` | mutation 的 15 组 logit 求和是否合理 | 中等，代码简单但文献竞争大 |
| 损失函数 | `trainer.py`、`utils/utils.py` | 小器官、边界、类别不平衡 | 低到中等，但只堆损失通常不够 |
| 三维上下文 | 数据加载与模型接口 | 当前二维切片之间完全独立 | 中高，问题明确 |
| 泛化与鲁棒性 | 数据与实验协议 | 跨数据集、跨设备、跨模态性能下降 | 中高，实验成本大 |
| 轻量化 | 编码器/解码器 | 参数、FLOPs、延迟、显存 | 中等，需要真实效率证据 |

这张表不是让你任选一行立即修改，而是让你知道：每个代码位置背后应对应什么研究问题。

## 2. “改代码”和“做科研创新”有什么本质区别

### 2.1 下面只是改代码

```text
把 CAB 换成 SE
把 SAB 换成 CBAM
把 3x3 换成 5x5
增加一个注意力模块
把 PVTv2 换成 Mamba
再加一个 Boundary Loss
把 add 换成 concat
```

这些操作都能产生一个新网络版本，但它们本身不自动构成创新。审稿人会继续追问：

- 为什么要这样换？
- 原模型哪里失败了？
- 新模块的哪一部分解决了什么？
- 只是增加参数量吗？
- 换成另一个常见模块是否同样有效？
- 在其他数据集上还有效吗？

### 2.2 下面才开始接近研究

假设你通过 baseline 结果发现：

```text
小器官 Dice 明显低于大器官；
HD95 很高；
可视化显示预测区域大体正确，但边界有断裂和远端假阳性；
这些错误主要出现在高分辨率 skip 融合之后。
```

你进一步提出：

```text
EMCAD 的 LGAG 只生成单一路径的空间门控，随后与解码特征固定相加；
它没有显式区分器官内部区域与不确定边界，可能无法在边界附近合理控制浅层细节。
```

然后提出假设：

```text
如果将区域信息和边界不确定性分开建模，并让两者共同控制 skip 融合，
那么可以在不过度引入浅层噪声的情况下改善小器官边界。
```

这时你的代码改动才有完整逻辑链：

```text
观察到的失败
 -> 原因假设
 -> 对应机制
 -> 可检验结果
```

即使最后没有提升，这仍然是一个可分析的研究实验。反过来，如果只是盲目换模块，即使偶然涨了分，也很难说明为什么。

## 3. 第一步不是创新，而是建立可信 baseline

很多学生最浪费时间的地方，是 baseline 还不可信就开始叠模块。最终不知道提升来自方法、环境、数据划分还是代码错误。

### 3.1 先冻结 baseline 身份

你至少要记录：

```text
Git commit
未提交 diff
Python/PyTorch/CUDA 版本
GPU 型号
训练和测试命令
编码器与预训练权重
数据清单
随机种子
输入尺寸
batch size
epoch/iteration 数
optimizer 与学习率
监督方式
评价脚本
```

当前工作区的 `train_synapse.py` 存在未提交修改。它不代表有问题，但在做 baseline 前必须保存 commit 与 diff，否则以后无法判断某次结果究竟对应哪一版代码。

### 3.2 先处理当前代码中的协议风险

这些属于实验正确性问题，不是论文创新：

#### 风险一：验证后没有恢复 train 模式

当前 `trainer.py` 在训练开始前调用一次 `model.train()`，每个 epoch 末验证会调用 `model.eval()`，下一 epoch 开头没有再次切回 `model.train()`。

这会使后续 epoch 的 BatchNorm、DropPath 等保持推理行为。必须先明确修正并重新跑 baseline。不能把修正前后的差值称作创新收益。

#### 风险二：用 `test_vol` 选择 best checkpoint

验证函数使用名为 `test_vol` 的 split。必须确认它实际是独立验证集，还是最终测试集。

如果每个 epoch 都在最终测试集上选择 `best.pth`，就是测试集参与模型选择。正确协议应是：

```text
train：更新权重
validation：选 best、调参数
test：所有设计冻结后只做最终评估
```

而且医学数据必须按患者/病例划分，不能按切片随机拆分。

#### 风险三：空类别指标规则异常

当前 Synapse 指标 helper 对“预测非空、真值为空”返回 Dice=1、Jaccard=1，这不符合通常直觉。必须在所有方法中统一评价规则，并在论文中说明。

#### 风险四：HD95/ASSD 没有使用真实 spacing

当前函数没有把真实 voxel spacing 传给 MedPy，距离单位实际上是数组网格单位，不能自动写成毫米。

这些问题不处理，后面的“提升 1%”可能没有可信意义。

### 3.3 baseline 至少跑什么

最低要求：

1. 用固定 train/val/test 清单跑完整 EMCAD。
2. 至少运行 3 个随机种子，报告均值和标准差。
3. 保存每个器官、每个病例的 Dice 和 HD95。
4. 保存预测 mask、原图、真值和叠加图。
5. 记录参数量、FLOPs、单张推理时间和显存。
6. 确认训练 loss、验证指标、checkpoint 选择都符合预期。
7. 与论文或公开实现的量级进行核对，但不要强求完全相同。

baseline 的最终产物不只是一行 mean Dice，而应包括：

```text
总体表现
每器官表现
每病例表现
边界表现
失败样本
训练稳定性
计算成本
```

只有这时你才有能力回答“EMCAD 哪里值得改”。

## 4. 怎样从 baseline 中找到科学问题

创新点通常不是坐在桌前凭空想出来的，而是从失败分析和文献缺口交叉产生。

### 4.1 做一张每器官表

示例结构：

| 器官 | Dice | HD95 | 体积大小 | 常见错误 | 是否稳定 |
|---|---:|---:|---:|---|---|
| spleen | 待实验 | 待实验 | 大 | 边界轻微偏移 | 待分析 |
| gallbladder | 待实验 | 待实验 | 小 | 漏分、断裂 | 待分析 |
| pancreas | 待实验 | 待实验 | 中小、形态复杂 | 边界模糊、远端误检 | 待分析 |
| liver | 待实验 | 待实验 | 大 | 局部边缘偏差 | 待分析 |

不要提前假定哪个器官最差，用实际结果填写。

### 4.2 做失败病例分类

把错误至少分成：

- 完全漏检。
- 局部漏分。
- 远端假阳性。
- 相邻器官混淆。
- 边界过平滑。
- 边界破碎。
- 小器官体积严重偏差。
- 相邻切片结果不连续。
- 模糊/低对比度区域失败。

每类统计出现频率，而不只挑两张好看的图。

### 4.3 对照模型内部结构提出原因候选

| 观察到的失败 | 可能相关的 EMCAD 结构 | 需要验证的假设 |
|---|---|---|
| 边界模糊 | EUCB、最高分辨率 skip、固定双线性插值 | 上采样或 skip 没有足够边界约束 |
| 小器官漏检 | 多次下采样、类别不平衡、深层预测 | 小目标信息在深层丢失或损失权重不足 |
| 假阳性噪声 | LGAG 与固定加法融合 | 浅层纹理未经充分筛选进入解码器 |
| 四个头预测冲突 | mutation supervision | 15 组求和没有显式解决尺度间语义冲突 |
| 相邻切片不连续 | 2D slice-based pipeline | 模型完全没有利用 z 轴上下文 |
| 跨数据集下降 | 归一化、编码器、BN、风格偏差 | 模型依赖特定成像分布 |
| 速度慢 | PVTv2-B2 或多输出训练 | 计算成本主要集中在哪个模块 |

表中的“可能”不是结论。需要设计额外诊断实验排除其他解释。

### 4.4 用诊断实验确认问题

例如你怀疑 skip 融合引入噪声，可以先做：

- 临时关闭某一级 skip，看哪些类别变化最大。
- 比较只用 `x1`、只用 `x2`、全部 skip。
- 可视化 LGAG gate 分布。
- 对比错误区域与 gate 高响应区域。
- 统计边界附近和器官内部的特征响应。
- 使用参数量匹配的简单门控作对照。

诊断实验不一定进入最终论文主表，但它决定你是否值得继续做这个方向。

## 5. 把问题写成“可证伪假设”

不合格的表述：

```text
现有模型特征提取不充分，因此我们设计一个新模块增强特征提取能力。
```

这句话几乎适用于所有论文，无法被明确验证。

较好的表述：

```text
EMCAD 在每一级使用单个空间门控过滤 skip，随后固定相加。
我们假设该机制在模糊边界区域不能区分有用的高频边缘与背景纹理，
因此小器官的 HD95 和远端假阳性较差。
如果显式分离区域置信度和边界不确定性，并用其共同控制 skip 融合，
则应主要改善边界指标和小器官，而不是无差别提升所有类别。
```

这段话可被实验推翻：

- 如果小器官和边界没有改善，假设不成立。
- 如果简单增加参数也达到同样效果，提出的机制缺少必要性。
- 如果只在一个 seed 上有效，结果不稳定。
- 如果 Dice 上升但 HD95 变差，需要重新解释。

一个好的假设通常包含：

```text
对象：原模型哪个具体机制
条件：在什么场景下失败
原因：为什么失败
干预：你改变什么
预测：哪类指标/样本应改善
```

## 6. EMCAD 上最常见的“伪创新”

### 6.1 只替换成熟模块

把 `CAB/SAB` 替换成另一个公开注意力，然后说“增强全局特征”。如果没有新的问题、机制和分析，通常只是组合应用。

### 6.2 只改卷积核集合

原 EMCAD 已经对 kernel sets 和 depth-wise convolution 变体做过消融。简单将 `[1,3,5]` 改成 `[1,3,5,7]` 很难成为新论文核心。

### 6.3 只把热门骨干换进来

把 PVTv2 换成 Mamba、Swin 或其他 backbone，通常属于 backbone replacement。除非你解决了医学分割中的具体问题，并证明适配机制必要，否则容易被认为是跟随热点。

### 6.4 同时堆很多模块

```text
新注意力 + 新损失 + 新上采样 + 新骨干
```

如果全部一起加入，指标即使提高，也无法知道是谁起作用。消融会迅速膨胀，论文主线也会混乱。

### 6.5 只报告最好的一次运行

单 seed 的小幅提升可能只是随机波动。尤其当提升小于不同 seed 的标准差时，不能声称稳定优越。

### 6.6 偷换实验条件

下面的比较不公平：

- proposed 训练 300 epoch，baseline 只训练 150。
- proposed 使用预训练，baseline 不使用。
- proposed 输入 352，baseline 输入 224。
- proposed 使用新划分，baseline 使用旧划分。
- proposed 选择最好测试结果，baseline 使用最后 epoch。

### 6.7 用测试集调参数

反复观察测试集并修改方法，会把研究者自己变成测试集上的优化器。最终结果不能代表泛化能力。

### 6.8 AI 生成了代码就当成自己的创新

AI 可以帮助实现、检索、调试和组织实验，但：

- AI 生成的想法不保证新颖。
- AI 生成的代码不保证正确。
- 你必须理解并承担全部方法和结果责任。
- 与已有论文相同的机制仍然需要引用，不能因为代码由 AI 写出就变成原创。

## 7. 推荐给硕士首篇论文的三条 EMCAD 路线

以下只是候选研究方向，不是已经确认的新颖性。正式选题前必须做针对性文献检索。

### 路线 A：边界与 skip 融合，推荐优先级最高

#### 可能的问题

EMCAD 用 LGAG 对 skip 做空间门控，再与解码特征固定相加。它可能难以区分：

- 器官真实边缘；
- CT 噪声和相邻组织纹理；
- 器官内部稳定区域；
- 模糊边界不确定区域。

#### 可以形成的研究问题

```text
怎样让高分辨率 skip 在器官内部、边界和背景区域采用不同的融合策略？
```

#### 优点

- 修改集中在 `lib/decoders.py`。
- 不需要重写整个编码器。
- 可以用 Dice、HD95、边界指标直接验证。
- 可做清楚的模块和位置消融。

#### 风险

- 边界注意力研究很多，新颖性需要严格检索。
- 如果 baseline 并不存在明显边界问题，方向缺乏依据。
- 仅增加 boundary loss 通常不足以构成完整创新。

### 路线 B：2.5D 邻层上下文，研究深度更强

#### 当前明确限制

Synapse 训练使用二维切片，测试也是逐切片独立前向。相邻切片没有共享隐藏状态或体上下文。

#### 可以形成的研究问题

```text
怎样在保留 EMCAD 二维效率的同时，利用相邻 CT 切片提高三维连续性？
```

#### 最简单对照

```text
输入单张中心切片：1 channel
输入前/中/后切片：3 channels，预测中心切片
```

但简单把三张切片塞入 RGB 通道只是 2.5D baseline，不一定是创新。真正的方法可以研究：

- 邻层可靠性加权。
- 不同编码尺度的跨切片适配器。
- 中心切片与邻层差异引导。
- 缺失首尾邻层的稳健处理。
- 跨切片一致性约束。

#### 优点

- 问题来自当前模型真实结构限制。
- 可在 Synapse、ACDC 等体数据上验证。
- 能报告三维连续性和边界距离。

#### 风险

- 数据加载、显存和实验设计更复杂。
- 必须保持患者级划分。
- 2.5D/3D 相关工作很多，需要明确与已有方法区别。

### 路线 C：四尺度预测冲突与自适应监督

#### 当前特点

EMCAD 返回四个全分辨率 logits。默认 mutation supervision 枚举 15 个非空输出子集，对子集 logits 求和并累加损失。

#### 可以形成的研究问题

```text
不同尺度预测发生冲突时，穷举求和监督是否会把错误尺度的信息传播给其他尺度？
```

可以先测量：

- 四个头的 pairwise Dice。
- 每个像素的预测一致率。
- pairwise KL/JS divergence。
- 各输出头的置信度与正确率。
- 各监督项的梯度方向是否冲突。

然后研究：

- 置信度加权监督。
- 不确定性区域的差异化监督。
- 课程式多尺度监督。
- 梯度冲突缓解。

#### 特别提醒

当前仓库 `DG_EMCAD_reference/` 已经包含基于 entropy、相邻尺度 JS disagreement、EMA teacher 和 boundary partition distillation 的参考方案。它展示了如何把“尺度冲突”发展成机制和消融，但不能自动当作你的新颖想法。

使用这条路线前必须：

1. 查清该参考代码的来源和形成过程。
2. 对相关工作进行系统检索。
3. 不能复制后重新命名并声称原创。
4. 如果继续研究，必须找到明确不同的问题或机制。

## 8. 完整示例：怎样把 skip 边界问题做成一篇论文

下面给出一条从零到论文的演示路线。名称仅用于说明研究方法，不代表已确认新颖，也不能直接当投稿标题。

### 8.1 暂定研究问题

```text
EMCAD 的固定 skip 门控和加法融合，是否在模糊边界处引入浅层噪声，
导致小器官边界定位不稳定？
```

### 8.2 第一步：先证明问题存在

需要得到以下证据：

1. baseline 的小器官 HD95 明显差或波动大。
2. 失败样本确实集中在模糊边界、邻近组织或低对比区域。
3. 关闭/改变浅层 skip 后，错误类型发生可解释变化。
4. LGAG gate 在错误区域没有形成合理抑制。
5. 问题在不止一个随机种子中出现。

如果这些现象不存在，就不应继续写“边界融合是主要瓶颈”。换问题比硬做更科学。

### 8.3 第二步：提出机制假设

假设可以写为：

```text
单一空间 gate 无法同时表示稳定器官区域和不确定边界的不同需求。
区域内部需要保留语义一致特征，边界区域需要更谨慎地选择高频 skip，
因此将区域与边界分开估计，再自适应融合，可能降低边界假阳性和漏分。
```

### 8.4 第三步：设计最小方法

例如设计一个双路径 skip gate：

```text
输入：decoder feature g，encoder skip x

region branch：估计器官区域相关权重
boundary branch：估计边界/不确定区域权重
fusion branch：根据两类权重决定 x 如何进入解码器

输出：与原 LGAG 相同 shape 的 filtered skip
```

接口应尽量保持：

```text
new_gate(g, x) -> filtered_x
```

这样可以只替换 LGAG，尽量不改变 EMCAD 其他部分。最小改动有两个好处：

- 更容易确认收益来自新机制。
- 更容易复用原 checkpoint、训练脚本和通道结构。

如果需要边界监督，可以从分割 mask 自动生成边界标签，不需要额外人工标注。但必须说明边界生成方式、宽度和损失权重。

### 8.5 第四步：代码落点

可能涉及：

| 文件 | 可能改动 | 原则 |
|---|---|---|
| `lib/decoders.py` | 新 gate 类，替换或并联 LGAG | 保持输入输出通道和空间尺寸一致 |
| `lib/networks.py` | 通常尽量不改 | 四个输出头和模型接口保持一致 |
| `trainer.py` | 若有辅助边界 loss，加入损失 | 不改变 baseline 训练预算和其他损失 |
| `utils/` | 生成边界标签、增加边界指标 | 图像与标签处理必须可复现 |

第一版不要同时换 encoder、MSCB、loss 和数据增强。

### 8.6 第五步：先做最小冒烟测试

在正式训练前必须通过：

```text
模型能构建
随机输入 forward 成功
四个输出 shape 正确
loss 是有限值
backward 成功
新参数有非零梯度
旧参数仍参与更新
显存可接受
一个小 batch 可以过拟合
```

小数据过拟合测试很重要。如果几十个样本都无法拟合，先不要跑 300 epoch。

### 8.7 第六步：设计消融矩阵

最低可用矩阵：

| ID | 配置 | 回答的问题 |
|---|---|---|
| E0 | 原始 EMCAD | baseline 是多少 |
| E1 | EMCAD + 参数量匹配的普通卷积 | 提升是否只是因为参数更多 |
| E2 | 只加 boundary loss，不换 gate | 是监督起作用还是结构起作用 |
| E3 | 只用 region branch | 区域分支贡献多少 |
| E4 | 只用 boundary branch | 边界分支贡献多少 |
| E5 | region + boundary，不加辅助 loss | 双路径结构本身是否有效 |
| E6 | 完整方法 | 两者结合是否互补 |
| E7 | 只放最高分辨率一级 | 模块应放在哪里 |
| E8 | 放三层 skip | 多层部署是否必要 |

不一定全部进入主文，但你必须通过这些实验知道方法为什么有效。

### 8.8 第七步：公平比较

所有 E0-E8 保持一致：

```text
同一数据清单
同一预处理
同一输入尺寸
同一 encoder 和预训练
同一 epoch/iteration
同一 optimizer 和学习率
同一 supervision
同一 checkpoint 选择规则
同一评价脚本
同一组 seeds
```

如果新方法收敛更慢，不应私下给它更多 epoch。可以额外做“充分收敛”实验，但主公平表必须控制预算。

### 8.9 第八步：需要报告什么

#### 分割效果

- Mean Dice。
- Mean HD95。
- 每个器官 Dice/HD95。
- 每病例结果。
- 三个或更多 seed 的 mean ± std。

#### 边界证据

- Boundary Dice、NSD 或明确选择的边界指标。
- 模糊边界和小器官子集结果。
- 远端假阳性、漏分的数量或体积统计。

#### 效率

- 参数量。
- FLOPs/MACs，说明输入大小。
- 推理时间和硬件。
- 峰值显存。

#### 机制证据

- gate 可视化。
- region/boundary 分支响应图。
- 正确样本和失败样本。
- 与参数匹配对照比较。

### 8.10 第九步：你的论文主张应该多窄

不宜写：

```text
我们解决了医学图像分割中的边界问题，并显著优于现有方法。
```

更可信的写法：

```text
我们针对 EMCAD 类层次化编码器-解码器中固定 skip 门控对模糊边界适应不足的问题，
提出区域与边界分解的融合机制。在两个腹部/心脏分割基准上，
该方法主要改善小结构的边界距离，并保持有限计算开销。
```

论文主张越具体，越容易用实验支持。

## 9. 第二个示例：从二维 EMCAD 发展 2.5D 研究

### 9.1 baseline 的事实

当前 Synapse 病例虽然是 `[D,H,W]`，但模型逐切片独立推理。第 `z` 张切片不知道 `z-1` 和 `z+1` 的预测或特征。

### 9.2 先建立普通 2.5D 对照

```text
输入：[slice(z-1), slice(z), slice(z+1)]
标签：slice(z) 的 mask
```

这三张切片正好可以作为 3 个输入通道进入 PVTv2。但它只是必须比较的简单 baseline。

### 9.3 一个更像研究的问题

邻层并不总是有用：

- 器官在相邻层可能快速出现或消失。
- 首尾切片缺少一侧邻居。
- 呼吸、重采样和层厚影响对应关系。
- 远邻层可能引入错误结构。

因此可以提出：

```text
怎样根据邻层与中心层的一致性，自适应决定邻层在不同尺度、不同位置贡献多少？
```

### 9.4 必须做的对照

| 配置 | 目的 |
|---|---|
| 单切片 2D | 原始 EMCAD |
| 简单复制中心切片三次 | 排除仅通道数变化 |
| 直接堆叠 3 张切片 | 普通 2.5D baseline |
| 5 张切片 | 邻域宽度影响 |
| 固定平均邻层特征 | 简单融合对照 |
| 自适应邻层融合 | proposed |
| 打乱邻层顺序或使用错误邻层 | 检验是否真的利用解剖连续性 |

### 9.5 应增加的证据

- 切片间预测面积变化曲线。
- 相邻切片 mask 一致性。
- 3D 连通域错误。
- 体积误差。
- 对不同层厚病例的敏感性。

如果 proposed 只提高二维 Dice，却没有改善任何三维连续性证据，那么“利用三维上下文”的主张仍不充分。

## 10. 文献检索应该发生在什么时候

不是等代码写完才搜索，也不是只搜索一次。

### 10.1 发现问题后搜索

目标：确认问题是否真实、有无已有定义。

例如边界 skip 方向可搜索概念组合：

```text
medical image segmentation boundary-aware skip fusion
uncertainty-guided skip connection segmentation
small organ segmentation boundary attention
adaptive gated skip medical segmentation
```

### 10.2 设计方法前搜索

目标：避免把已有模块重新发明一次。

建立对照表：

| 论文 | 解决的问题 | 方法机制 | 使用数据 | 与你的差别 | 可作为何种 baseline |
|---|---|---|---|---|---|

不要只记录论文标题和最终 Dice。

### 10.3 实验后再搜索

目标：根据实际结果重新定位贡献。如果你最初想解决边界，但实验只改善大器官区域 Dice，就需要修改方法解释，而不是继续强写边界故事。

### 10.4 新颖性判断的底线

以下任一情况都不能轻易声称 novel：

- 数学形式与已有方法相同，只换名字。
- 两个公开模块串联，没有新的问题或交互机制。
- 已有论文在相同任务和位置做过相同操作。
- 仅把通用方法第一次放进 EMCAD。

“第一次用于 EMCAD”通常不是强新颖性，因为 EMCAD 只是一个具体基础模型。

## 11. 一项核心创新怎样撑起完整论文

一个核心模块可以形成多项实验问题：

```text
是否有效？
哪一部分有效？
为什么有效？
放在哪里有效？
参数量相同还有效吗？
不同器官都有效吗？
不同数据集有效吗？
不同 encoder 有效吗？
计算成本是否合理？
什么时候失败？
```

所以“一项创新”并不等于只做两行实验：

```text
Baseline
Baseline + Ours
```

一个扎实的单创新论文，往往包含：

- 1 个明确问题。
- 1 个核心方法。
- 5 到 8 个受控配置。
- 2 个左右数据集或足够强的跨场景验证。
- 多 seed。
- 参数/速度分析。
- 可视化与失败案例。
- 与已有替代方法的公平比较。

这比堆三个模块但没有机制证据更有说服力。

## 12. 怎样判断结果够不够发论文

没有统一的“Dice 提高多少就能发”。审稿判断是整体证据，不是单一阈值。

### 12.1 很弱的结果包

```text
一个数据集
一个 seed
只报告 mean Dice
只和原 EMCAD 比
没有参数量
没有消融
没有失败分析
提升很小
```

即使分数上涨，也很难支撑可靠论文。

### 12.2 初步可投稿的结果包

```text
问题明确
方法与问题对应
baseline 可信
至少一个完整消融矩阵
同协议 SOTA/替代方法比较
每类 Dice + HD95
多 seed 或足够的稳定性分析
计算成本
定性结果和失败案例
第二数据集或外部验证
```

### 12.3 更强论文还需要什么

- 新颖问题或更深机制，而不只是模块替换。
- 跨编码器、跨数据集、跨域的稳定性。
- 更严格的统计检验。
- 理论、复杂度或机制分析。
- 与强基线和近期方法公平比较。
- 代码、划分和配置可复现。

粗略地说，CCF-C 或一般医学影像会议可能接受范围较窄但完整、可信的工作；CCF-B 通常需要更强的新颖性、广泛验证和更清楚的影响。它不是硬门槛，也不存在“加两个模块就升一级”的规则。

## 13. 论文是怎样从实验中长出来的

### 13.1 标题

标题应体现问题和机制，不只是堆缩写：

```text
[核心机制] for [具体问题] in Medical Image Segmentation
```

标题必须在文献检索后再确定，示例名称不能直接当作新颖声明。

### 13.2 摘要的五句话

1. 医学/技术问题是什么。
2. 现有 EMCAD 类方法的具体限制是什么。
3. 你提出什么核心机制。
4. 在哪些数据和指标上验证。
5. 最主要且有边界的结论是什么。

### 13.3 Introduction 的逻辑

```text
第一段：任务重要性和真实困难
第二段：现有方法与 EMCAD 的能力
第三段：仍未解决的具体问题和证据
第四段：你的方法、机制和贡献
```

不要从“近年来深度学习快速发展”开始写一整页空话。

### 13.4 Method

先给 baseline 和符号，再介绍 proposed。必须写清：

- 输入输出 shape。
- 新模块插入位置。
- 数学计算。
- 辅助标签如何生成。
- loss 组成和权重。
- 训练和推理是否增加成本。

### 13.5 Experiments

至少包含：

- 数据集和划分。
- 预处理。
- 实现细节。
- 比较方法。
- 主结果。
- 消融。
- 效率。
- 可视化。
- 失败和局限。

### 13.6 Contribution 不要夸大

较合理的三点结构：

```text
1. 识别并形式化一个具体问题。
2. 提出一个与该问题对应的核心机制。
3. 通过多数据/多指标/受控消融证明其效果和适用边界。
```

“首次”“显著优于”“全面解决”等词必须有充分检索和统计证据。

## 14. 12 周可执行路线

这是理想化节奏，实际时间取决于算力、数据和实验失败次数。

### 第 1 周：冻结代码和实验协议

- 修正影响 baseline 正确性的训练/验证问题。
- 固定患者级 train/val/test 清单。
- 固定评估脚本和空类规则。
- 记录环境与代码版本。
- 完成 forward、loss、短训练测试。

产物：`Baseline Protocol v1`。

### 第 2 周：完整复现 baseline

- 跑至少 3 seeds。
- 生成每器官、每病例结果。
- 保存预测图和失败案例。
- 记录训练时间和资源。

产物：可信 EMCAD baseline 表。

### 第 3 周：失败分析

- 给错误分类。
- 统计小器官、边界、切片连续性。
- 做少量诊断性开关实验。
- 提出 2 到 3 个原因假设。

产物：Failure Analysis 报告。

### 第 4 周：文献矩阵与选题冻结

- 围绕具体问题检索，而不是泛读所有分割论文。
- 建立方法对照表。
- 排除明显重复方案。
- 最终只保留一个核心问题。

产物：一页 Problem-Hypothesis-Method-Evidence 方案。

### 第 5 周：最小实现

- 新建研究分支。
- 只实现核心机制。
- 写 shape/gradient 冒烟测试。
- 在小数据上过拟合。

产物：可训练的 prototype。

### 第 6 周：单 seed 快速筛选

- E0 baseline。
- 参数量匹配对照。
- 核心组件拆分。
- 淘汰无效设计。

产物：保留一个最终方法版本。

### 第 7 至 8 周：正式消融

- 固定版本跑多 seeds。
- 完成位置、组件、权重、替代模块比较。
- 记录所有失败实验。

产物：消融表和机制图。

### 第 9 周：第二数据集或跨场景验证

- 保持方法不变，只做必要任务适配。
- 不根据测试结果重新设计模块。
- 报告稳定性和失败边界。

产物：泛化证据。

### 第 10 周：效率和可视化

- 参数、FLOPs、延迟、显存。
- 典型成功、典型失败、gate/attention 图。
- 统计显著性或置信区间。

产物：完整 figures 和 tables。

### 第 11 周：写论文

- 先写 Method 和 Experiments。
- 再写 Introduction 和 Related Work。
- 最后写 Abstract 和 Conclusion。

### 第 12 周：审计和投稿准备

- 核对每个数字与原始 CSV。
- 核对数据划分和 checkpoint。
- 核对引用与新颖性表述。
- 复跑关键结果。
- 检查匿名、格式、页数和代码说明。

# Experiment ID

## 16. 怎样利用 Codex 提高这条路线的效率

Codex 适合承担：

- 追踪实际代码调用链和 tensor shape。
- 为新模块写最小实现和单元测试。
- 检查新参数是否进入 optimizer/state_dict。
- 自动生成多组实验命令。
- 解析日志和汇总 CSV。
- 生成每器官、每病例表格。
- 计算参数量、FLOPs 和推理时间。
- 对比两个实验的配置差异。
- 生成预测可视化脚本。
- 检查数据清单是否重叠。
- 按原始结果辅助写论文初稿。

Codex 不能替你完成：

- 决定一个问题是否真正重要。
- 保证想法在全球文献中从未出现。
- 证明实验协议在医学上合理。
- 替你解释不符合预期的结果。
- 替你承担论文中的真实性责任。
- 在没有实验数据时生成可信结论。

最好的协作方式不是说“帮我创新一个模块”，而是提供：

```text
当前 baseline 结果
失败样本
相关论文矩阵
你的原因假设
允许修改的代码范围
必须保持不变的实验条件
希望验证的具体预测
```

这样 AI 才是在加速研究，而不是随机生成网络结构。

## 18. 你现在最应该做的事情

对于当前 EMCAD 项目，不建议马上让我给你加入 Mamba、注意力或新 loss。正确顺序是：

### 第一步

先建立修正后的可信 Synapse baseline，解决 train/eval、验证集、指标定义和实验记录问题。

### 第二步

输出：

```text
3 seeds 的每器官 Dice/HD95
每病例 CSV
10 到 20 个典型失败病例
小器官、边界和切片连续性统计
```

### 第三步

根据真实失败在下面两条中选一条：

```text
边界/skip 融合问题
或
二维切片缺少邻层上下文
```

首篇论文不建议同时做两条。

### 第四步

写一页选题说明，格式固定为：

```text
Problem：EMCAD 在什么情况下失败？
Evidence：哪些数字和图证明它失败？
Cause hypothesis：为什么失败？
Method：只改变什么？
Prediction：哪些指标和样本应改善？
Alternatives：还有哪些更简单解释？
Ablations：怎样排除这些解释？
Novelty：与最近工作差别是什么？
```

这页写不清楚，就不要开始大规模改代码。

## 19. 最后的现实判断

硕士阶段基于基础模型做创新，合理目标通常不是发明下一代通用视觉架构，而是：

1. 找到一个真实、具体、可测量的局部问题。
2. 提出一个结构清楚、与问题对应的改进。
3. 用严谨实验说明它在什么条件下有效。
4. 诚实说明计算成本、失败场景和适用边界。
5. 把代码、数据协议、结果和论文完整交付。

一个真正形成成果的项目，最终应该留下：

```text
可信 baseline
固定数据划分
清楚的问题定义
可复现的新方法代码
完整消融和对比实验
每类/每病例结果
效率与失败分析
论文稿件
可公开或可归档的实验材料
```

所以，你不应把任务理解成“在 EMCAD 上加什么模块能发论文”，而应理解成：

> **利用 EMCAD 这个受控实验平台，发现一个它尚未解决的问题，提出一个可检验的解决机制，并构建足够严谨的证据链。**

这才是从基础模型走向创新、论文和科研成果的完整过程。
