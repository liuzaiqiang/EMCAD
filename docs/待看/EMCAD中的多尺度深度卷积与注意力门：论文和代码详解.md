# EMCAD 中的多尺度深度卷积与注意力门：论文和代码详解

核对日期：2026-09-22。依据：本项目的论文 PDF、`lib/decoders.py`、`lib/networks.py` 和 `train_synapse.py`。本文只解释结构，不修改模型代码，不把示意数值当作训练实测结果。

## 1. 先把两句话说清楚

你说的“尺度深度卷积”，在 EMCAD 中准确对应 **多尺度深度卷积（Multi-scale Depth-wise Convolution，MSDC）**。

- 多尺度：对同一份特征使用不同大小的卷积核，默认是 1×1、3×3、5×5。
- 深度卷积：这里的 depth-wise 指“逐通道卷积”，不是网络层数深，也不是沿 CT 的前后切片方向卷积。
- 注意力门：主要对应 **大核分组注意力门（Large-kernel Grouped Attention Gate，LGAG）**，用解码特征和编码器跳跃连接特征共同计算权重，再筛选跳跃连接信息。

一句话区分：**MSDC 负责从不同邻域提取信息，LGAG 负责决定跳跃连接中的信息保留多少。** 两者解决的问题不同，也不是替代关系。

|---|---|---|---|
| MSDC | 第 3.1.2 节，图 2(f)，公式 (5)、(6) | `lib/decoders.py:254`，`class MSDC` | 4 个，每个 MSCB 中一个 |

注意包含关系：**MSDC 在 MSCB 里面，MSCB 又是 MSCAM 的组成部分。LGAG 则位于跳跃连接融合处，不在 MSDC 里面。**

以下以 Synapse 默认训练入口、PVTv2-B2、输入 `[B,1,224,224]` 为例。`B` 是批量大小，特征布局是 `[批量,通道,高,宽]`。实际运行若覆盖配置，应以命令、配置和日志为准。

## 3. 先看两者在完整路径中的位置

输入经过可学习的 1→3 通道适配器，再由编码器产生四级特征：

| 编码特征 | 形状 | 含义 |
|---|---|---|
| x1 | `[B,64,56,56]` | 较高分辨率的特征 |
| x2 | `[B,128,28,28]` | 第二级特征 |
| x3 | `[B,320,14,14]` | 第三级特征 |
| x4 | `[B,512,7,7]` | 最深层特征 |

解码路径可以写成：

```text
x4 → CAB → SAB → MSCB（含 MSDC）→ d4
                                  ↓ EUCB 上采样
x3 ─────────────→ LGAG(g, x3) → 与 g 相加 → CAB → SAB → MSCB → d3
                                                                  ↓ EUCB
x2 ─────────────────────────────→ LGAG(g, x2) → 与 g 相加 → CAB → SAB → MSCB → d2
                                                                                  ↓ EUCB
x1 ─────────────────────────────────────────────→ LGAG(g, x1) → 与 g 相加 → CAB → SAB → MSCB → d1
```

每一级的 `g` 都指该级 EUCB 输出，不是所有级共享同一个张量。每个解码输出接自己的分割头。

更精确地，以第一个跳跃连接为例，实际代码为：

```python
d3 = self.eucb3(d4)
x3 = self.lgag3(g=d3, x=skips[0])
d3 = d3 + x3
d3 = self.cab3(d3) * d3
d3 = self.sab(d3) * d3
d3 = self.mscb3(d3)
```

来源：`lib/decoders.py:965` 起。这里不是先把两个特征直接拼接；实际是**跳跃连接先过门，再与解码主路逐元素相加**。

## 4. MSDC：“多尺度”到底体现在哪？

### 4.1 不同卷积核观察不同大小的特征邻域

假设当前特征为 `[B,128,56,56]`，默认并行 MSDC 会让它同时通过三条支路：

| 支路 | 在当前特征图上直接观察的范围 | 输出形状 |
|---|---|---|
| 1×1 depth-wise | 当前位置 | `[B,128,56,56]` |
| 3×3 depth-wise | 当前位置及周围一圈 | `[B,128,56,56]` |
| 5×5 depth-wise | 更宽的局部邻域 | `[B,128,56,56]` |

这里的 3×3、5×5 指**特征图上的位置范围**，不能直接理解为原始 CT 上的 3×3、5×5 像素。编码器已经提取过上下文，尤其 PVTv2 还包含注意力运算，所以它们也不是整个网络的完整感受野。

在器官分割中，不同邻域有机会提供局部变化、边界附近信息、周围组织关系等互补线索。但不能机械地说“1×1 只识别小器官，5×5 只识别肝脏”：各分支没有这样的人工职责标签，学到什么取决于数据和优化。

### 4.2 多尺度不是把图片缩放三次

默认 MSDC 中三个分支的空间尺寸相同；它改变的是卷积核大小，而不是分别生成 224、112、56 尺寸的输入。

EMCAD 还具有四级不同分辨率特征，这是另一层面的多尺度。应区分：

- 编码器/解码器层级：7、14、28、56 等不同空间分辨率。
- 同一 MSDC 内：同一分辨率上采用 1、3、5 不同卷积核。

## 5. MSDC：“深度卷积”到底体现在哪？

### 5.1 关键不是名字，而是 groups

项目真实代码的核心是：

```python
nn.Conv2d(
    self.in_channels, self.in_channels,
    kernel_size, stride, kernel_size // 2,
    groups=self.in_channels, bias=False
)
```

来源：`lib/decoders.py:279`。

当输入和输出通道都是 128，且 `groups=128` 时，每个输入通道独立使用一个卷积核生成对应输出通道。

普通卷积会把多个输入通道的信息加权组合到一个输出通道；这里的 depth-wise 卷积不做这种跨通道组合。它只在每个通道内部进行空间计算。

例如某个通道的一块 3×3 区域为：

```text
1  2  1
0  3  0
1  2  1
```

为方便演示，假设卷积核九个值都是 1/9，则该位置的卷积结果为 `11/9≈1.222`。另一个通道独立计算自己的值，不会加入这个通道的求和。

实际卷积核是训练学到的，不一定是平均滤波器；卷积后还经过 BN 和激活，所以 1.222 也不是完整分支的最终输出。

### 5.2 为什么这样更省？

忽略 bias、BN，仅比较输入输出通道均为 C 的卷积核参数：

- 普通 k×k 卷积：`C × C × k²`。
- depth-wise k×k 卷积：`C × k²`。

取 C=128、k=3：

- 普通卷积：147,456 个权重。
- depth-wise 卷积：1,152 个权重。
- 此单层的卷积核权重数量相差 128 倍。

三个 depth-wise 分支 `[1,3,5]` 一共是 `128×(1+9+25)=4,480` 个卷积权重。

**这不意味着整个 EMCAD 少了 128 倍参数，也不意味着推理快了 128 倍。** 还要计算 1×1 卷积、其他模块、编码器，以及硬件上的实际算子效率。

### 5.3 缺失的跨通道交流从哪里补？

MSDC 外面的 MSCB 有普通 1×1 卷积，它们可以混合不同通道；中间还有通道重排。

注意：channel shuffle 只是改变通道排列，不会自己把两个数加权融合。真正的可学习跨通道组合主要由普通 1×1 卷积完成。不能把 shuffle 说成额外提取了新空间特征。

## 6. 把最后一级 MSCB 的尺寸和数值完整串起来

最后一级进入 MSCB 的特征为 `[B,64,56,56]`，它已经经过 CAB 和 SAB。默认扩张倍数为 2，步幅为 1，分支融合为相加。

| 步骤 | 操作 | 输出 |
|---|---|---|
| 1 | 普通 1×1 卷积，64→128；BN；ReLU6 | `[B,128,56,56]` |
| 2 | MSDC 的 1×1 depth-wise；BN；ReLU6 | `[B,128,56,56]` |
| 3 | MSDC 的 3×3 depth-wise；BN；ReLU6 | `[B,128,56,56]` |
| 4 | MSDC 的 5×5 depth-wise；BN；ReLU6 | `[B,128,56,56]` |
| 5 | 三个分支逐元素相加 | `[B,128,56,56]` |
| 6 | channel shuffle，groups=gcd(128,64)=64 | `[B,128,56,56]` |
| 7 | 普通 1×1 卷积，128→64；BN | `[B,64,56,56]` |
| 8 | 加上 MSCB 输入的残差 | `[B,64,56,56]` |

假设同一位置、同一通道上三个分支的最终数值是 0.8、1.3、0.4，则融合值为 **2.5**。这里不是平均值，没有自动除以 3，也没有单独的三个动态尺度权重。

在 ReLU6 配置下，每条分支的值在 `[0,6]`，三个分支相加后可以到 18。后面的 1×1 卷积和 BN 会继续变换，MSCB 的最终输出并不受 `[0,6]` 约束，可能为负。

假设某个最终输出位置上，残差输入是 0.7，投影和 BN 后的新特征是 -0.2，则该位置输出为 0.5。这里的数值仅解释运算，不代表本项目的实测激活。

### 6.1 为什么在代码里看到 MSDC 返回的是列表？

论文公式 (5) 将分支求和写在 MSDC 数学表达中；代码将职责拆开：

- `MSDC.forward`：生成三个分支，返回 `outputs` 列表。
- `MSCB.forward`：接收列表，在 `add=True` 时完成求和。

这是实现边界不同，不是默认多尺度求和消失了。

另外，论文公式 (4) 展示的变换链没有显式写出代码里的最终残差加法。理解当前项目时，应以 `MSCB.forward` 的 `return x + out` 为准，不能仅照公式省略残差。

### 6.2 另外两种配置

- `dw_parallel=False`：后续分支接收递归更新后的 `x = x + dw_out`，不是三条支路都处理原始输入。
- `add=False`：三个分支沿通道拼接，上例得到 `[B,384,56,56]`，之后再用 1×1 卷积投影。

两者是不同开关。`add` 不控制解码器与 skip 的融合，也不控制 MSCB 最后的残差相加。

## 7. 注意力门 LGAG 究竟在做什么？

### 7.1 用“复核员”理解，但不要把比喻当实际语义

编码器 skip 中有细节，也有无关组织和纹理。解码器上采样特征携带当前阶段的语义线索，但定位细节可能不够精细。

LGAG 类似一个复核环节：结合两路特征，为每个位置算一个软权重，决定这个位置的 skip 特征通过多少。

它不是手写规则，也不知道哪个位置一定属于胃。它通过分割损失反向传播学习参数，并可能学错。

### 7.2 两个输入分别是什么？

第一次门控的真实调用是：

```python
x3 = self.lgag3(g=d3, x=skips[0])
```

- `g`：EUCB 上采样后的解码特征，`[B,320,14,14]`。
- `x`：编码器的 x3 跳跃连接特征，`[B,320,14,14]`。
- 门控结果：`x * psi`，即筛选的是 skip，不是直接筛选 g。

**论文与代码的命名差异：**本地 PDF 第 3.1.1 节的文字把 g 括注为 skip 特征、x 括注为上采样特征；当前代码的传参来源相反。本文明确遵循实际 `EMCAD.forward` 的调用关系，不把论文这段文字与代码说成完全一致。

### 7.3 第一个 LGAG 的逐步计算

本项目创建 lgag3 时设置 `F_g=320`、`F_l=320`、`F_int=160`、`kernel_size=3`、`groups=160`。

| 步骤 | 运算 | 形状 |
|---|---|---|
| 1 | g 经 3×3 分组卷积，320→160；BN | `[B,160,14,14]` |
| 2 | x 经独立的 3×3 分组卷积，320→160；BN | `[B,160,14,14]` |
| 3 | 两路逐元素相加，再 ReLU | `[B,160,14,14]` |
| 4 | 普通 1×1 卷积，160→1；BN | `[B,1,14,14]` |
| 5 | Sigmoid，形成 psi | `[B,1,14,14]` |
| 6 | 原始 x 乘 psi，沿通道广播 | `[B,320,14,14]` |
| 7 | 在 LGAG 外部与 g 相加 | `[B,320,14,14]` |

对应实际代码：

```python
g1 = self.W_g(g)
x1 = self.W_x(x)
psi = self.activation(g1 + x1)
psi = self.psi(psi)
return x * psi
```

可写成：

`alpha = sigmoid(BN(Conv1×1(ReLU(BN(GConv3×3(g)) + BN(GConv3×3(x))))))`

`gated_skip = x ⊙ alpha`

`fused = g + gated_skip`

这里两路 BN 分别处理各自卷积结果，不是把两路先相加再只做一个 BN。

### 7.4 “门”为什么不是简单开和关？

假设某位置进入 Sigmoid 前的标量为 2，则权重约为 0.881；另一个位置是 -2，则权重约为 0.119。

若两个位置原有某通道值都是 4：

- 第一个位置：`4×0.881≈3.524`。
- 第二个位置：`4×0.119≈0.476`。

这是连续软门控，不是对位置做硬删除。对有限输入，Sigmoid 数学上位于 `(0,1)`；数值计算时可能非常接近甚至舍入到端点。

还有三个关键细节：

1. alpha 是每个位置一个数，同位置的全部 320 个通道共享这个权重，不是 320 张独立门图。
2. alpha 不是器官分割概率，也不是“属于胃”的概率；它只是中间特征的门控权重。
3. 单独 `x×alpha` 不会把 x 的绝对值放大。所谓突出相关特征，更多是相对于被压低的其他位置而言；后续相加和卷积可以再改变幅值。

## 8. LGAG 的分组卷积，为什么不是 MSDC 那种深度卷积？

对于 lgag3：输入通道 320，输出通道 160，分组数 160。

- 每组输入 2 个通道。
- 每组输出 1 个通道。
- 每组内部可以对那两个输入通道进行加权组合。

而 MSDC 的 depth-wise 卷积中，每组输入 1 个通道、输出 1 个通道。

**深度卷积是分组卷积的特殊形式，但 LGAG 当前这两个 3×3 投影并不是 depth-wise 卷积。**

lgag3 单条投影仅计算卷积核权重时：

- 当前分组 3×3：`160×(320/160)×9=2,880`。
- 相同输入输出通道的普通 3×3：`160×320×9=460,800`。
- 相同输入输出通道的普通 1×1：`160×320=51,200`。

可见，采用更大的空间核，并不一定更昂贵：分组数也决定成本。但这个比较不包含完整门控中的两路投影、bias、BN、psi 等全部参数。

论文中“large-kernel”是相对经典注意力门的 1×1 投影而言，当前默认是 3×3。不要把它误读为默认使用 7×7、31×31 等现代大核设计。

## 9. 三个 LGAG 和四个 MSDC 的尺寸总表

| 解码阶段 | 进入该级 MSCB 的形状 | MSDC 内部各分支形状（扩张×2） | 该级 LGAG 的中间通道 | 门图 |
|---|---|---|---|---|
| d4 | `[B,512,7,7]` | `[B,1024,7,7]` | 无 | 无 |
| d3 | `[B,320,14,14]` | `[B,640,14,14]` | 160 | `[B,1,14,14]` |
| d2 | `[B,128,28,28]` | `[B,256,28,28]` | 64 | `[B,1,28,28]` |
| d1 | `[B,64,56,56]` | `[B,128,56,56]` | 32 | `[B,1,56,56]` |

最深层 d4 直接处理 x4，因此该处没有另一路待融合的 skip，也就没有第四个 LGAG。

四级各含三个 depth-wise 分支，所以这些 MSDC 合计有 12 个 depth-wise 卷积层。三个 EUCB 中另有单尺度 depth-wise 卷积，不能漏算，也不能把 EUCB 误称为 MSDC。

## 10. LGAG 和 CAB、SAB、自注意力有什么区别？

| 模块 | 接收什么 | 权重形状 | 主要作用 |
|---|---|---|---|
| CAB | 当前一份特征 | `[B,C,1,1]` | 给不同通道不同权重 |
| SAB | 当前一份特征 | `[B,1,H,W]` | 给不同空间位置不同权重 |
| LGAG | g 与 skip 两份特征 | `[B,1,H,W]` | 用两路信息共同决定 skip 哪些位置通过多少 |
| PVTv2 自注意力 | 编码器中的 token 特征 | token 关系权重，具体尺寸依阶段和空间缩减设置而变 | 聚合位置之间的上下文信息 |

LGAG 和 SAB 都能产生空间权重，但信息来源、所在位置和任务不同。LGAG 也不是计算 Q、K、V 的 Transformer 自注意力。

MSDC 本身不是注意力门；默认三分支直接相加，没有“针对当前病例动态给三个尺度分配 softmax 权重”的机制。周围存在 CAB、SAB，并不等于 MSDC 已实现显式的尺度选择器。

## 11. 两者如何配合帮助器官分割？

以胃附近的一片组织为教学场景：

1. 编码器提取包括胃、周围组织和边界线索的特征，但通道并不与器官一一对应。
2. EUCB 把深层解码特征上采样到与 skip 相同的空间大小。
3. LGAG 结合两路信息，有机会压低不相关位置的 skip 响应，保留有用细节。
4. 筛选后的 skip 与主路相加；CAB、SAB 进一步重加权。
5. MSCB 内的 MSDC 从多种局部邻域提取信息，随后跨通道融合并保留残差。
6. 更高分辨率阶段重复此过程，最后分割头输出类别 logits。

这是一种合理机制解释，不代表模型真的有“胃专家”“边界专家”这样的固定分工，也不构成其已经改善胃分割的实测证据。

它们也有局限：门控可能误压低小器官；多尺度提取不能恢复输入中已丢失的信息；二维卷积不会自动看见前后 CT 切片；更低计算量不保证每台设备上都更快。

## 12. 论文有没有证据证明它们有用？

有，但应按消融边界解读。以下是本地论文原表，不是本轮重新训练所得结果。

### 12.1 表 4：LGAG 和 MSCAM 的组件消融

Synapse、PVTv2-B2，论文报告五次运行的平均结果：

| Cascaded | LGAG | MSCAM | 平均 Dice（%） |
|---|---|---|---|
| 否 | 否 | 否 | 80.10 ± 0.2 |
| 是 | 否 | 否 | 81.08 ± 0.2 |
| 是 | 是 | 否 | 81.92 ± 0.2 |
| 是 | 否 | 是 | 82.86 ± 0.3 |
| 是 | 是 | 是 | 83.63 ± 0.3 |

解读：在有级联和 MSCAM 的条件下，加入 LGAG 的平均 Dice 差值是 **0.77 个百分点**。在级联基线上加入 MSCAM，差值是 **1.78 个百分点**。

但 MSCAM 包含 CAB、SAB 和 MSCB，不能把 1.78 全部归功于 MSDC；上述差值也不能当作你的新实验必然复现的增益。表中的 ± 沿用原文标记，本文不自行认定其为置信区间。

## 13. 当前项目的默认参数，别看错入口

| 参数 | Synapse 训练脚本默认值 | 影响 |
|---|---|---|
| `kernel_sizes` | `[1,3,5]` | MSDC 三种卷积核 |
| `expansion_factor` | `2` | MSCB 中 C→2C |
| `no_dw_parallel` | `False` | 实际传入 `dw_parallel=True` |
| `concatenation` | `False` | 实际传入 `add=True` |
| `lgag_ks` | `3` | LGAG 两路分组投影的核大小 |
| `activation_mscb` | `relu6` | MSCB/MSDC 的激活函数 |

来源：`train_synapse.py:53` 起的参数定义及 `:216` 起的构造调用。

两个容易踩的坑：

1. `lib/decoders.py` 中 `EMCAD` 类自身默认扩张倍数是 6，但 `EMCADNet` 默认传入 2，Synapse 脚本也默认传入 2。正常训练路径不能照孤立类签名算成六倍。
2. `EMCADNet` 自身的 `activation` 默认是 `relu`，但 Synapse 脚本显式传入 `relu6`。本文的 ReLU6 数值范围针对这个默认训练入口，不代表所有直接实例化方式。

此外，`lgag_ks=1` 时，LGAG 构造函数会将 `groups` 强制设为 1。因此这个开关不只是把 3×3 换成 1×1，也同时改变分组方式；将其作为消融时必须说明这一点。

## 14. 以后想改进它们，应该问什么？

本次不改代码。如果后续要提高 Dice，可以从明确假设出发：

- 改 MSDC：你认为直接求和会掩盖不同病例、位置的尺度差异吗？如果引入动态权重，要比较参数匹配替代方案，而不是预设一定更好。
- 改 LGAG：现有单张空间门图是否压低了小器官线索？可以记录门值分布并关联错误区域，但门图可视化不等于因果证明。
- 评估时：固定患者级划分和训练预算，用验证集做选择，报告平均及各器官 Dice、病例差异、HD95 和效率；不要反复用测试集选择模块。

目前已确认的是结构和论文证据；本次未加载训练权重、未运行前向 hooks、未重新训练，所以不声称已测得你模型的真实中间数值或独立模块增益。

## 15. 最后记住这四句话

1. **MSDC：用不同大小的逐通道卷积核，在较低开销下提取不同邻域的信息。**
2. **MSCB：在 MSDC 外加通道扩张、融合、重排、投影与残差，补齐完整特征处理链。**
3. **LGAG：结合解码主路和编码 skip，算出空间软门，筛选 skip 后再相加融合。**
4. **论文卖点不是“多用几个卷积核一定涨分”，而是在实验中实现更好的精度与解码成本平衡。**
