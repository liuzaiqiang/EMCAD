# 多尺度深度卷积与深度可分离卷积详解

## 先给结论

**多尺度深度卷积（multi-scale depth-wise convolution）和深度可分离卷积（depthwise separable convolution）不是一回事。**

可以把它们看成回答两个不同问题的设计：

| 概念 | 它主要回答什么问题 | 关注的核心维度 |
| --- | --- | --- |
| 多尺度深度卷积 | 同一层特征要不要同时观察大小不同的邻域？ | 空间范围、感受野、分支尺度 |
| 深度可分离卷积 | 能不能把昂贵的普通卷积拆成更便宜的两步？ | 空间处理与通道混合的计算分解 |

所以：

1. 一个模块可以是多尺度的，但不是深度可分离的。
2. 一个模块可以是深度可分离的，但只有一个尺度。
3. 一个模块也可以同时具备两者：使用多个不同大小的深度卷积分支，再用 1x1 点卷积融合通道。

EMCAD 中正是这种“两个概念组合使用”的情况：MSDC 负责多尺度深度卷积分支，MSCB 负责把这些分支嵌入扩张、融合和残差结构中，EUCB 则使用了非常典型的“深度卷积 + 1x1 点卷积”高效路径。

## 1. 先把“卷积”说清楚

设输入特征图的形状是：

~~~text
X: [B, C_in, H, W]
~~~

其中：

- B：batch size，一次送入网络的图像数量。
- C_in：输入通道数。医学图像网络中的通道可以理解为不同类型的特征响应，例如边缘、纹理、形状、组织区域等。
- H、W：特征图的高和宽。
- C_out：卷积输出通道数。
- k：卷积核边长，例如 3x3 卷积的 k=3。

### 1.1 普通卷积在做什么

普通 2D 卷积的一个输出通道，会同时查看：

1. 所有输入通道；
2. 每个输入通道的一个空间邻域；
3. 用不同权重把这些信息混合起来。

用简化的文字公式表示：

~~~text
输出[o, i, j]
  = 所有输入通道 c、所有卷积位置 (u, v) 的
    输入[c, i+u, j+v] * 权重[o, c, u, v] 的加权求和
~~~

普通卷积的权重张量形状大致是：

~~~text
[C_out, C_in, k, k]
~~~

忽略 bias 时，参数量约为：

~~~text
k * k * C_in * C_out
~~~

它的优点是表达能力强，因为一个输出通道可以在每一个空间位置同时利用所有输入通道的信息；缺点是参数量和计算量都比较大。

例如，3x3、C_in=32、C_out=64 的普通卷积，忽略 bias 时需要：

~~~text
3 * 3 * 32 * 64 = 18,432 个卷积权重
~~~

普通卷积把两件事一次完成了：

- 空间混合：观察邻近像素或邻近特征位置；
- 通道混合：把不同通道的特征组合起来。

深度可分离卷积要做的，就是把这两件事拆开；多尺度深度卷积要做的，则是让空间观察范围不只有一种大小。

## 2. 什么是多尺度深度卷积

### 2.1 “多尺度”是什么意思

卷积核大小决定一次卷积能观察多大的局部邻域：

- 1x1：只看当前位置，不看周围空间邻域；
- 3x3：看当前位置及其附近区域；
- 5x5：看更宽的局部区域；
- 更大的卷积核或空洞卷积：可以进一步扩大有效感受野。

医学图像分割中的目标大小变化很大：

- 小病灶或细血管需要关注细粒度边缘和纹理；
- 中等大小结构需要适度上下文；
- 大器官或大面积病变需要更宽的区域信息。

如果一层只使用 3x3，它的观察范围比较固定。**多尺度卷积**就是在同一层建立多个空间观察尺度，例如同时建立 1x1、3x3、5x5 三条分支。

### 2.2 “深度卷积”是什么意思

这里的“深度”不是“网络很深”，也不是“卷积层数很多”，而是英文 **depth-wise** 的翻译。

深度卷积通常设置：

~~~python
nn.Conv2d(C, C, kernel_size=k, groups=C)
~~~

groups=C 的含义是：把 C 个通道分成 C 组，每组只有一个通道。于是：

- 第 1 个卷积核只处理第 1 个通道；
- 第 2 个卷积核只处理第 2 个通道；
- ……；
- 不同通道之间在这一步不直接交流。

因此，一个 k x k、输入输出通道都为 C 的深度卷积，忽略 bias 时参数量约为：

~~~text
k * k * C
~~~

而不是普通卷积的：

~~~text
k * k * C * C
~~~

它非常省参数，但单独使用时不能完成通道之间的充分混合，所以通常还要配合 1x1 点卷积。

### 2.3 多尺度深度卷积的完整结构

一个典型的多尺度深度卷积模块可以这样理解：

~~~text
                    ┌─ depth-wise 1x1 ─┐
输入 X ─────────────┼─ depth-wise 3x3 ─┼─ 融合 ─ 输出 Y
                    └─ depth-wise 5x5 ─┘
~~~

每一条分支都使用深度卷积，但不同分支采用不同卷积核大小。

设三条分支分别为 D_1、D_3、D_5，则：

~~~text
Y_1 = D_1(X)
Y_3 = D_3(X)
Y_5 = D_5(X)
~~~

融合方式可以是：

~~~text
逐元素相加：Y = Y_1 + Y_3 + Y_5
~~~

也可以是：

~~~text
通道拼接：Y = concat(Y_1, Y_3, Y_5, dim=channel)
~~~

还可以在融合后加一个普通 1x1 点卷积，把各尺度的通道信息重新组合起来。

### 2.4 多尺度深度卷积的例子

假设输入特征为：

~~~text
X: [B, 64, 128, 128]
~~~

建立三条并行深度卷积分支：

~~~text
分支 A：depth-wise 1x1，输出 [B, 64, 128, 128]
分支 B：depth-wise 3x3，输出 [B, 64, 128, 128]
分支 C：depth-wise 5x5，输出 [B, 64, 128, 128]
~~~

如果采用逐元素相加：

~~~text
[B, 64, 128, 128]
+ [B, 64, 128, 128]
+ [B, 64, 128, 128]
= [B, 64, 128, 128]
~~~

输出通道数不会增加，但每个位置的响应同时包含了三种空间范围的信息：

- 1x1 分支更接近当前位置的逐点响应；
- 3x3 分支补充局部边缘、纹理和邻域关系；
- 5x5 分支补充更宽的局部上下文。

如果只比较深度卷积分支的卷积权重，三条分支的参数量是：

~~~text
64 * (1*1 + 3*3 + 5*5)
= 64 * 35
= 2,240
~~~

如果把它换成三个普通的 64 -> 64 卷积分支，卷积权重约为：

~~~text
64 * 64 * 35 = 143,360
~~~

所以多尺度深度卷积保留了多尺度观察能力，同时利用深度卷积降低了空间卷积的成本。但它仍然有三条分支，因此实际运行时间不会等于单个 3x3 深度卷积的时间。

### 2.5 多尺度不一定等于多个卷积核

“多尺度”是一个更宽泛的设计思想，常见实现包括：

1. 多个卷积核：1x1、3x3、5x5。
2. 相同卷积核、不同空洞率：例如 dilation 为 1、2、3。
3. 不同分辨率分支：一条分支保留原分辨率，另一条分支先池化再处理。
4. 图像金字塔或特征金字塔。
5. 串行累积的不同尺度卷积。

因此看到“多尺度”，首先要问：**它到底通过什么机制产生不同尺度？** 不要默认所有多尺度模块都使用 1x1/3x3/5x5。

### 2.6 多尺度深度卷积的优势

#### 优势 1：适应目标大小变化

不同尺度分支可以同时处理小目标、一般目标和较大结构。对于医学图像，病灶大小、器官边界和纹理范围往往差异很大，这种设计比单一卷积核更灵活。

#### 优势 2：兼顾细节和上下文

小卷积核偏向局部细节，大卷积核提供更宽上下文。分割网络既要知道“这个像素是不是边界”，也要知道“这个边界是否属于目标区域”，多尺度有助于同时获得这两类信息。

#### 优势 3：深度卷积分支的参数量较低

如果每个尺度都使用深度卷积，参数量远小于多个普通卷积，适合解码器、边缘设备或对计算量敏感的模型。

#### 优势 4：可以按任务调整

可以选择更多或更少的尺度，也可以把分支设为并行、串行、相加或拼接，具有较强的结构可调性。

### 2.7 多尺度深度卷积的劣势

#### 劣势 1：分支越多，运行开销越大

虽然每条深度卷积分支很便宜，但 1x1/3x3/5x5 三条分支仍需要三次卷积、三次归一化和三次激活。GPU 或其他加速器还要承担更多 kernel launch、特征读写和中间张量保存。

#### 劣势 2：深度卷积本身缺少通道交流

每个深度卷积分支只在各自通道内处理空间信息。如果没有后续点卷积、注意力或其他融合操作，不同通道之间的信息交换会不足。

#### 劣势 3：多个尺度可能产生冗余

如果训练数据很少，3x3 和 5x5 分支学到的内容可能高度相似；新增分支不一定带来有效信息，反而可能增加过拟合风险。

#### 劣势 4：分支融合方式会影响效果

- 相加不会增加通道数，计算和显存较省，但不同分支的独立信息可能被直接混合；
- 拼接保留的信息更多，但通道数增加，后续 1x1 融合层会变重；
- 串行分支有累积关系，但不同分支不再完全独立，训练和分析更复杂。

#### 劣势 5：大卷积核不等于全局理解

5x5 只是比 3x3 看得更宽，仍然是局部感受野。对于很大的器官或远距离依赖，还需要更深层网络、空洞卷积、池化、Transformer 或其他全局建模方法。

## 3. 什么是深度可分离卷积

### 3.1 核心思想：把普通卷积拆成两步

普通卷积同时做“空间混合”和“通道混合”。深度可分离卷积把它拆成：

~~~text
第一步：depth-wise convolution
      每个通道独立做空间卷积

第二步：point-wise convolution
      使用 1x1 普通卷积混合通道
~~~

数据流是：

~~~text
输入 X
  -> depth-wise kxk
  -> point-wise 1x1
  -> 输出 Y
~~~

### 3.2 第一步：depth-wise 空间卷积

输入：

~~~text
[B, C_in, H, W]
~~~

深度卷积通常保持通道数：

~~~text
[B, C_in, H, W]
  -> depth-wise kxk
     groups=C_in
  -> [B, C_in, H', W']
~~~

这一步的职责是：对每个通道分别观察空间邻域。它回答的是：

> 当前通道附近的像素或特征如何变化？

它不负责充分回答：

> 不同通道之间如何组合？

### 3.3 第二步：point-wise 1x1 卷积

随后使用普通的 1x1 卷积：

~~~python
nn.Conv2d(C_in, C_out, kernel_size=1)
~~~

它不会查看周围位置，只在每一个 (i, j) 位置上对通道向量做线性组合：

~~~text
[x_1, x_2, ..., x_Cin]
  -> 1x1 卷积
  -> [y_1, y_2, ..., y_Cout]
~~~

因此，1x1 点卷积的职责是：

- 混合通道；
- 改变通道数；
- 把深度卷积产生的各通道空间响应组合成新的语义特征。

### 3.4 深度可分离卷积的参数量

输入通道为 C_in、输出通道为 C_out、空间核为 k x k 时：

普通卷积参数量约为：

~~~text
k * k * C_in * C_out
~~~

深度可分离卷积参数量约为：

~~~text
depth-wise:  k * k * C_in
point-wise:  1 * 1 * C_in * C_out
总计：       k * k * C_in + C_in * C_out
~~~

当通道数较大时，节省非常明显。

### 3.5 深度可分离卷积的例子

假设：

~~~text
输入： [B, 32, 64, 64]
目标输出： [B, 64, 64, 64]
空间卷积核：3x3
~~~

深度可分离卷积的处理过程：

~~~text
输入
  [B, 32, 64, 64]
       |
       | depth-wise 3x3, groups=32
       | 每个通道单独处理
       v
  [B, 32, 64, 64]
       |
       | point-wise 1x1, 32 -> 64
       | 每个位置进行通道混合
       v
  [B, 64, 64, 64]
~~~

参数量为：

~~~text
depth-wise: 3 * 3 * 32 = 288
point-wise: 1 * 1 * 32 * 64 = 2,048
总计：2,336
~~~

同样输入输出通道下的普通 3x3 卷积需要：

~~~text
3 * 3 * 32 * 64 = 18,432
~~~

在这个例子中，深度可分离卷积的卷积权重大约只有普通卷积的八分之一左右。注意，这个比例是参数量或理论乘加量的比较；实际速度还会受到硬件、内存访问、框架实现和批大小影响。

### 3.6 为什么它不是普通卷积的完全等价替换

普通卷积的权重可以写成：

~~~text
W[out_channel, in_channel, u, v]
~~~

也就是说，对每个输入通道、每个输出通道和每个空间位置，都可以有独立权重。

深度可分离卷积则先对每个输入通道使用一个空间核，再由 1x1 卷积把通道混合。它相当于对普通卷积的连接关系施加了结构约束，表达能力通常低于同规模的普通卷积。

因此它的真实取舍是：

~~~text
少很多参数和计算
换取一定程度的表达能力下降或优化难度变化
~~~

在很多视觉任务中，这种取舍是值得的，尤其是网络很大、部署资源有限时；但不能假设替换后精度一定完全不变。

### 3.7 深度可分离卷积的优势

#### 优势 1：参数量和理论计算量低

它把最昂贵的 k*k*C_in*C_out 分解为 k*k*C_in + C_in*C_out，通常能显著降低模型大小和乘加次数。

#### 优势 2：适合移动端和边缘设备

移动端、嵌入式设备或显存有限的环境通常不能承受大量普通卷积。深度可分离卷积可以减少模型存储、权重传输和部分计算压力。

#### 优势 3：职责分离清晰

深度卷积负责空间模式，点卷积负责通道组合，结构容易解释，也方便作为轻量模块嵌入更大的网络。

#### 优势 4：容易和上采样、残差、注意力组合

例如可以先上采样，再用深度卷积修整局部空间响应，最后用点卷积改变通道数；这正是 EMCAD 中 EUCB 的基本思路。

### 3.8 深度可分离卷积的劣势

#### 劣势 1：表达能力可能下降

空间处理阶段不允许不同通道直接交互，只能等到后面的 1x1 卷积再混合。对于需要复杂跨通道空间关系的任务，可能不如普通卷积灵活。

#### 劣势 2：理论省计算不等于实际一定快

深度卷积的每个通道相互独立，计算密度低，可能受到内存访问和 kernel launch 的限制。在某些 GPU、CPU 或推理框架上，理论 FLOPs 很低，但实际延迟并没有按同样比例下降。

#### 劣势 3：点卷积仍可能很重

当输入和输出通道很多时，1x1 点卷积本身需要 C_in*C_out 个权重，可能成为主要计算来源。不能只看到深度卷积很便宜，就忽略点卷积的成本。

#### 劣势 4：对归一化、激活和训练设置较敏感

在小 batch 医学图像训练中，BatchNorm 的统计稳定性、学习率、初始化和激活函数都会影响轻量模块的训练效果。模块轻量不代表训练一定更容易。

#### 劣势 5：硬件支持差异较大

某些硬件对规则的普通卷积优化得很好，却不一定对深度卷积有同等高效的实现。因此部署前应实际测量参数量、显存、吞吐和端到端延迟。

## 4. 两个概念到底差在哪里

### 4.1 它们改变的是不同东西

可以把卷积设计拆成两个问题：

~~~text
问题 A：空间上看多大范围？
问题 B：空间处理和通道混合要不要拆开？
~~~

多尺度深度卷积主要解决问题 A：

~~~text
1x1、3x3、5x5 等多个尺度一起看
~~~

深度可分离卷积主要解决问题 B：

~~~text
depth-wise 空间卷积 -> point-wise 通道混合
~~~

所以它们是**正交的设计维度**，不是同义词。

### 4.2 四种组合情况

| 结构 | 是否多尺度 | 是否深度可分离 | 说明 |
| --- | ---: | ---: | --- |
| 一个普通 3x3 卷积 | 否 | 否 | 单一尺度，同时做空间和通道混合 |
| 多个普通卷积分支 | 是 | 否 | 有多个感受野，但每个分支都较重 |
| 一个 depth-wise 3x3 + 一个 point-wise 1x1 | 否 | 是 | 单尺度的轻量卷积 |
| 多个 depth-wise 分支 + point-wise 融合 | 是 | 可以是 | 同时获得多尺度和轻量化 |

### 4.3 用一个比喻理解

假设要检查一张医学图像：

- **多尺度**像是拿小、中、大三把尺子观察同一片区域：解决“看多宽”。
- **深度可分离**像是先分别检查每种特征，再把各类特征在每个位置汇总：解决“先分别处理，再混合”。

一把小尺子、中尺子和大尺子可以都采用“分别检查每类特征”的方式。因此多尺度和深度可分离可以同时存在。

## 5. EMCAD 代码中如何对应这两个概念

本节对应当前项目中的 lib/decoders.py。代码已经有详细注释，这里从概念角度把数据流重新串起来。

### 5.1 MSDC：多尺度深度卷积本体

在 lib/decoders.py 的 MSDC 类中，核心代码逻辑是：

~~~python
nn.Conv2d(
    self.in_channels,
    self.in_channels,
    kernel_size,
    stride,
    kernel_size // 2,
    groups=self.in_channels,
    bias=False,
)
~~~

这里同时出现了两个关键点：

1. kernel_size 来自 kernel_sizes，默认是 [1, 3, 5]，所以有多个空间尺度。
2. groups=self.in_channels，所以每条分支是 depth-wise 卷积。

因此 MSDC 的准确含义是：

~~~text
Multi-scale depth-wise convolution
多个不同卷积核大小的深度卷积分支
~~~

它内部每条分支的顺序是：

~~~text
depth-wise kxk -> BatchNorm2d -> 激活函数
~~~

MSDC.forward() 返回的是一个列表：

~~~text
[输出_1x1, 输出_3x3, 输出_5x5]
~~~

它本身还没有决定最终是相加还是拼接，这个决定交给外层 MSCB。

### 5.2 MSCB：把 MSDC 放进完整的多尺度卷积块

当前 EMCAD 的 MSCB 可以画成：

~~~text
输入 x
  |
  | 1x1 point-wise pconv1：通道扩张
  | C_in -> C_ex
  v
扩张后的特征
  |
  | MSDC：1x1/3x3/5x5 depth-wise 分支
  v
多个尺度输出
  |
  | add=True 时逐元素相加
  | add=False 时通道拼接
  v
channel shuffle
  |
  | 1x1 point-wise pconv2：通道融合和投影
  | C_combined -> C_out
  v
与输入相加的残差输出（stride=1 时）
~~~

这说明：

- MSDC 是多尺度深度卷积部分；
- pconv1 和 pconv2 是普通 1x1 点卷积，负责通道扩张、通道融合和通道投影；
- 整个 MSCB 采用了倒残差式设计：先用 1x1 扩张通道，再在较宽的中间特征上做便宜的深度卷积，最后用 1x1 压回输出通道；
- stride=1 时还会使用残差连接。

因此，**不能把 MSDC 单独直接称作完整的深度可分离卷积**。它是多尺度深度卷积模块；MSCB 则把它和前后两个点卷积、分支融合及残差连接组合成了更大的块。

### 5.3 EMCAD 中 MSCB 的一个形状例子

以 PVTv2-B2 的一个解码层为例，假设输入为：

~~~text
x: [B, 64, 56, 56]
~~~

如果 expansion_factor=2，则：

~~~text
1. pconv1：64 -> 128
   [B, 64, 56, 56] -> [B, 128, 56, 56]

2. MSDC 三条分支
   depth-wise 1x1 -> [B, 128, 56, 56]
   depth-wise 3x3 -> [B, 128, 56, 56]
   depth-wise 5x5 -> [B, 128, 56, 56]

3. add=True，三条分支逐元素相加
   [B, 128, 56, 56]

4. channel shuffle
   形状仍为 [B, 128, 56, 56]

5. pconv2：128 -> 64
   [B, 128, 56, 56] -> [B, 64, 56, 56]

6. 与原输入残差相加
   [B, 64, 56, 56] + [B, 64, 56, 56]
   = [B, 64, 56, 56]
~~~

这就是“通道先扩张，多尺度深度卷积处理，再压回通道并保留残差”的完整过程。

### 5.4 EUCB：项目中更接近经典深度可分离路径的地方

lib/decoders.py 中的 EUCB 采用：

~~~text
最近邻上采样
  -> 3x3 depth-wise convolution
  -> BatchNorm + ReLU
  -> channel shuffle
  -> 1x1 point-wise convolution
~~~

其形状变化是：

~~~text
[B, C_in, H, W]
  -> 上采样
  -> [B, C_in, 2H, 2W]
  -> depth-wise 3x3，通道不变
  -> [B, C_in, 2H, 2W]
  -> point-wise 1x1，C_in -> C_out
  -> [B, C_out, 2H, 2W]
~~~

这里的 depth-wise 3x3 + point-wise 1x1 就非常接近教材中所说的深度可分离卷积路径，只是前面多了上采样，中间还保留了项目中的通道重排步骤。

### 5.5 EMCAD 中的准确表述

比较严谨的说法是：

> EMCAD 解码器使用了多尺度深度卷积和轻量化点卷积/深度卷积组合。其 MSDC 通过多个不同大小的 depth-wise 分支提取多尺度局部信息，MSCB 通过前后两个 1x1 点卷积完成通道扩张与融合，EUCB 通过上采样、depth-wise 空间细化和 point-wise 通道投影实现高效解码。

不够严谨的说法是：

> EMCAD 里的 MSDC 就是一个普通的深度可分离卷积。

原因是 MSDC 的核心是多个尺度的深度卷积分支，它本身返回多分支结果；而经典深度可分离卷积通常指一条 depth-wise kxk -> point-wise 1x1 的两阶段序列。

## 6. 如何从代码中识别它们

### 6.1 识别 depth-wise 卷积

重点看 groups：

~~~python
nn.Conv2d(C, C, kernel_size=3, groups=C)
~~~

通常表示每个通道单独卷积。

在当前项目中，以下形式就是典型线索：

~~~python
groups=self.in_channels
~~~

或：

~~~python
groups=dim
~~~

### 6.2 识别 point-wise 卷积

重点看卷积核是不是 1x1：

~~~python
nn.Conv2d(C_in, C_out, kernel_size=1)
~~~

它通常改变通道数，不改变 H、W，并负责跨通道线性组合。

### 6.3 识别深度可分离卷积

通常需要看到相邻或逻辑上配套的两步：

~~~text
depth-wise kxk, groups=C_in
        -> point-wise 1x1
~~~

如果只看到：

~~~text
多个 groups=C 的不同卷积分支
~~~

那只能说明它是多尺度深度卷积，还不能仅凭这一点称为完整深度可分离卷积。

### 6.4 识别多尺度卷积

重点看是否存在多个不同的：

- kernel_size；
- dilation；
- 分辨率分支；
- 池化尺度。

当前项目中：

~~~python
kernel_sizes=[1, 3, 5]
~~~

就是多尺度的直接证据。

## 7. 什么时候选哪一种

### 更适合使用多尺度深度卷积的情况

- 目标尺寸差异明显；
- 同时需要边缘细节和区域上下文；
- 任务是医学图像分割、目标检测、遥感等空间尺度变化明显的问题；
- 可以接受少量分支带来的额外开销；
- 需要在轻量计算和多尺度表达之间平衡。

### 更适合使用深度可分离卷积的情况

- 模型部署到移动端、嵌入式设备或边缘设备；
- 参数量、显存或推理功耗受限；
- 需要降低模型大小和理论计算量；
- 单一或少数空间尺度已经足够；
- 愿意用一定表达能力换取效率。

### 两者一起使用的情况

如果既希望处理不同大小的目标，又希望控制计算量，可以使用：

~~~text
多个不同大小的 depth-wise 分支
        -> 相加或拼接
        -> 1x1 point-wise 通道融合
~~~

这就是“多尺度 + 深度可分离思想”的组合，而不是把两个概念当作同一个术语。

## 8. 常见误解

### 误解 1：“深度卷积”就是网络很深

不是。这里的 depth-wise 是分组方式，常见判断依据是 groups=输入通道数。

### 误解 2：只要是 depth-wise 卷积，就是深度可分离卷积

不是。深度可分离卷积通常还需要后面的 1x1 point-wise 卷积完成通道混合。单独一个 depth-wise 卷积只是深度卷积。

### 误解 3：多尺度深度卷积等于多个普通卷积

不一定。多尺度只说明有多个尺度；这些分支可以是普通卷积，也可以是深度卷积、空洞卷积或其他算子。

### 误解 4：多尺度分支越多，效果一定越好

不一定。分支会带来更多计算、显存和融合难度；如果数据量小或尺度设计重复，可能没有收益甚至过拟合。

### 误解 5：参数少就一定推理快

不一定。实际速度还取决于硬件对 depth-wise 和 1x1 卷积的优化程度、内存访问、批大小、张量布局和框架实现。

### 误解 6：1x1 卷积没有空间邻域，所以没有用

不对。1x1 卷积虽然不观察相邻位置，但可以在每个像素位置高效地混合通道、改变通道数，并承担深度可分离卷积中的通道融合职责。在 EMCAD 的 MSCB 中，它还是扩张和投影的关键部件。

## 9. 最后用一句话记忆

~~~text
多尺度深度卷积：多个大小不同的“空间观察窗口”，每个窗口内部按通道独立卷积。

深度可分离卷积：先按通道独立做空间卷积，再用1x1卷积进行通道混合。
~~~

再压缩成两个关键词：

~~~text
多尺度 = 看多大
可分离 = 怎么拆
~~~

在 EMCAD 中：

~~~text
MSDC 解决“多个尺度的空间信息提取”；
MSCB 负责扩张、分支融合、点卷积投影和残差；
EUCB 体现“depth-wise 空间细化 + point-wise 通道投影”的深度可分离设计。
~~~
