# EMCAD 中的 Token：位置、作用与完整数据流详解

本文基于当前项目源码静态核对，以 **Synapse、输入 224×224、PVTv2-B2 编码器**为例。B 表示批量大小。本文只新增解释文档，不修改模型、训练或测试代码；下列数值演示不是实际训练权重或预测结果。

## 1. 先给结论：EMCAD 哪里涉及 token？

在当前完整分割网络 `EMCADNet` 中，显式的 token 序列计算主要位于 **PVTv2 编码器**，具体包括：

1. 四个阶段的 OverlapPatchEmbed：把图像或特征图变成 token 序列。
2. Patch Embedding 内的 LayerNorm：逐个 token 归一化通道特征。
3. 每个 Transformer Block 的两次 LayerNorm：分别为注意力和 MLP 整理 token 数值。
4. Attention 中的 Q/K/V 投影、多头拆分、空间降采样和加权聚合：让不同位置的信息发生交互。
5. MLP 中的两个 Linear：逐 token 扩展和压缩通道。
6. MLP 内的 DWConv：token 临时恢复为二维网格，进行局部卷积，再变回 token。
7. Block 的残差连接和 DropPath：在 token 布局上融合分支结果，并在训练时施加随机深度。
8. 每个阶段末尾的 LayerNorm 和 reshape：把处理后的 token 还原成二维特征图。

**EMCAD 解码器收到的是四张二维特征图，而不是直接收到 `[B,N,C]` 的 token 列表。** CAB、SAB、MSDC、MSCB、EUCB、LGAG 在当前实现中均不执行 PVTv2 那种 Q/K/V token 自注意力。

这里说的是当前选择 PVTv2-B2 的路径。如果改用项目支持的 ResNet 编码器，就不会经过本文这套 PVTv2 token 序列处理。

## 2. token 到底是什么？

### 2.1 在这里，它是一处空间位置的特征向量

假设第一阶段生成一张 `[B,64,56,56]` 的特征图。对某一个样本而言：

- 有 56×56=3136 个空间位置。
- 每个位置有 64 个通道值。
- 把同一位置的这 64 个值放在一起，就是该位置的一个 token。

所以，一个 token 是一个包含 64 个数的向量，而不是单个数。把全部位置排列起来，就是 `[B,3136,64]`。

| 符号 | 含义 | 第一阶段示例 |
|---|---|---|
| B | 本批次图像数量 | 例如 1 或 12 |
| N | 每张图的 token 数，也就是该层空间位置数 | 3136 |
| C | 每个 token 的特征维度，也就是通道数 | 64 |
| H、W | token 对应的二维网格尺寸 | 56、56 |

可以把它想成一张器官调查表：3136 行对应 3136 个位置，64 列对应每个位置学习到的 64 项特征。这里的“特征”通常没有预先指定的人类名称，不能直接断言某列就是胃、肝脏或边缘。

### 2.2 token、像素、patch、通道不是同一个概念

| 概念 | 在本模型中的含义 |
|---|---|
| 原始像素 | 输入切片某位置的灰度数值 |
| patch | 用于局部特征提取的一片邻域；本项目通过重叠卷积隐式处理 |
| token | 对一个特征网格位置的向量表示 |
| 通道 | 这个向量的一个维度，或特征图的一张通道平面 |
| 类别 | 分割标签，例如背景与 8 个器官；不等同于编码器通道 |

第一阶段 token 在刚经过投影卷积时来自一个 7×7 邻域。经过注意力后，它还能结合其他区域的信息。因此不能始终把它当成一块固定原图区域的纯局部描述。

### 2.3 它与大语言模型的 token 有什么关系？

共同点是：都把处理单元表示成向量，供 Transformer 运算。

区别是：这里没有文字分词、词表或单词编号。视觉 token 是卷积从连续图像数值中计算出来的特征向量。它也不是 API 计费里统计的文本 token。

## 3. 从完整模型找到 token 所在位置

当前调用链为：

```text
输入切片 [B,1,224,224]
  ↓ 输入适配器：1×1 Conv + BN + ReLU
三通道表示 [B,3,224,224]
  ↓ self.backbone(x)：PVTv2-B2
  ├─ Stage 1：PatchEmbed → token → 3 个 Block → Norm → x1
  ├─ Stage 2：PatchEmbed → token → 4 个 Block → Norm → x2
  ├─ Stage 3：PatchEmbed → token → 6 个 Block → Norm → x3
  └─ Stage 4：PatchEmbed → token → 3 个 Block → Norm → x4
  ↓ 返回四张特征图
EMCAD 解码器：以 x4 为起点，融合 x3、x2、x1
  ↓
四个分割头 → [p4,p3,p2,p1] → 测试选择 p1
```

四个阶段是串行的：Stage 2 接收 x1，Stage 3 接收 x2，Stage 4 接收 x3。上面的分支列举仅表示编码器的组成，不表示四个阶段并行处理原图。

源码证据：

- [`lib/networks.py:101`](../lib/networks.py#L101)：`self.backbone = pvt_v2_b2()`。
- [`lib/networks.py:227`](../lib/networks.py#L227)：输入适配器、编码器、解码器的前向调用。
- [`lib/pvtv2.py:858`](../lib/pvtv2.py#L858)：四阶段实际执行顺序。
- [`lib/pvtv2.py:1092`](../lib/pvtv2.py#L1092)：B2 的通道、头数、深度等配置。

## 4. 四个阶段分别有多少 token？

| 阶段 | PatchEmbed 输入 | 投影后空间尺寸 | token 序列 | Block 数 | 阶段输出 |
|---|---|---|---|---:|---|
| 1 | `[B,3,224,224]` | 56×56 | `[B,3136,64]` | 3 | `[B,64,56,56]` |
| 2 | `[B,64,56,56]` | 28×28 | `[B,784,128]` | 4 | `[B,128,28,28]` |
| 3 | `[B,128,28,28]` | 14×14 | `[B,196,320]` | 6 | `[B,320,14,14]` |
| 4 | `[B,320,14,14]` | 7×7 | `[B,49,512]` | 3 | `[B,512,7,7]` |

越往后，位置数量变少，每个位置的特征维度变多。这样构建出不同空间分辨率、不同语义层次的特征，供分割解码器融合。

**一个阶段里反复执行 Block，不会反复减少 token 数。**例如第一阶段三个 Block 的输入输出都是 `[B,3136,64]`，发生变化的是里面的数值。

四阶段的 N 相加为 4165，但这不是网络一次性接收的 token 序列长度，也不是显存用量的直接公式。实际内存还涉及每个 Block 的 Q/K/V、注意力矩阵、MLP 隐藏特征及反向传播保存的中间结果。

## 5. 第一个涉及 token 的地方：OverlapPatchEmbed

### 5.1 先卷积，再排成 token

源码：[`lib/pvtv2.py:514`](../lib/pvtv2.py#L514)。

```python
def forward(self, x):
    x = self.proj(x)
    _, _, H, W = x.shape
    x = x.flatten(2).transpose(1, 2)
    x = self.norm(x)
    return x, H, W
```

第一阶段的 `self.proj` 是 7×7 卷积、stride=4、padding=3，将 3 通道投影为 64 通道：

```text
[B,3,224,224]
  → 7×7 卷积
[B,64,56,56]
  → flatten(2)：把高和宽合并
[B,64,3136]
  → transpose(1,2)：交换通道维和位置维
[B,3136,64]
```

空间尺寸按卷积公式计算：`floor((224+2×3−7)/4)+1=56`。

这里不是把原图切成互不重叠的 4×4 小块。4 是采样步长，实际核大小是 7，相邻投影窗口相互重叠。后面三个阶段使用 3×3 卷积、stride=2、padding=1，作用于上一阶段特征图。

### 5.2 一个最小数值例子：展平到底改了什么？

假设有一张 2 通道、2×2 的特征图，忽略 B：

```text
通道 1：        通道 2：
1  2           10  20
3  4           30  40
```

转为 token 后是：

| token 索引 | 原来的空间位置 | 特征向量 |
|---:|---|---|
| 0 | 左上 | `[1,10]` |
| 1 | 右上 | `[2,20]` |
| 2 | 左下 | `[3,30]` |
| 3 | 右下 | `[4,40]` |

从 `[2,2,2]` 变成 `[4,2]`，仍是原来的 8 个数。**仅展平和转置不提取特征、不压缩信息，也没有可训练权重。**前面的卷积才做了可学习的局部变换与降采样；后面的 LayerNorm 会改变数值。

通常位置映射是 `token_index = row × W + column`。因此恢复时需要保留 H、W。仅知道 N 无法唯一确定原网格，例如 N=12 可能是 3×4，也可能是 2×6。

## 6. 第二类位置：对 token 进行 LayerNorm

LayerNorm 出现在：

- 每阶段 PatchEmbed 的末尾。
- 每个 Block 的注意力之前、MLP 之前。
- 前三个阶段的 Attention 内，K/V 来源经过空间降采样之后。
- 每阶段全部 Block 执行结束之后。

对 `[B,N,C]` 而言，它通常在最后的 C 维计算均值和方差，再进行可学习的缩放和平移：

`y_c = gamma_c × (x_c − mean(x)) / sqrt(var(x)+epsilon) + beta_c`。

它不把不同样本或不同位置混为同一组统计。例如第一阶段，一个位置的 64 个特征值共同参与该 token 的归一化。

简化为 4 维 token `[1,2,3,4]`，在 gamma=1、beta=0 且忽略 epsilon 时，结果约为 `[-1.342,-0.447,0.447,1.342]`。

用途是稳定特征数值，方便后续投影和训练。token 数 N 和维度 C 都保持不变。它也不会让不同 token 变得相同。

## 7. 第三类位置：Attention 让 token 交换信息

源码：[`lib/pvtv2.py:263`](../lib/pvtv2.py#L263)。

### 7.1 Q、K、V 分别做什么？

对已有特征做可学习的线性投影，得到：

- Q（Query）：当前位置用来查询其他区域的表示。
- K（Key）：其他区域用于和查询匹配的表示。
- V（Value）：匹配后实际汇总的内容表示。

这些不是三种额外输入图片，也不是人工给器官写的标签。它们来自当前特征，随着训练学习。

核心公式是 `Attention(Q,K,V)=softmax(QKᵀ/√d)V`，其中 d 是每个头的特征维度。

### 7.2 本项目只对 K/V 来源降低空间分辨率

以第一阶段为例：

```text
输入 token：[B,3136,64]
  ├─ Q 路径：Linear → 保留 3136 个查询
  └─ K/V 路径：恢复 [B,64,56,56]
               → 8×8、stride=8 的卷积
               → [B,64,7,7]
               → [B,49,64]
               → LayerNorm → Linear → K、V
```

空间降采样卷积是普通卷积，默认 groups=1，不是 MLP 里的逐通道 DWConv，也不是简单“挑出 49 个原 token”。它学习如何把区域特征聚合成较少的表示。

第一阶段只有一个注意力头：

| 张量 | 形状 | 含义 |
|---|---|---|
| Q | `[B,1,3136,64]` | 每个原位置都有查询 |
| K | `[B,1,49,64]` | 49 个区域的匹配表示 |
| V | `[B,1,49,64]` | 49 个区域的内容表示 |
| QKᵀ | `[B,1,3136,49]` | 每个查询与每个区域的匹配分数 |
| softmax 后 | `[B,1,3136,49]` | 每个查询的 49 个权重之和为 1 |
| 聚合 V 后 | `[B,1,3136,64]` | 每个原位置得到更新信息 |
| 合并头并投影后 | `[B,3136,64]` | 返回 Block 要求的布局 |

这里的 softmax 表示“参考各区域的比例”，不是“像素属于各器官的概率”。后者是在最终分割 logits 上计算的另一种 softmax。

### 7.3 一个加权汇总例子

假设为了说明，只保留三个参考区域，其 V 向量为：

```text
区域 A：[2,0]
区域 B：[0,4]
区域 C：[1,1]
```

某个查询位置经过匹配与 softmax，得到权重 `[0.6,0.3,0.1]`，则它汇总得到：

`0.6×[2,0]+0.3×[0,4]+0.1×[1,1]=[1.3,1.3]`。

实际模型有更多区域和特征维度，之后还有输出投影与残差连接，但加权汇总的原理一样。

在医学分割中，这提供了一种利用更大范围结构信息的能力。例如局部灰度相似的区域，可以结合其他位置的特征辅助判断。不能保证每个注意力头都形成了人类可解释的器官关系，也不能把高注意力权重直接当成可靠的病灶解释。

### 7.4 四阶段的注意力形状

| 阶段 | 查询 N | 通道 C | 头数 h | 每头维度 d | sr_ratio | K/V 数 N′ | 注意力矩阵形状 |
|---|---:|---:|---:|---:|---:|---:|---|
| 1 | 3136 | 64 | 1 | 64 | 8 | 49 | `[B,1,3136,49]` |
| 2 | 784 | 128 | 2 | 64 | 4 | 49 | `[B,2,784,49]` |
| 3 | 196 | 320 | 5 | 64 | 2 | 49 | `[B,5,196,49]` |
| 4 | 49 | 512 | 8 | 64 | 1 | 49 | `[B,8,49,49]` |

第四阶段不再执行 K/V 空间降采样，直接从原 token 投影 K、V。

多头是把通道维拆分为多个子空间。例如 Stage 3 的 320 维拆成 5 个头，每头 64 维。它没有把 196 个位置增加成 980 个空间位置，也不表示 5 个器官。

### 7.5 为什么压缩 K/V？

第一阶段如果做完整两两注意力，每个样本每个头需要 `3136×3136=9,834,496` 个匹配分数。现在是 `3136×49=153,664`，匹配分数数量减少为 1/64。

这是注意力矩阵的元素数比较，不等于整个模型显存和耗时都减少 64 倍。投影、降采样卷积、MLP 等仍有计算成本。

主序列仍然保留 3136 个位置，因为 Q 没有降采样。压缩的代价是 K/V 对空间细节的表达更粗，后续还需要局部运算和多尺度特征来补充。

## 8. 第四类位置：MLP 加工 token，DWConv 连接邻居

源码：[`lib/pvtv2.py:141`](../lib/pvtv2.py#L141)、[`lib/pvtv2.py:985`](../lib/pvtv2.py#L985)。

```python
x = self.fc1(x)
x = self.dwconv(x, H, W)
x = self.act(x)
x = self.drop(x)
x = self.fc2(x)
x = self.drop(x)
```

### 8.1 Linear 处理每个 token 的通道，不混合不同位置

第一阶段的 MLP 将 64 维扩大到 512 维，再压回 64 维：

`[B,3136,64] → [B,3136,512] → … → [B,3136,64]`。

每个位置都应用同一组 Linear 参数，位置数量不变。扩大维度提供更多中间特征组合空间，GELU 提供非线性。这里的 512 个隐藏通道不是 512 个器官。

| 阶段 | MLP 通道变化 | token 数 |
|---|---|---:|
| 1 | 64 → 512 → 64 | 3136 |
| 2 | 128 → 1024 → 128 | 784 |
| 3 | 320 → 1280 → 320 | 196 |
| 4 | 512 → 2048 → 512 | 49 |

### 8.2 DWConv 暂时把 token 放回二维网格

```python
B, N, C = x.shape
x = x.transpose(1, 2).view(B, C, H, W)
x = self.dwconv(x)
x = x.flatten(2).transpose(1, 2)
```

第一阶段 MLP 内部的具体路径：

`[B,3136,512] → [B,512,56,56] → 3×3 DWConv → [B,512,56,56] → [B,3136,512]`。

卷积使用 `groups=512`，各通道独立结合其空间 3×3 邻域。空间大小不变，通道数也不变，但每个位置的数值会吸收邻居信息。

这一设计让模型既能通过注意力参考跨区域信息，也能通过卷积明确利用二维局部邻接关系。它不是沿展平后的一维序列随意取相邻元素，因此不会把一行末尾和下一行开头误当成普通水平邻居。

这也说明“用了 token 就没有卷积”是误解：本项目在 token 处理过程中多次恢复二维布局执行卷积。

## 9. 第五类位置：残差与 DropPath 也作用于 token 张量

[`lib/pvtv2.py:415`](../lib/pvtv2.py#L415) 的 Block 前向：

```python
x = x + self.drop_path(self.attn(self.norm1(x), H, W))
x = x + self.drop_path(self.mlp(self.norm2(x), H, W))
return x
```

两次残差加法都要求两侧 `[B,N,C]` 形状相同。它们将注意力和 MLP 的结果加到主特征上，提供直接的信息与梯度通路。

简化例子：原 token 为 `[0.2,0.5,-0.1]`，修正为 `[0.1,-0.2,0.4]`，相加得到 `[0.3,0.3,0.3]`。这里没有丢掉这个空间位置，也没有改变 token 数量。

当前 B2 的普通 Dropout 概率为 0，因此虽然 MLP 和 Attention 中有相关层，它们不随机丢弃数值。DropPath 最大概率为 0.1，按 16 个 Block 的全局深度从 0 线性增加；正常评估模式下不丢弃。

标准 DropPath 在训练时按样本屏蔽整条残差分支的贡献，保留时相应缩放。它不是删除某个 token，也不是 token pruning，更不保证跳过分支内部的实际计算。两条残差分支都调用 DropPath。

## 10. 第六类位置：阶段结束，把 token 恢复为特征图

第一阶段处理完三个 Block 后：

```python
x = self.norm1(x)
x = x.reshape(B, H, W, -1).permute(0, 3, 1, 2).contiguous()
outs.append(x)
```

路径为 `[B,3136,64] → [B,56,56,64] → [B,64,56,56]`。

恢复布局没有把 64 维向量变回原始灰度，而是把已经更新的特征重新排成二维网格。这张图一方面进入下一编码阶段，另一方面保留在 `outs` 中，最终交给解码器。

四阶段完成后，返回 `[x1,x2,x3,x4]`。不是将它们拼成一条长 token 序列，也不是求平均得到一个全图向量。

这对分割很重要：分割需要保留位置对应关系，而不仅是输出整张图的一个类别。

## 11. 解码器为什么也有 attention，却不按 token 序列写？

“注意力”是更广泛的概念，并不都需要 Q/K/V。

| 模块 | 当前主要数据布局 | 用途 | 是否是 PVTv2 式 token 自注意力 |
|---|---|---|---|
| PVTv2 Attention | `[B,N,C]`，内部拆为多头 | 位置间匹配与加权汇总 | 是，且 K/V 可降采样 |
| CAB | `[B,C,H,W]` | 生成通道权重，选择有用通道 | 否 |
| SAB | `[B,C,H,W]` | 生成空间权重，突出有用位置 | 否 |
| LGAG | 两路二维特征图 | 用解码特征引导筛选 skip 特征 | 否 |
| MSDC/MSCB | `[B,C,H,W]` | 多尺度局部卷积与特征融合 | 否 |
| EUCB | `[B,C,H,W]` | 上采样并调整通道 | 否 |
| 分割头 | `[B,C,H,W]` → `[B,9,H,W]` | 将特征转为各类别 logits | 否 |

解码器里的一个空间位置依然可以抽象地看成一个特征向量，但源码没有因此执行显式的 token 序列 Transformer 运算。

此外，channel shuffle 也会使用 view、transpose 等操作，其目的是重排通道分组，不是把空间位置变成 Transformer token。看到 reshape 不能直接断言那里存在 token 注意力。

## 12. 有没有 CLS token、位置编码、器官 token？

### 12.1 当前有效路径没有 CLS token

有些分类 Transformer 会额外加入一个 CLS token，代表整张图。但当前 PVTv2 分割编码器没有在有效前向中添加它，因此第一阶段是 3136 个 token，不是 3137 个。

源码 `no_weight_decay()` 返回的字符串集合含有 `cls_token` 和 `pos_embed1` 等名字，但这只是兼容接口中的名称，不能证明参数已创建或参与了前向。应以真实初始化与前向计算为准。

### 12.2 当前没有显式添加可学习的位置嵌入表

有效路径没有执行 `x = x + pos_embed`。这不等于网络完全没有空间结构信息：重叠卷积、二维 DWConv、padding，以及 H/W 对应的网格组织都提供了空间结构约束。

但不要进一步说模型因此就拥有精确的绝对坐标编码；这里表达的是局部空间关系和卷积结构带来的位置信息来源。

### 12.3 没有 8 个器官专属 token

3136、784、196、49 都是空间位置数量。64、128、320、512 都是特征通道数。它们与 Synapse 的 8 个器官没有一一对应关系。

器官类别在最终输出头的 9 个 logits 通道中得到明确表示：背景加 8 个器官。

### 12.4 没有跨切片 token 交互

当前这里处理的是单张二维切片的 H×W 位置。把不同切片放进同一个 batch，注意力仍分别在每个样本内部进行，不会自动让第 1 张切片的 Q 去参考第 2 张切片的 K/V。

因此，连续取 7 张或 9 张作为独立 batch 样本，不会仅凭 token 机制变成 2.5D 上下文建模。要跨切片交流，需要额外的输入融合、跨切片注意力或其他明确设计。BN 的批次统计共享也不等同于学习有顺序的切片上下文。

## 13. token 对你的分割 Dice 有什么实际意义？

### 13.1 全局判断与边界细节需要配合

注意力让一个位置可以参考更大范围的信息，可能帮助区分局部外观相似的器官区域。高分辨率特征、局部卷积和解码器则有助于定位边界。

但是，采用 token 或 Transformer 并不自动保证更高 Dice。数据划分、标注、输入尺寸、预训练、优化过程以及解码能力都会影响结果。不能仅凭 83.63 的 Dice 判断 token 数不足或某个模块学习不充分。

### 13.2 输入尺寸会改变 token 数和计算量

| 输入尺寸 | Stage 1 | Stage 2 | Stage 3 | Stage 4 |
|---|---:|---:|---:|---:|
| 224×224 | 3136 | 784 | 196 | 49 |
| 352×352 | 7744 | 1936 | 484 | 121 |

352 输入的各阶段 K/V 数为 121，不再是 49。因此第一阶段的每头注意力矩阵从 `3136×49=153,664` 个元素增加到 `7744×121=937,024`，约为原来的 6.10 倍。

这仍只是矩阵元素数，不是整网资源精确预测。提高输入分辨率可能减少缩小图像造成的细节损失，但不会凭空提高原始扫描分辨率，也不保证 Dice 必然增加；还可能迫使你减小 batch。

### 13.3 哪些因素改变 token 数，哪些不会？

| 操作或配置 | 会不会改变主序列 token 数 N？ |
|---|---|
| 增大输入空间尺寸 | 会 |
| 阶段间有 stride 的 PatchEmbed | 会 |
| 第一阶段适配器 1→3 通道 | 不会，它尚未生成 token |
| LayerNorm | 不会 |
| Q/K/V 的 Linear | Linear 本身不会 |
| Attention 中 sr 卷积 | 改变 K/V 来源的 N′，不改变主输出 N |
| 增加注意力头数 | 不会；会改变通道分头方式 |
| MLP 扩展通道 | 不会；改变 C_hidden |
| MLP 的 3×3 DWConv | 当前 stride=1，因此不会 |
| 增加 Block 数 | 不会；增加特征变换深度 |
| DropPath | 不会 |
| 调整 batch size | 改变 B，不改变单张图 N |

## 14. 一个完整的人类事例

把一张腹部 CT 想成一张需要逐区域辨认器官的地图：

1. **输入适配器**把同一份灰度资料转换为编码器能接收的三通道表示，没有增加新切片。
2. **PatchEmbed**在地图上按重叠邻域提取资料，形成 3136 张位置卡片，每张记录 64 个特征值；每张卡片就是一个 token。
3. **LayerNorm**整理每张卡片的数值尺度，方便后续计算。
4. **Q/K/V 注意力**让每张位置卡片查询 49 份区域摘要，并按匹配程度取回信息。
5. **第一次残差连接**把取回的修正加入原卡片。
6. **MLP**扩充和重组每张卡片的特征；其中 DWConv 先把卡片放回地图，再参考邻近位置。
7. **第二次残差连接**加入这轮局部与通道加工结果。
8. **重复 Block**多次更新同一批卡片，卡片数量不变。
9. **阶段结束恢复特征图**，再由下一阶段重新提取更少、维度更高的卡片。
10. **解码器**拿到四种尺度的地图特征，逐步融合与恢复空间细节。
11. **分割头**给每个输出位置计算背景与 8 个器官的分数，最终形成器官标签图。

这个比喻中的“卡片”和“摘要”都是数值向量，不是模型生成的中文报告；它们也没有预先写好的器官名称。

## 16. 自查问题

- `[B,3136,64]` 中哪个数字是 token 数？3136；64 是每个 token 的特征维度。
- token 化会不会自动丢信息？单纯 flatten/transpose 不会；前面的降采样卷积可能压缩空间信息。
- 49 个 K/V 是否意味着输出只剩 49 个位置？第一阶段不是，Q 保留 3136 个位置，输出仍有 3136 个。
- 多头是不是多个器官？不是，它是特征子空间的拆分。
- MLP 只处理当前位置吗？其中 Linear 按位置独立处理，DWConv 会结合二维邻居。
- 解码器的 SAB 是 Q/K/V 注意力吗？当前实现不是，它生成空间门控权重。
- 最终 `P[-1]` 是最后一个 token 吗？不是，它是四个完整分割输出中的最后一个，形状为 `[B,9,224,224]`。
- 一个 token 是否一直只代表固定原图小块？有固定网格位置，但内容会经卷积和注意力吸收更广范围信息。
- 训练时把相邻切片放在一起，会自动形成跨切片 token 注意力吗？不会，当前 B 维的样本各自进行注意力计算。
