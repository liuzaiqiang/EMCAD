# 深度学习医学图像分割科研避坑 200 条（2026 版）

适用对象：医学图像分割方向的硕士研究生。本文不是“模型清单”，而是一份从问题定义到论文发表的风险清单。每条都按“坑点—为什么—怎么做”组织；遇到难点时，先看解释，再把最后的动作写进自己的实验记录。

## 一、先把研究问题说清楚（1—10）

1. **把“医学图像分割”当成单一任务**：CT、MRI、超声、内镜、皮肤镜和显微图像的噪声、空间尺度、标注方式完全不同；先写清模态、器官/病灶、2D/3D、语义/实例分割。
2. **只说“提升 Dice”而不说临床对象**：Dice 高不等于边界、体积或小病灶可靠；在开题时同时定义目标区域、允许的误差和潜在使用场景。
3. **把分类标签当成分割标签**：BUSI 的 benign/malignant 是图像级类别，不能直接当像素类别；先核对 mask 的语义、类别编码和空 mask 含义。
4. **把二分类前景/背景误认为必须输出两通道**：单通道 sigmoid 输出前景概率，背景是其补集；只有互斥多类任务通常才用含背景的多通道 softmax。
5. **忽略实例分割与语义分割差异**：DSB18 等细胞任务可能要求区分相邻实例；只用语义 Dice 会把粘连细胞误判为成功。
6. **把“改网络”当成研究问题**：没有明确失败模式时堆模块只是工程改造；先用可检验假设描述“哪类边界/尺度/域偏移会改善”。
7. **研究范围无限扩张**：同时换数据、骨干、损失、增强和后处理，最后无法归因；硕士课题优先固定一个主问题和一条验证链。
8. **把数据集名称当作任务定义**：同名数据集可能有不同版本和标注协议；记录下载来源、版本、许可、病例数、切片数和标签表。
9. **忽略标注者和标注协议**：专家、初级医生、共识标签的噪声结构不同；论文中说明标注来源，必要时做 inter-rater 或软标签分析。
10. **没有预先写成功标准**：看到结果后才决定“提升算成功”会造成选择性报告；训练前写主指标、最小临床相关差异、统计方法和停止规则。

## 二、数据来源、许可与隐私（11—20）

11. **从不明网盘拿数据直接发表**：来源、版本和许可无法追溯；保留官方页面、下载日期、哈希值和许可文本。
12. **把研究许可当成可商业发布许可**：数据能用于论文不代表能打包进产品或公开镜像；把用途限制写进项目 README。
13. **把病人隐私当成“已匿名”**：DICOM 头、文件名、烧录信息和面部区域都可能泄露；公开前做字段清理、面部去识别和人工抽查。
14. **把外部数据复制进 Git 仓库**：大型医学数据通常不应入库，也可能违反协议；只提交下载脚本、版本和校验信息。
15. **不记录下载版本**：数据集更新后同名文件可能变化；保存压缩包 SHA-256、目录清单和样本计数。
16. **忽略数据使用审批**：临床数据需要伦理、数据使用协议或机构授权；没有审批就不要把“可获得”写成“可公开”。
17. **将患者姓名、住院号留在日志或截图**：训练日志和可视化同样可能构成泄露；脱敏后再分享，并检查 TensorBoard、异常堆栈和文件路径。
18. **把网络下载的预训练权重当作无条件可用**：权重可能有许可证、训练数据限制和安全风险；记录来源、许可证、校验值及是否允许再分发。
19. **盲目合并不同数据集**：像素间距、设备、协议和标签定义不同，合并会制造伪提升；先做域统计和标签映射，再决定是否联合训练。
20. **不保留原始只读副本**：预处理覆盖原文件后无法定位错误；采用 raw/interim/processed 分层，原始目录只读并有清单。

## 三、划分与泄漏（21—30）

21. **按切片随机划分 3D 病例**：同一患者的相邻切片会同时进入训练和测试，结果虚高；按患者或检查编号划分。
22. **把同一视频的内镜帧分到不同集合**：相邻帧几乎重复；按视频、序列或病变事件分组。
23. **预处理后才划分**：用全体数据估计归一化统计量、裁剪框或形态模板会泄漏测试信息；先划分，再只用训练集拟合参数。
24. **用测试集挑 checkpoint**：测试集变成隐形验证集；只用训练/验证选择模型，测试集只在最终锁定后运行一次或极少次数。
25. **反复查看测试结果并调参**：即使没有梯度，人工决策也会过拟合测试集；建立独立外部测试或时间锁定集。
26. **随机种子只写在口头**：同一代码可能因数据顺序、CUDA 算法和多进程产生差异；记录所有 seed、版本、确定性开关和硬件。
27. **验证集太小却过度解读**：几个病例的均值可能被单个异常病例主导；报告病例数、置信区间和逐病例结果。
28. **训练/验证分布完全不匹配**：验证集若只含容易病例，早停会选择错误模型；按病例难度、设备和类别分层划分。
29. **把外部测试集当作训练调参集**：外部集一旦被看过就不再是独立证据；调参只在内部验证，外部结果最后一次报告。
30. **不保存 split manifest**：同一个“80/10/10”每次样本不同，实验不可比；保存患者 ID、文件相对路径、版本和生成脚本。

## 四、标注与预处理（31—40）

31. **不核对图像与 mask 是否配对**：按排序硬配会把标签错位；用唯一 ID 配对，并检查尺寸、方向、数量和随机叠加可视化。
32. **把 mask 用双线性插值缩放**：会产生 0.3、0.7 等伪标签；标签使用 nearest，图像才用线性/三次插值。
33. **把 mask 当普通图像归一化**：归一化会改变类别编码；mask 只做类型转换和合法值检查。
34. **忘记 CT 的窗宽窗位**：直接把 HU 截断或归一化可能丢失病灶对比；记录窗口、截断范围和是否按病例归一化。
35. **MRI 不处理强度非一致性**：不同设备和序列强度不可直接比较；说明 N4、z-score 或 Nyul 等处理是否使用，且只用训练集拟合统计量。
36. **超声增强过强**：过度 speckle、旋转或弹性变换可能生成不存在的病理形态；限制幅度并人工查看增强样本。
37. **裁剪把目标裁掉**：随机 crop 若大部分为空会让模型学背景；设置前景采样比例并统计目标保留率。
38. **只保存最终 PNG 不保留坐标元数据**：医学空间中的 spacing、origin、direction 丢失后 HD95/体积没有意义；3D 数据保留 NIfTI/DICOM 空间信息。
39. **改变方向却不更新 affine**：视觉方向和物理坐标不一致；重采样后同步更新 affine，并用已知标记点验证。
40. **忽略空 mask 样本**：空标签在 Dice、召回率和损失中有特殊处理；预先定义空-空、空-非空的评分规则。

## 五、标注噪声与数据质量（41—50）

41. **默认标注是真值**：医学标注有边界模糊、漏标和观察者差异；抽样复核并记录疑难病例。
42. **用小目标的 Dice 直接比较难度**：一个像素偏移会让小目标 Dice 大幅下降；同时报告 HD95、召回率和目标尺寸分层结果。
43. **不检查连通域和孔洞**：标签中意外的小碎片会误导模型；统计连通域、面积、孔洞和异常长宽比。
44. **把插值产生的标签当新标注**：重采样不是增加真实信息；标记“原生/重采样”来源，避免重复计数。
45. **标签类别编号前后不一致**：0/1 与 0/255 混用会导致损失或评估全错；在加载器入口统一映射并断言合法值集合。
46. **用肉眼只看几张图**：抽样偏差会漏掉系统性错配；按设备、患者、尺寸和阳性率分层抽查。
47. **忽略极端病例**：异常大/小、术后、金属伪影病例决定泛化边界；建立难例清单并单独报告。
48. **删除难例以“清理数据”**：删掉失败样本会美化结果；只能基于预先定义的质量标准剔除，并报告数量和原因。
49. **把重复图像当独立样本**：镜像、压缩副本或同一病例导出多次会放大权重；用感知哈希和病例 ID 去重。
50. **不做数据审计表**：没有审计就无法解释结果；至少记录样本数、阳性率、尺寸、spacing、缺失值和异常项。

## 六、模型设计与公平基线（51—60）

51. **先堆 Transformer 再找问题**：复杂模型增加算力和调参空间，不自动带来科学贡献；先建立简单 U-Net/nnU-Net 风格基线。
52. **只与过时或弱基线比较**：故意选择弱对手属于不公平；选择与任务、年份、资源约束匹配且可复现的强基线。
53. **骨干网络和预训练权重混为一谈**：换 encoder 与是否加载权重是两个变量；实验表分开列出架构、初始化和冻结策略。
54. **参数量增加却声称“更高效”**：精度提升可能来自容量增加；同时报告参数量、FLOPs、峰值显存、吞吐和延迟。
55. **只改一个模块却重写训练流程**：收益无法归因；基线和方法保持数据、损失、epoch、调度器完全一致。
56. **注意力模块位置随意**：不同分辨率和通道数下作用不同；说明放置层级、输入输出形状和动机。
57. **多尺度特征直接拼接导致显存爆炸**：空间尺寸或通道不匹配会隐式插值、报错或大量占用；画出每层张量形状并做显存测试。
58. **深监督权重没有说明**：辅助头会改变优化目标；记录每个尺度的 loss 权重、训练时是否启用以及推理时是否移除。
59. **模块命名替代机制解释**：新名字不等于新方法；用公式、伪代码和消融说明输入、变换、融合和残差路径。
60. **忽略部署约束**：医学场景可能需要 CPU、低延迟或可解释输出；从课题开始记录推理时间、内存和失败模式。

## 七、损失函数与优化（61—70）

61. **只用 Dice 处理极度不平衡**：Dice 对空集和小目标敏感，可能忽略概率校准；按任务组合 BCE/CE、Dice、Tversky 或边界损失，并说明目的。
62. **把 logits 先 sigmoid 再喂 BCEWithLogitsLoss**：会重复激活，导致梯度和数值不稳定；BCEWithLogitsLoss 接收原始 logits。
63. **多类任务用独立 sigmoid 却声称互斥**：各类概率可同时为 1；互斥类别通常用 softmax + CE，独立属性才用 sigmoid。
64. **Dice 平滑项随意设置**：epsilon 太大可能改变小目标排序；记录公式、smooth 值和空集处理。
65. **训练损失下降就宣布成功**：优化目标与临床指标不完全相同；以验证集指标和逐病例可视化决定。
66. **学习率照搬别人**：batch、分辨率、优化器和预训练状态不同，最佳学习率会变；至少做有依据的范围搜索。
67. **梯度累积忘记除以累积步数**：等效学习率被放大；明确 loss 缩放、optimizer.step 时机和有效 batch size。
68. **混合精度出现 NaN 却继续训练**：结果可能已损坏；监控 scaler、梯度范数、loss finite 状态并保存异常批次。
69. **梯度裁剪阈值不记录**：裁剪会改变优化轨迹；记录 norm 类型、阈值以及触发比例。
70. **不同实验使用不同 epoch 却直接比较**：训练预算不一致；固定 epoch/迭代数或报告完整学习曲线与最佳点规则。

## 八、训练、验证与 checkpoint（71—80）

71. **把最后一个 epoch 当最佳模型**：最后模型可能过拟合；根据验证集主指标保存 best，并保存 last 便于续训。
72. **验证时忘记 `eval()`**：BatchNorm 和 Dropout 状态错误；验证前 `model.eval()`，结束后恢复训练模式。
73. **验证阶段未使用 `no_grad()`**：浪费显存且可能保留计算图；使用推理上下文并确认没有梯度累积。
74. **只保存模型权重**：无法可靠续训；同时保存 optimizer、scheduler、scaler、epoch、best 指标、配置和随机状态。
75. **checkpoint 与配置不绑定**：同名 `best.pth` 可能来自不同类别数或输入尺寸；每次实验目录包含 config、命令、代码版本和数据 manifest。
76. **断点续训改变数据划分**：续训前后验证集变化会破坏最佳模型含义；锁定 manifest 和预处理版本。
77. **自动恢复加载错权重**：文件名相近会把别的任务权重载入；加载后断言键名、类别数、missing/unexpected keys。
78. **只看平均验证 Dice**：平均值掩盖某类或某病例崩溃；保存 per-class、per-case 和分位数。
79. **早停耐心值没有依据**：过小会错过学习率退火后的提升；结合曲线、验证噪声和计算预算预设规则。
80. **训练日志没有时间戳和环境信息**：无法区分代码改动和硬件波动；日志写入 git commit、Python/PyTorch/CUDA、GPU、主机和启动命令。

## 九、评价指标与统计（81—90）

81. **只报告 Dice**：Dice 对边界距离不敏感；至少结合 HD95/ASD、IoU、敏感度、特异度或体积误差。
82. **把 HD95 当最大 Hausdorff 距离**：HD95 是 95 分位距离，不能代表最坏点；论文中写清实现和单位。
83. **在 2D 切片上计算 3D 指标**：切片间距和重建方向被忽略；体数据指标在统一物理空间计算。
84. **不同实现的 Dice 定义混用**：macro、micro、foreground-only、含背景的平均结果不可直接比较；给出公式和代码版本。
85. **把 batch 平均当病例平均**：大病例或切片多的患者权重更大；医学报告通常先按病例聚合，再计算均值。
86. **阈值 0.5 固定却不说明**：阈值影响 Dice、召回和体积；在验证集确定阈值，测试时锁定并报告。
87. **后处理在测试集上调参**：连通域阈值、孔洞填充也会过拟合；所有后处理参数只用训练/验证确定。
88. **没有置信区间**：单一均值无法表达病例不确定性；用病例级 bootstrap 或预先定义的统计方法报告区间。
89. **多次实验只挑最高一次**：随机波动被误报成方法提升；报告多 seed 的均值、标准差和全部运行记录。
90. **统计检验单位错了**：把切片当独立样本会夸大样本量；以患者/检查为统计单位，必要时使用配对检验。

## 十、泛化、外部验证与临床相关性（91—100）

91. **内部测试高就声称临床可用**：同域数据不能证明跨医院泛化；至少加入时间、设备或机构外部验证。
92. **外部集标签协议不同却硬比较**：指标差异可能来自定义而非模型；先建立标签映射和协议对照表。
93. **忽略域偏移**：扫描仪、染色、操作者和压缩方式都会改变分布；报告域信息并做分层结果。
94. **只测平均性能不测亚组**：年龄、性别、设备、病变大小等亚组可能退化；在合法且有伦理依据时做预先定义的亚组分析。
95. **把数据增强当泛化证明**：增强只说明模拟变化下的鲁棒性；真实外部数据仍需独立验证。
96. **用合成数据替代真实测试**：生成数据可能过于容易；明确 synthetic 的用途，不能把它当临床证据。
97. **不报告失败病例**：只展示漂亮可视化会造成发表偏差；给出失败率、典型失败类别和修复是否可行。
98. **把校准问题当分割问题**：Dice 高但概率不可信会影响风险排序；评估置信度、可靠性图和不确定性。
99. **忽略人工工作流**：自动 mask 与医生编辑时间、漏诊风险并不等价；若声称辅助诊断，设计读者研究或编辑负担评估。
100. **把研究结果写成诊疗建议**：模型实验不能替代医生和临床验证；论文明确研究性结论边界与适用人群。

## 十一、可解释性与不确定性（101—110）

101. **把热力图当因果解释**：Grad-CAM 等只显示相关区域，不证明模型依据正确；结合遮挡、反事实和错误案例。
102. **只展示成功案例的注意力图**：解释方法也可能在失败时失效；同时展示成功和失败样本。
103. **把 softmax 最大值当可靠置信度**：神经网络可能过度自信；做温度缩放、校准误差或深度集成评估。
104. **忽略标注不确定性**：边界模糊处强行二值化会制造伪精确；可考虑软标签、多个标注者或边界容忍指标。
105. **不区分 epistemic 与 aleatoric 不确定性**：模型无知和数据本身模糊的处理不同；在方法和解释中分别说明。
106. **用单次 dropout 就宣称贝叶斯可信**：近似方法有假设和校准限制；说明采样次数、指标和验证方式。
107. **不测试分布外输入**：模型可能对新医院图像输出高置信错误；加入 OOD 检测或至少做异常输入压力测试。
108. **把不确定性图直接交给临床使用**：颜色图不是决策规则；定义阈值、升级人工复核条件和责任边界。
109. **解释图改变了原始结果**：可视化后处理可能让人误以为模型更准确；原始预测和展示版本分开保存。
110. **没有记录解释算法版本**：不同库的归一化和插值不同；固定实现、参数、随机种子和可视化脚本。

## 十二、实验设计与消融（111—120）

111. **一次改很多变量**：无法知道提升来自哪里；采用单变量或正交的消融矩阵。
112. **消融只删模块不做等参数对照**：删掉模块同时减少参数量，结论不公平；加入参数量或 FLOPs 匹配的替代模块。
113. **没有最小可运行基线**：新方法失败时不知道是代码还是假设；先跑通数据、损失、评估和 checkpoint 闭环。
114. **消融数据集随意更换**：不同数据集的难度改变结论；主实验固定数据和 split，跨数据集作为泛化验证。
115. **只做一次 seed**：单次提升可能是随机波动；关键配置至少多 seed，预算不足时诚实报告限制。
116. **不做学习曲线**：只比较最终数字看不出收敛和过拟合；保存 train/val 曲线并分析早期、稳定期、退化期。
117. **没有负结果记录**：删掉失败实验会造成研究者自由度偏差；记录失败原因、修复尝试和停止理由。
118. **把调参结果写成方法贡献**：调度器和阈值优化不是结构创新；把工程调优与科学贡献分开叙述。
119. **只比较最优点不比较计算代价**：临床或实验室可能更关心速度和稳定性；报告精度-成本前沿。
120. **消融表缺少配置细节**：读者无法复现“w/o A”；给每个变体列出模块、损失、参数量、输入尺寸和训练预算。

## 十三、代码质量、数据管线与复现（121—130）

121. **把 notebook 当唯一代码**：状态隐式、执行顺序不明；核心流程放入可命令行运行的脚本。
122. **路径写死在个人电脑**：换机器即失效；使用配置文件、相对路径和环境变量，并打印解析后的绝对路径。
123. **静默跳过坏样本**：数量变化却不报警；坏文件应记录清单，默认失败或显式统计。
124. **没有 shape/assert 检查**：通道错位可能悄悄训练；在数据、模型输出和指标入口加入形状、dtype、值域断言。
125. **随机增强未固定来源**：Python、NumPy、PyTorch、worker 各有随机状态；统一初始化并记录 worker 设置。
126. **多进程 DataLoader 导致不可复现**：worker 顺序、平台和缓存影响结果；先用 `num_workers=0` 验证，再逐步增加并记录。
127. **依赖只写“大版本”**：PyTorch、CUDA、MONAI、Albumentations 小版本都可能改变行为；锁定环境文件和安装渠道。
128. **升级环境后不做回归测试**：速度或数值变化可能被误当创新；用固定小样本做 forward、loss、指标和 checkpoint 回归。
129. **代码改动没有 commit**：无法把结果对应到实现；每次实验记录 git commit、未提交 diff 和分支名。
130. **删除中间结果节省空间**：中间 mask、日志和预测是排错证据；按保留策略归档压缩，不要直接覆盖。

## 十四、GPU、性能与工程安全（131—140）

131. **只看 GPU 利用率判断训练快慢**：CPU、磁盘、数据解码、验证和同步都可能是瓶颈；同时监控吞吐、等待时间、显存和 I/O。
132. **把显存大等同于速度快**：显存容量、计算吞吐和内存带宽是不同约束；比较时固定 batch、分辨率、精度和软件栈。
133. **忽略图像分辨率的平方/立方成本**：宽高各加倍，2D 像素约四倍，3D 体素约八倍；先做显存预算。
134. **混用不匹配的 CUDA、驱动和 PyTorch**：可能退回兼容路径或直接崩溃；记录 `torch.version.cuda`、驱动、GPU 架构和实际环境。
135. **为了速度盲目开启非确定算法**：速度提升可能换来结果波动；论文实验使用确定性设置或量化其影响。
136. **显存不足只减 batch**：可能改变优化统计和结果；同时考虑 patch、梯度累积、混合精度、checkpointing，并报告等效 batch。
137. **验证阶段占满时间却不计入成本**：只报训练 epoch 时间会误导；分开报告训练、验证、预处理和后处理时间。
138. **后台任务抢 GPU 却不记录**：温度、功耗、时钟和进程影响速度；实验前清理占用并保存硬件监控摘要。
139. **把下载脚本执行在受限网络中反复重试**：可能损坏缓存或触发限流；使用校验、断点续传和离线安装包。
140. **在日志中打印密钥和隐私路径**：调试输出会进入共享平台；使用脱敏变量名、相对路径和最小权限账号。

## 十五、论文写作与图表（141—150）

141. **先写夸张结论再找数字**：会诱导选择性报告；先锁定分析计划，再生成表格和结论。
142. **把“state of the art”写成无条件事实**：不同 split、预处理和版本不可直接比；使用“在本实验设置下”并给出可比条件。
143. **方法图与代码不一致**：图上有分支、代码里没有，审稿人很快发现；从实际张量流和 commit 生成图。
144. **公式缺少张量维度**：读者无法判断是否可实现；在关键公式旁写输入、输出形状和广播规则。
145. **表格只放均值不放波动**：看不出稳定性；报告标准差、置信区间或逐病例分布。
146. **只放最好可视化**：可视化是定性证据，不可替代统计；按预先规则选成功、一般、失败案例。
147. **图像过度裁剪或增强**：可能隐藏伪影和失败边界；保留原图、预测、真值、误差图和比例尺。
148. **单位和坐标轴不清**：HD95 的 mm 与像素不能混用；所有图表注明单位、方向和聚合方式。
149. **引用二手博客代替原论文**：机制和数据集描述容易失真；关键方法引用原始论文、官方文档或数据发布论文。
150. **参考文献由模型自动生成后不核验**：可能出现不存在的 DOI、作者或页码；逐条核对 DOI、题名、年份和实际贡献。

## 十六、学术规范、署名与开放科学（151—160）

151. **把 AI 工具列为作者**：工具无法承担准确性、完整性和原创性责任；作者必须是能审核并负责工作的自然人。
152. **不披露 AI 辅助写作或代码生成**：不同期刊要求不同，隐瞒会带来合规风险；按目标期刊在方法、致谢或投稿信中披露。
153. **让 AI 生成未核验引用**：幻觉引用会直接损害可信度；所有引用回到出版社、期刊或 DOI 页面核对。
154. **把患者图像上传到公共模型**：可能违反伦理和数据协议；优先本地/机构部署，必要时先脱敏并获得批准。
155. **把未发表稿件交给公共模型润色**：稿件可能包含未公开结果和敏感信息；使用机构批准工具并保存版本和披露记录。
156. **用生成式图像制造实验结果**：合成图不能冒充真实样本或预测；图像增强必须保留生成参数并明确标注用途。
157. **让 AI 自动改数字、表格和统计结论**：文本流畅不代表数字正确；数字由脚本生成，AI 只做语言层面辅助。
158. **署名顺序靠工具贡献量决定**：署名要依据实质性智力贡献和责任；使用 CRediT 或课题组书面约定。
159. **审稿时把稿件上传外部模型**：可能违反保密和期刊政策；审稿材料默认不得进入公共生成式 AI。
160. **只公开最终代码不公开数据处理**：别人无法复现关键结果；公开可分享的预处理、split、配置、评估脚本和限制说明。

## 十七、2026 年 AI 深度使用下的新风险（161—170）

161. **把“能让 AI 写代码”误认为掌握研究**：代码生成速度提高，但假设、标签和评价仍需研究者负责；每段生成代码都要用最小测试验证。
162. **让 AI 一次性重构整个项目**：大范围改动难以审计；采用小提交、单功能变更和自动回归测试。
163. **只看 AI 的解释不读原论文和代码**：摘要可能省略限制；AI 输出作为检索入口，关键结论回到原始来源。
164. **用 AI 自动筛文献却不检查召回偏差**：模型可能漏掉非英语、负结果或相邻领域；保留检索式、数据库和人工纳排标准。
165. **把自动生成的实验计划当预注册**：AI 不会替你承担选择责任；由研究者锁定假设、主终点和分析计划并留时间戳。
166. **让 AI 读取全部临床数据做“探索”**：无目的搜索容易产生偶然关联和隐私风险；先定义最小必要数据、用途和访问权限。
167. **使用闭源大模型却无法追踪版本**：模型更新会改变代码、解释和检索结果；记录模型名称、版本/日期、提示词、附件和输出修订过程。
168. **把 AI 生成的 synthetic 数据当真实增样本**：生成分布可能复制训练集或引入伪影；做近重复检测、专家审查和真实外部测试。
169. **忽略模型供应链风险**：预训练权重、数据集脚本和依赖包可能含恶意代码；固定来源、校验哈希、隔离环境并最小权限运行。
170. **把“自动化闭环”交给无人值守服务器**：AI 可能连续修改代码、重跑和选择结果；设置资源上限、人工审批点、审计日志和停止条件。

## 十八、AI 辅助科研的正确工作流（171—180）

171. **不区分 AI 的四种角色**：检索、编程、分析、写作的风险不同；为每种角色单独记录输入、输出、人工核验和最终责任人。
172. **提示词没有任务边界**：开放式提示易生成臆测；在提示中给数据字典、约束、禁止事项、输出格式和“未知就说未知”。
173. **让模型直接决定实验结论**：模型没有实验现场和统计责任；结论必须来自固定脚本和锁定数据。
174. **用 AI 生成评估代码却没有手算基准**：指标实现的一个维度错误会污染整篇论文；用手工小例子验证 Dice、IoU、HD95 和空集。
175. **AI 修改代码后不看 diff**：隐式改了学习率、类别数或路径；逐行审查 diff 并运行 smoke test。
176. **只保存最终提示词**：无法知道中间事实从何而来；保存对话摘要、引用来源、人工修订和工具版本。
177. **用 AI 生成数据字典却不与样本核对**：字段含义可能被模型猜错；从真实文件统计反推数据字典。
178. **把 AI 的“看起来合理”当作医学知识**：病理边界和临床意义需要专家；建立导师/影像科专家复核环节。
179. **自动化报告没有异常报警**：脚本可能在全空预测时仍输出漂亮均值；设置 NaN、全空、全满、数量突变和指标反常报警。
180. **没有 AI 使用登记表**：投稿时无法准确披露；记录工具、日期、用途、是否输入敏感数据、人工核验和对最终文本的影响。

## 十九、投稿、答辩与长期维护（181—190）

181. **只按摘要字数选期刊**：范围、数据共享和 AI 政策同样关键；投稿前逐项核对指南和最新版本。
182. **忽略预印本与正式稿差异**：预印本公开后仍需维护版本；标注版本、DOI、修订内容和数据可用性。
183. **答辩只背网络结构**：老师更关心问题、证据和局限；准备“为什么这样划分、为何指标可信、失败在哪里”的证据链。
184. **无法从论文重跑一张表**：这是可复现性硬伤；答辩前用干净环境从 manifest 重跑关键表和图。
185. **论文提交后删除原始日志**：审稿补实验会失去基线；按实验 ID 归档代码、配置、日志、权重和结果。
186. **只保存最好模型不保存随机种子**：无法解释重跑差异；把 seed、commit、环境和数据版本写入 checkpoint 元数据。
187. **不准备审稿人质疑的反例**：过度防御会削弱可信度；主动报告局限、外部验证不足和临床转化障碍。
188. **忽略复现实验的时间成本**：审稿周期内环境和依赖会变化；提供锁定环境、容器或最小重现脚本。
189. **把开源等同于可复现**：仓库公开但数据、权重和配置缺失仍不可复现；写清哪些因许可不能提供及替代方案。
190. **项目结束后无人维护**：链接、依赖和模型服务会失效；指定维护人、版本标签、归档 DOI 和弃用说明。

## 二十、每天可执行的研究习惯（191—200）

191. **不写实验 ID**：没有唯一 ID 就无法关联代码、日志和图；格式包含日期、任务、变体和 seed。
192. **一天只记“跑了一个实验”**：信息不足以排错；记录命令、数据版本、配置、起止时间、最好指标和异常。
193. **不保存失败样本列表**：失败模式无法形成研究问题；每次验证保存预测、真值、指标和病例 ID。
194. **不做固定小样本 smoke test**：全量训练前发现 bug 太晚；每次改动先跑 1—2 个 batch，检查 loss、梯度、输出值域和可视化。
195. **不做数据管线单元测试**：错配可能训练数小时后才发现；测试配对、标签值、插值、尺寸、spacing 和空 mask。
196. **不做每周结果快照**：后续改动会覆盖历史；每周导出表格、曲线、配置和代码 commit，写三行结论与下一步。
197. **把导师口头意见当最终协议**：口头建议可能被误解；会后写成假设、实验、判定标准并请对方确认。
198. **同时追逐所有新模型**：2026 年模型迭代很快，追热点会打断主线；设定“相关性门槛”，只有能检验主问题的技术才加入。
199. **忽视自己的学习基础**：只会调用框架难以定位问题；按优先级补齐概率、优化、医学成像、统计和软件工程。
200. **没有停止规则**：无限调参会消耗时间并制造选择偏差；预设实验预算、主结论、失败判据和何时转向下一个问题。

## 使用这 200 条的建议

不要试图一次背完。每个新实验开始前，至少检查第 21—30、51—60、71—90、111—130 条；每周从 191—200 条中选 2 条落实。把“坑点”转换成项目中的文件：`split_manifest.csv`、`config.json`、`command.txt`、`metrics_per_case.csv`、`failed_cases.csv`、`environment.txt` 和 `AI_use_log.md`。这样做的目标不是把流程变重，而是让每个数字都能回答“来自哪份数据、哪段代码、哪次运行”。

## 2026 年 AI 使用的最低合规底线

- AI 可以辅助检索、代码草拟、语言润色和重复性自动化，但研究者必须核验事实、代码、数据和结论，并承担最终责任。
- 不把可识别患者数据、未公开稿件、受限评审材料或密钥输入未经批准的公共模型。
- 不让 AI 生成、篡改或选择性删除实验数据、预测图和统计结果；任何生成内容都必须明确用途并可追溯。
- 投稿前查看目标期刊/会议的最新 AI 披露、署名、图像和数据政策。ICMJE 明确要求披露 AI 辅助技术使用且不将聊天机器人列为作者；Nature Portfolio 也强调 AI 不能承担作者责任，具体要求可能随刊物更新。
