# EMCAD 完整模型全流程：从一张 CT 切片到八个器官分割

> 本文依据当前项目中的 `train_synapse.py`、`trainer.py`、`lib/networks.py`、`lib/pvtv2.py`、`lib/decoders.py`、`utils/dataset_synapse.py` 和 `utils/utils.py` 编写。默认讨论 Synapse、`PVTv2-B2`、输入 `224×224`、9 类输出、`kernel_sizes=[1,3,5]`、`expansion_factor=2`、并行 MSDC、分支相加、`lgag_ks=3`、MSCB 使用 ReLU6 的实际训练配置。

## 1. 先用一句话理解 EMCAD

EMCAD 可以看成一家处理腹部 CT 的“多器官会诊中心”：

1. 数据预处理部门先统一 CT 的灰度范围、方向和大小；
2. PVTv2-B2 编码器从四个高度观察切片，逐渐从边缘纹理提炼到器官级语义；
3. EMCAD 解码器从最粗的全局判断出发，逐级放大，并有选择地取回浅层的高清细节；
4. 四个预测头分别提交一份 9 类像素判定；
5. 训练时用交叉熵和 Dice 追究错误，再把纠错信号反向传给所有部门；
6. 测试时对一个病例的所有切片逐张处理，再堆回三维病例计算指标。

这家“会诊中心”最终不是回答“这张图有没有肝脏”，而是给 `224×224` 中的每一个像素分配一个类别：背景或 8 个器官之一。

## 2. 全文统一事例：腹部 CT 多器官会诊中心

假设医院送来某位患者的一张轴向腹部 CT 切片。真实标签中可能同时包含肝脏、脾脏、胃、胰腺等器官。模型要绘制一张与原图等大的彩色区域图。

| 模型概念 | 会诊中心中的角色 | 真正的数学含义 |
|---|---|---|
| CT 切片 | 一张腹部地图 | 连续灰度数组 |
| 像素/体素 | 地图上的一个地点 | 一个采样位置 |
| 通道 | 一组专业线索 | 网络学习出的特征维度 |
| feature map | 某类线索在全图的响应分布 | `[B,C,H,W]` 张量，不是原图缩略图 |
| 编码器 | 四级影像分析部 | 逐级降采样并提炼语义 |
| Transformer token | 编号后的地图小区域 | `[B,N,C]` 中的一个位置向量 |
| CAB | 决定哪些专业线索更值得听 | 通道权重 `[B,C,1,1]` |
| SAB | 决定地图上哪些位置更值得看 | 空间权重 `[B,1,H,W]` |
| MSDC | 用不同大小的观察窗检查 | 1×1、3×3、5×5 深度卷积 |
| EUCB | 把粗地图展开到更精细一级 | 2 倍上采样并变换通道 |
| LGAG | 由上级结论指挥资料筛选 | 用 decoder 特征门控 encoder skip |
| skip connection | 早期部门保存的高清证据 | `x1/x2/x3` 编码特征 |
| 输出头 | 四个层级各自提交分类报告 | 1×1 卷积得到 9 类 logits |
| CE | 检查每个地点类别是否判错 | 像素级多类交叉熵 |
| Dice loss | 检查整块器官轮廓是否重合 | 类别区域重叠损失 |
| 反向传播 | 根据错案逐级追责和修正规则 | 自动求导计算参数梯度 |

这个比喻只用于理解职责。模型没有医生式意识，“重要”“关注”和“会诊”本质上都是可学习权重、卷积、矩阵乘法与加法。

## 3. 一眼看完整数据流

```text
原始 3D CT 与标签
  |
  | 截断 [-125,275] HU、归一化到 [0,1]、转成 [D,H,W]
  | 训练病例拆为独立 2D 轴向切片
  v
[B,1,224,224]
  |
  | 1x1 Conv + BN + ReLU，单通道适配为 3 通道
  v
[B,3,224,224]
  |
  | PVTv2-B2 四阶段编码
  +--> x1 [B, 64,56,56] ------------------------------ skip 1 --+
  +--> x2 [B,128,28,28] --------------------- skip 2 --+        |
  +--> x3 [B,320,14,14] ------------ skip 3 --+        |        |
  +--> x4 [B,512, 7, 7]                       |        |        |
              |                               |        |        |
              | CAB -> SAB -> MSCB            |        |        |
              v                               |        |        |
             d4 [B,512, 7, 7] -> EUCB -> LGAG(x3) + -> d3 [B,320,14,14]
                                                           |
                                     CAB -> SAB -> MSCB <-+
                                                           v
                                    EUCB -> LGAG(x2) + -> d2 [B,128,28,28]
                                                           |
                                     CAB -> SAB -> MSCB <-+
                                                           v
                                    EUCB -> LGAG(x1) + -> d1 [B,64,56,56]

d4 -> 1x1 head -> [B,9, 7, 7] -> x32 bilinear -> p4 [B,9,224,224]
d3 -> 1x1 head -> [B,9,14,14] -> x16 bilinear -> p3 [B,9,224,224]
d2 -> 1x1 head -> [B,9,28,28] ->  x8 bilinear -> p2 [B,9,224,224]
d1 -> 1x1 head -> [B,9,56,56] ->  x4 bilinear -> p1 [B,9,224,224]

训练：四个 logits -> mutation/deep supervision/last layer -> CE + Dice -> backward
测试：只取 P[-1]，即 p1 -> softmax -> argmax -> 2D 类别图 -> 堆回 3D 病例
```

## 4. 张量尺寸总账

`B` 是 batch size。默认 `batch_size=6` 时，表中的 `B` 通常为 6；为了通用性仍写作 `B`。

| 环节 | 张量 | 形状 | 会诊中心理解 |
|---|---|---:|---|
| 输入切片 | image | `[B,1,224,224]` | B 张单通道腹部地图 |
| 输入适配 | adapted | `[B,3,224,224]` | 每张地图转成 3 组可学习的初始描述 |
| 编码 stage 1 | x1 | `[B,64,56,56]` | 高清、偏局部的 64 类线索 |
| 编码 stage 2 | x2 | `[B,128,28,28]` | 范围更大的 128 类线索 |
| 编码 stage 3 | x3 | `[B,320,14,14]` | 器官部件级的 320 类线索 |
| 编码 stage 4 | x4 | `[B,512,7,7]` | 最粗但语义最强的 512 类线索 |
| 解码 stage 4 | d4 | `[B,512,7,7]` | 整理最深层全局报告 |
| 解码 stage 3 | d3 | `[B,320,14,14]` | 加回筛选后的 x3 细节 |
| 解码 stage 2 | d2 | `[B,128,28,28]` | 加回筛选后的 x2 细节 |
| 解码 stage 1 | d1 | `[B,64,56,56]` | 加回筛选后的 x1 细节 |
| 四个预测 | p4/p3/p2/p1 | 各 `[B,9,224,224]` | 每像素 9 个未归一化评分 |
| 标签 | label | `[B,224,224]` | 每像素一个整数 0～8 |

9 类中，`0` 是背景，`1～8` 的当前测试脚本顺序是：主动脉、胆囊、左肾、右肾、肝脏、胰腺、脾脏、胃。

## 5. 数据进入模型前发生了什么

### 5.1 原始三维 CT 预处理

`utils/preprocess_synapse_data.py` 对每个病例执行：

1. 读取 CT 和对应标签 NIfTI；
2. 把 CT 强度截断到 `[-125,275] HU`；
3. 用 `(x - (-125)) / 400` 映射到 `[0,1]`；
4. 将数组从 `(H,W,D)` 转成 `(D,H,W)`；
5. 训练病例沿 D 轴拆成一张张 `.npz`，测试病例保留为完整 `.npy.h5`。

会诊中心的理解：接诊部门统一“地图的印刷标准”。过黑和过白的极端值被压到边界，所有病例使用同一把灰度尺，切片方向也统一。

这里的 `clip` 不是空间裁剪，不会删除图像边缘或器官；它只截断 CT 强度。当前 Synapse 活动训练路径也没有随机空间 crop。它会旋转、翻转和 resize，但不是随机切掉一块图像。因此，不能把“灰度截断”“尺寸缩放”和“空间裁剪”混为一谈。

### 5.2 训练时的数据增强

`RandomGenerator` 对 CT 和标签同步执行随机变换：

- 一定概率做 0°、90°、180°、270° 旋转，再上下或左右翻转；
- 否则有一定概率做 `[-20°,19°]` 小角度旋转；
- 将图像和标签统一缩放到 `224×224`；
- CT 图像缩放用三次插值 `order=3`；标签用最近邻 `order=0`，防止产生 2.4、5.7 这类不存在的类别。

增强的作用是让会诊中心见到“地图换个朝向仍是同一器官”，减少对固定位置和方向的死记硬背。CT 和标签必须同步变换，否则相当于拿甲患者的地图配乙患者的答案。

### 5.3 训练样本的边界

当前模型按单张 2D 切片训练。一批数据通常是 `[B,1,224,224]`，模型不知道这张切片的前一张和后一张是什么。因此它不能直接利用 Z 轴连续性。测试时虽然最后堆回 3D 病例，但每张切片仍是独立推理；“事后堆叠”不等于“模型看过三维上下文”。

## 6. 输入适配器：为什么 1 通道要变 3 通道

Synapse CT 是单通道，但 ImageNet 预训练的 PVTv2-B2 入口期望 3 通道。`EMCADNet` 使用：

`1×1 Conv(1→3) → BatchNorm2d(3) → ReLU`

形状由 `[B,1,224,224]` 变为 `[B,3,224,224]`，空间尺寸不变。

会诊中心的理解：接待处不改变地图的地点数量，而是为每个地点生成三份不同的初始描述，供原本为三通道图像设计的编码部门读取。

必须注意：这不是三个 CT 窗，也不是简单复制三份，更不是三位医生。1×1 卷积的三个输出通道有独立可学习权重，BN 再调整其批次统计，ReLU 加入非线性。

## 7. PVTv2-B2 编码器：四级影像分析部

### 7.1 编码器为什么要逐级缩小地图

高分辨率适合找边界，却昂贵且容易只见局部；低分辨率丢失精细边缘，却能让一个位置综合更大范围的信息。PVTv2 用四个 stage 同时保存这两类能力：

- `x1`：位置精细，偏边缘、纹理、局部结构；
- `x2`：局部与中程结构；
- `x3`：器官部件和较强语义；
- `x4`：全局布局和最强语义，但边界最粗。

它们不是同一图像的普通缩略图，而是经过卷积、注意力和 MLP 学习后的特征。

### 7.2 Overlap Patch Embedding：把地图切成互相重叠的调查区

每个 stage 的第一步是 `OverlapPatchEmbed`：卷积投影后，将二维特征展平成 token，再做 LayerNorm。

| stage | 输入 | 卷积核/步长 | token 形状 | 恢复后的特征 |
|---|---:|---:|---:|---:|
| 1 | `[B,3,224,224]` | 7×7 / 4 | `[B,3136,64]` | `x1=[B,64,56,56]` |
| 2 | `[B,64,56,56]` | 3×3 / 2 | `[B,784,128]` | `x2=[B,128,28,28]` |
| 3 | `[B,128,28,28]` | 3×3 / 2 | `[B,196,320]` | `x3=[B,320,14,14]` |
| 4 | `[B,320,14,14]` | 3×3 / 2 | `[B,49,512]` | `x4=[B,512,7,7]` |

会诊中心的理解：不是把地图切成互不相干的小方块，而是让相邻调查区适度重叠，减少边界处信息被生硬截断。

### 7.3 每个 Transformer Block 内部做什么

PVTv2-B2 四阶段 Block 数为 `[3,4,6,3]`。每个 Block 的主流程是：

1. `LayerNorm`：统一每个 token 内各特征的尺度；
2. `Attention`：让一个位置结合其他位置的信息；
3. `DropPath`：训练时随机跳过整条残差支路，起正则化作用；
4. 第一次残差相加：原 token 加上注意力修正；
5. 第二个 `LayerNorm`；
6. `MLP`：先扩展通道，再用 DWConv 引入局部空间关系，经过 GELU 和 dropout 后压回原通道；
7. 第二次残差相加：保留原信息，并加入 MLP 修正。

会诊中心的理解：每个调查员先校准自己的记录，再跨区域交换情报，然后做一次局部综合分析。两条残差连接相当于“原始记录不能被新意见完全覆盖，只允许在其上修订”。

### 7.4 Spatial-Reduction Attention：为什么不让所有位置都昂贵地两两比较

标准自注意力会让所有 token 两两比较，早期 `56×56=3136` 个位置的成本很高。PVTv2 的 `sr_ratios=[8,4,2,1]`：

- Query 保持当前全部位置；
- Key 和 Value 在前三级先做空间降采样；
- 最深层只有 `7×7`，`sr_ratio=1`，无需再缩小。

多头数为 `[1,2,5,8]`。多头相当于允许不同组从不同关系角度交换信息，但这些“角度”同样只是学习出的子空间，不对应固定的医学器官。

会诊中心的理解：每个地点都可以发问，但早期不必逐一询问地图上所有地点，而是先把被询问方汇总成较少的区域代表，从而节省计算。

### 7.5 MLP 中的 DWConv 有什么作用

纯 token MLP 主要在通道维加工，未必天然知道相邻位置。PVTv2 的 MLP 在第一次线性扩展后，把 token 临时还原为二维图，执行 3×3 depth-wise convolution，再展平回来。

会诊中心的理解：跨区域会议之后，每个专业还要回到地图上检查邻近地点，让 Transformer 的全局关系与卷积的局部连续性互补。

## 8. EMCAD 解码器：从全局判断逐级画回边界

编码结束时，`x4=[B,512,7,7]` 知道“这里大概是什么”，但不能直接画出 224×224 的精确边界。解码器从 x4 起步，依次回到 14、28、56 的空间尺度。

每一级的核心模式是：

`通道筛选 CAB → 空间筛选 SAB → 多尺度细化 MSCB`

论文将这套组合称为 MSCAM，但当前代码中没有独立的 `MSCAM` 类；它是在 `EMCAD.forward` 里把 CAB、SAB、MSCB 串起来实现的。

## 9. CAB：先决定“听哪些专业线索”

CAB 输入 `[B,C,H,W]`，输出 `[B,C,1,1]` 的通道权重。

内部步骤：

1. 全局平均池化：每个通道得到一个“整体平均表现”；
2. 全局最大池化：每个通道得到一个“最强局部表现”；
3. 两路共享 `1×1 Conv(C→C/16) → ReLU → 1×1 Conv(C/16→C)`；
4. 两路结果相加后过 Sigmoid，得到 C 个 0～1 权重；
5. `EMCAD.forward` 将权重广播乘回原特征。

以 d2 为例：

- 输入 `[B,128,28,28]`；
- 平均池化和最大池化各得到 `[B,128,1,1]`；
- 瓶颈变成 `[B,8,1,1]`，再恢复 `[B,128,1,1]`；
- 最后乘回所有 28×28 位置，形状仍为 `[B,128,28,28]`。

会诊中心的理解：128 个通道像 128 类专业证据。CAB 根据整张地图的平均情况与最显著情况，决定本病例中哪些证据更可信。

CAB 只能为每个通道给一个全局权重，同一通道在所有位置使用同一个权重，所以它不能独自回答“胃具体在哪里”。

四级 CAB 参数不共享，因为它们分别处理 512、320、128、64 通道，权重形状不同。

## 10. SAB：再决定“地图上看哪些位置”

SAB 输入 `[B,C,H,W]`，输出 `[B,1,H,W]` 的空间权重。

内部步骤：

1. 沿通道求平均，得到 `[B,1,H,W]`；
2. 沿通道取最大，得到另一张 `[B,1,H,W]`；
3. 拼成 `[B,2,H,W]`；
4. 通过 7×7 卷积压成 `[B,1,H,W]`；
5. Sigmoid 得到每个位置 0～1 的权重；
6. 在 `EMCAD.forward` 中广播乘回 C 个通道。

会诊中心的理解：CAB 已决定“哪些专业意见重要”，SAB 接着在地图上圈出“哪些地点值得这些专业重点检查”。

SAB 与通道数无关，所以当前代码只创建一个 `self.sab`，在 7×7、14×14、28×28、56×56 四个尺度重复使用。同一次前向中，每个尺度会生成不同权重图，但 7×7 卷积参数是共享的。

## 11. MSDC：用三把不同大小的尺子观察

MSDC 默认创建三条 depth-wise convolution 分支：

- 1×1：最局部、近似逐点变换；
- 3×3：观察邻近区域；
- 5×5：观察更大局部上下文。

每条支路都是 `depth-wise Conv → BN → ReLU6`。depth-wise 表示每个通道独立做空间卷积，不在该步混合不同通道，所以计算量远低于同通道数的普通卷积。

当前 `dw_parallel=True`，三条分支读取同一份输入。若关闭并行，后一分支会读取前一分支残差更新后的特征，变成递进式处理。

会诊中心的理解：同一份证据交给近距离、中距离和较大范围三组调查员。近距离看小边缘，大范围看器官周围关系，避免只用一种观察尺度。

MSDC 本身返回三个张量组成的列表，并不负责最终融合。

## 12. MSCB：一座完整的多尺度加工车间

MSCB 把 MSDC 包装为带通道扩张、融合、重排、投影和残差的完整块。以 d2 的 `C=128` 为例，实际默认流程是：

1. `1×1 Conv + BN + ReLU6`：`128→256`，得到 `[B,256,28,28]`；
2. MSDC 三分支：分别得到三个 `[B,256,28,28]`；
3. `add=True`：三个分支逐元素相加，仍为 `[B,256,28,28]`；
4. channel shuffle：只重新排列 256 个通道，形状不变；
5. `1×1 Conv + BN`：`256→128`；
6. 与块输入残差相加，得到 `[B,128,28,28]`。

会诊中心的理解：先把 128 类证据扩展成 256 个调查岗位；三组分别使用不同观察范围；把结论汇总；打乱原来的专业小组边界，让信息重新交流；压缩成 128 条正式结论；最后与车间入口的原始报告相加，防止加工过度。

### 12.1 为什么要扩张再压缩

直接在 128 通道上加工容量有限。先扩到 256 通道，给不同模式更多中间表示空间；空间卷积采用便宜的 depth-wise 形式；最后用 1×1 卷积完成跨通道融合并压回 128。

### 12.2 channel shuffle 在做什么

depth-wise 或分组处理容易让通道之间各管各的。shuffle 不创造新值，只重新排列通道顺序，使后续 1×1 卷积更容易组合来自不同原组的信息。

### 12.3 残差连接在做什么

MSCB 输出是“原输入 + 学到的修正”。若新加工暂时无益，网络仍可保留原信息；梯度也多一条直接传播路径。

### 12.4 `add=True` 到底控制什么

它只控制 MSDC 的 1×1、3×3、5×5 分支是相加还是拼接。它不控制 encoder skip 与 decoder 主路的融合。后者在当前代码中始终是逐元素相加。

如果命令行使用 `--concatenation`，三条 256 通道分支会拼成 768 通道，再由 1×1 投影压回 128；参数量、计算量和统计行为都会改变。

`MSCBLayer` 是一层包装器，可堆叠 n 个 MSCB；当前 EMCAD 四处都传 `n=1`，所以每个解码阶段实际只有一个 MSCB。

## 13. EUCB：把粗地图展开到更精细一级

EUCB 的内部流程是：

`Nearest Upsample ×2 → 3×3 depth-wise Conv → BN → ReLU → channel shuffle → 1×1 Conv`

PVTv2-B2 的三个实例为：

| EUCB | 输入 | 输出 |
|---|---:|---:|
| eucb3 | `[B,512,7,7]` | `[B,320,14,14]` |
| eucb2 | `[B,320,14,14]` | `[B,128,28,28]` |
| eucb1 | `[B,128,28,28]` | `[B,64,56,56]` |

会诊中心的理解：把低分辨率总览地图展开两倍，先修整放大造成的粗糙局部，再把专业线索数转换为下一层能接收的数量。

这里 `nn.Upsample` 未指定 mode，对四维张量采用最近邻上采样。EUCB 中以 `groups=C` 调用 channel shuffle 时，每组只有一个通道，当前配置下实际上等价于恒等重排；真正的跨通道学习来自最后的 1×1 卷积。

## 14. LGAG：让上级结论筛选高清旧档案

浅层 skip 有清晰边缘，但也包含大量背景纹理。直接全部加回来可能把噪声带入解码器。LGAG 同时接收：

- `g`：当前 decoder 已上采样特征，表示“现在想找什么”；
- `x`：同分辨率 encoder skip，表示“早期保存了什么高清细节”。

以第一个 LGAG 为例：

1. `g=[B,320,14,14]` 经 3×3 分组卷积和 BN，变成 `[B,160,14,14]`；
2. `x3=[B,320,14,14]` 经另一套参数得到 `[B,160,14,14]`；
3. 两者相加并 ReLU；
4. 1×1 卷积、BN、Sigmoid 生成 `psi=[B,1,14,14]`；
5. `x3 × psi`，返回筛选后的 `[B,320,14,14]`；
6. EMCAD 在门外执行 `d3 = d3 + gated_x3`。

会诊中心的理解：上级报告说“现在重点寻找胃的可能区域”，门卫据此从基层高清档案中放行相关位置的边缘信息，压低无关背景。

LGAG 的 psi 是单通道空间门，因此同一位置的所有 skip 通道共享一个系数。通道选择主要交给后面的 CAB。Sigmoid 让门值处于 0～1，LGAG 本身做抑制或保留，不直接把 skip 放大到原幅度以上。

## 15. 四级解码按真实执行顺序走一遍

### 15.1 第四级：在 7×7 全局报告上先整理

输入：`x4=[B,512,7,7]`

1. CAB 生成 `[B,512,1,1]`，筛选通道；
2. SAB 生成 `[B,1,7,7]`，筛选位置；
3. MSCB：512→1024，多尺度加工，再压回 512 并残差相加；
4. 得到 `d4=[B,512,7,7]`。

这里没有 skip，因为 x4 本身就是编码器最深层。它先形成全局“器官在哪里”的粗判断。

### 15.2 第三级：恢复到 14×14，并取回 x3

1. d4 经 EUCB3：`[B,512,7,7]→[B,320,14,14]`；
2. LGAG3 用该特征筛选 `x3=[B,320,14,14]`；
3. decoder 主路与门控后的 x3 相加；
4. CAB → SAB → MSCB；
5. 得到 `d3=[B,320,14,14]`。

### 15.3 第二级：恢复到 28×28，并取回 x2

1. d3 经 EUCB2：`[B,320,14,14]→[B,128,28,28]`；
2. LGAG2 筛选 `x2=[B,128,28,28]`；
3. 相加后执行 CAB → SAB → MSCB；
4. 得到 `d2=[B,128,28,28]`。

### 15.4 第一级：恢复到 56×56，并取回 x1

1. d2 经 EUCB1：`[B,128,28,28]→[B,64,56,56]`；
2. LGAG1 筛选 `x1=[B,64,56,56]`；
3. 相加后执行 CAB → SAB → MSCB；
4. 得到 `d1=[B,64,56,56]`。

解码器到这里并没有生成 224×224 特征。它停在输入的 1/4 尺度，最终尺寸恢复由分割头后的插值完成，以控制计算量。

## 16. 四个预测头：四个层级都要交作业

四个独立的 1×1 卷积将解码特征变成 9 个类别通道：

- d4：512→9，7×7，再双线性放大 32 倍；
- d3：320→9，14×14，再放大 16 倍；
- d2：128→9，28×28，再放大 8 倍；
- d1：64→9，56×56，再放大 4 倍。

最终 `P=[p4,p3,p2,p1]`，四个元素都是 `[B,9,224,224]`。

会诊中心的理解：四个高度的部门都必须给出一份与原地图同大的 9 类报告。深层报告轮廓粗但理解全局，浅层报告边界更细。

### 16.1 一个像素的 9 个数是什么意思

假设某像素的 logits 是：

`[-1.2, 0.4, -0.3, 0.1, 0.2, 2.8, -0.7, 0.5, 1.1]`

它们是背景和 8 个器官的原始竞争分数，不是概率，也不要求加起来等于 1。softmax 后才会成为总和为 1 的概率；argmax 会选择最大分数对应的类别。本例最大值位于通道 5，按当前顺序即肝脏。

### 16.2 双线性插值做了什么

插值只在每个类别通道内部补空间采样点，不会把“肝脏通道”和“胃通道”混在一起。它能平滑恢复尺寸，但不能凭空恢复编码时已经完全丢失的精细结构，所以 skip connection 很重要。

### 16.3 代码命名与论文命名不要混淆

当前代码返回列表最后一个 `p1` 是最高分辨率解码头，测试取 `P[-1]`。论文中的阶段命名方向可能不同，阅读时应以张量尺寸和实际索引为准。

## 17. 训练：模型怎样知道自己错在哪里

### 17.1 CrossEntropyLoss：逐像素追究类别错误

CE 接收 `[B,9,224,224]` logits 和 `[B,224,224]` 整数标签。对每个像素，它鼓励真实类别的分数高于其他 8 类。

会诊中心的理解：逐地点核对。“这个位置真实是胃，你却把主动脉分数打得最高”，就会受到惩罚。

CE 擅长类别判别，但大器官像素多、背景更多，仅靠逐像素平均可能对小器官区域不够敏感。

### 17.2 DiceLoss：从整块器官重叠角度追究错误

当前 DiceLoss：

1. 对 logits 做 softmax；
2. 把标签转成 `[B,9,H,W]` one-hot；
3. 对每一类计算 soft Dice loss；
4. 9 类等权平均，包括背景类。

单类公式使用：

`1 - (2×交集 + 1e-5) / (预测概率平方和 + 标签平方和 + 1e-5)`

会诊中心的理解：不只逐地点判卷，还把“预测肝脏区域”与“真实肝脏区域”整体叠放，检查覆盖和遗漏。

当前实现对一个 batch 内某类别的所有样本和空间位置一起求和，属于 batch-level soft Dice；它不是先逐张计算再平均。

### 17.3 两种损失如何合并

每个监督项使用：

`0.3 × CrossEntropy + 0.7 × DiceLoss`

CE 关注像素类别竞争，Dice 关注区域重叠，两者互补。

## 18. mutation supervision：为什么四个输出能形成 15 份考卷

当前默认 `supervision='mutation'`。四个输出索引 `[0,1,2,3]` 的所有非空子集共有 `2^4-1=15` 个：

- 4 个单头组合；
- 6 个双头组合；
- 4 个三头组合；
- 1 个四头组合。

对于组合 `[0,2,3]`，代码先逐元素相加 logits：`p4+p2+p1`，再对这个和计算一次 CE 和 Dice。它不是先 softmax 后平均概率。

15 份损失直接累加，没有除以 15。于是：

- 同一个头会从多个组合收到梯度；
- 共享 encoder/decoder 会汇总所有路径的梯度；
- mutation 的 loss 数值天然比只算 4 项或 1 项更大，不能直接用绝对 loss 大小横向比较三种监督模式。

另外两种模式是：

- `deep_supervision`：四个输出各自单独计算，共 4 项；
- `last_layer`：只监督 `P[-1]`，共 1 项。

会诊中心的理解：不仅考核四个部门各自报告，还随机要求不同层级联合提交意见，迫使各层输出在单独和联合时都具有辨别力。

## 19. 反向传播与参数更新：一次训练 batch 的闭环

一次 batch 的真实顺序是：

1. `optimizer.zero_grad()` 清除上一批梯度；
2. 15 个组合损失相加为总 loss；
3. `loss.backward()` 使用链式法则计算梯度；
4. 梯度从损失返回四个预测头；
5. 再返回 d1～d4、CAB/SAB/MSCB、LGAG、EUCB；
6. 再经 skip 与主路返回 PVTv2 四阶段和输入适配器；
7. `AdamW.step()` 更新所有可训练参数。

会诊中心的理解：最终错案会追溯到每个环节。例如胃边界漏分，可能同时调整最高分辨率输出头、浅层门控、空间注意力、多尺度卷积，甚至更早的编码特征，而不是只处罚最后一个部门。

当前实际优化器是 AdamW，基础学习率 `1e-4`，weight decay `1e-4`。代码中的多项式学习率衰减被注释，实际每次迭代将学习率写回常数 `base_lr`。

训练配置默认 300 epoch、单 GPU batch size 6。每个 epoch 保存覆盖式 `last.pth`，指标刷新时保存 `best.pth`，每 50 轮还保存阶段性权重。这里只保存模型 `state_dict`，不含优化器、epoch 和随机状态，因此 `last.pth` 不是完整的无缝续训快照。

## 20. 测试：从二维结果重新组成三维病例

训练集被拆成 2D 切片，但测试集读取一个完整病例 `[D,H,W]`。`test_single_volume` / `val_single_volume` 执行：

1. 遍历深度 D 上的每张切片；
2. 若原切片不是 224×224，用连续插值缩放图像；
3. 加成 `[1,1,224,224]` 后送入模型；
4. 模型仍返回四个 logits，只取 `P[-1]`；
5. 对类别维执行 softmax，再 argmax 得到 2D 整数类别图；
6. 若之前缩放过，用最近邻插值还原原切片尺寸；
7. 写回 `prediction[ind]`，最后得到完整 `[D,H,W]` 预测体；
8. 对前景标签 1～8 分别计算指标，不把背景纳入测试均值。

正式测试路径可计算 Dice、HD95、Jaccard 和 ASD；训练期间的 `val_single_volume` 只返回逐类 Dice。

会诊中心的理解：每一页 CT 都单独会诊，结束后按原顺序装订回整本病例，再统计八种器官的三维重叠与边界误差。

### 20.1 为什么测试不是 Dice=100%

即便网络训练充分，也要面对病人差异、小器官和细长结构、边界模糊、2D 上下文缺失、224 缩放损失、类别不平衡、标注差异与模型容量限制。模型学习的是从训练患者推广到未见患者的规律，不是拿到测试答案。因此“训练够久”不等于测试必然 90+，更不等于 100%。

## 21. 当前训练代码中的验证边界问题

`trainer.py` 每个 epoch 使用 `split="test_vol"` 的病例计算 Dice，并据此选择 `best.pth`。如果这个 `test_vol` 确实是最终官方测试集，那么测试集已经参与模型选择，属于信息泄漏；此时得到的结果不能视为完全独立的最终测试性能。

规范做法应当是：

1. 训练患者只用于参数学习；
2. 独立验证患者用于选择 epoch、超参数和模块；
3. 最终测试患者只在方案完全冻结后评估一次或有限次数。

这不是 EMCAD 网络结构的一部分，却是理解整套实验流程不可缺少的一环。

## 22. 三种“注意力”不要混为一谈

| 名称 | 位于哪里 | 比较/加权对象 | 输出作用 |
|---|---|---|---|
| PVTv2 多头自注意力 | 编码器 Block | token 与 token 的关系 | 建模远近位置关系 |
| CAB | 解码每一级 | 通道的重要性 | 每个通道一个全局权重 |
| SAB | 解码每一级 | 空间位置的重要性 | 每个位置一个权重 |
| LGAG | 三条 skip | decoder 语义与 encoder 细节 | 筛选 skip 的空间位置 |

它们都叫 attention，但输入、计算和目的不同。PVT 注意力建立 token 间关系；CAB、SAB、LGAG 更接近生成权重并门控特征。

## 23. 五种“连接或融合”也不要混为一谈

1. PVT Block 残差：token 加上 Attention/MLP 的修正；
2. MSCB 残差：块输入加上多尺度卷积输出；
3. MSDC 分支聚合：由 `add` 决定多尺度支路相加或拼接；
4. encoder-decoder skip：LGAG 筛选后与 decoder 主路相加；
5. mutation 输出组合：把不同预测头的 logits 相加后算损失。

这五个“加法”发生在完全不同的层级，修改其中一个不能用来推断其他四个也改变了。

## 24. 用一组具体数字理解“权重不是删除”

假设某处有三个通道，某像素的特征为 `[2.0, -1.0, 0.5]`。CAB 给出的通道权重为 `[0.8,0.2,0.6]`，SAB 在该位置给出空间权重 `0.5`：

1. CAB 后：`[1.6,-0.2,0.3]`；
2. SAB 后：`[0.8,-0.1,0.15]`。

这表示不同线索和位置被软加权，不是硬删除。后续卷积、残差和训练仍可利用这些非零响应。只有权重非常接近 0 时才近似强抑制。

同理，LGAG 若在某位置给 `psi=0.1`，只是把该处 skip 证据缩到原来的十分之一；若给 `0.9`，则大部分放行。

## 25. 从头到尾复述一次完整故事

一位患者的三维腹部 CT 到达医院。预处理部门先把强度限制在腹部软组织常用范围，归一化并统一轴顺序。训练时，每张轴向切片被独立取出，和标签同步旋转、翻转、缩放为 224×224。

切片以 `[1,224,224]` 进入网络。接待处用可学习的 1×1 卷积将它转换成三通道。PVTv2-B2 的四级分析部逐级处理：第一级在 56×56 地图上记录边缘和纹理，第二级压到 28×28，第三极压到 14×14 并形成器官部件认识，第四级在 7×7 上形成最强的全局语义。每一级内部都经过重叠 patch embedding、多次归一化、自注意力、带 DWConv 的 MLP 和残差修正。

最深层 x4 交给 EMCAD。CAB 先挑选值得信任的 512 类语义线索，SAB 再圈出关键位置，MSCB 用 1×1、3×3、5×5 三种范围复核并通过残差形成 d4。EUCB 把 d4 放大到 14×14 并把通道改成 320。LGAG 使用这个较强语义报告筛选 x3 的高清档案，二者相加后再经过 CAB、SAB、MSCB，得到 d3。

同样过程再走两轮：d3 放大到 28×28，筛选并融合 x2，得到 d2；d2 放大到 56×56，筛选并融合 x1，得到 d1。这样，模型一边保留深层“这是什么器官”的理解，一边逐步找回浅层“边界具体在哪里”的证据。

d4、d3、d2、d1 各自通过一个独立 1×1 预测头，在每个位置生成 9 个类别 logits，再分别双线性插值到 224×224。训练时默认把四个头形成 15 个非空组合，每个组合用 `0.3×CE+0.7×Dice` 判卷。总损失反向传播到预测头、解码器、编码器和输入适配器，AdamW 根据梯度更新参数。这个过程在大量切片和 epoch 中反复进行。

测试时，一个完整患者仍被逐张切片送入模型。每张只取最后的 p1，softmax 后 argmax 得到类别图，再按深度顺序堆回三维预测体。最后针对 8 个前景器官计算病例级指标。这就是当前仓库中从原始 CT、二维训练、EMCAD 前向、损失学习，到三维病例评估的完整闭环。

## 26. 每个模块解决的问题总表

| 模块/组件 | 主要解决的问题 | 没有它可能怎样 |
|---|---|---|
| HU 截断与归一化 | 统一 CT 强度尺度 | 极端值和病例分布差异增加学习难度 |
| 同步增强 | 提高方向和位置变化鲁棒性 | 更容易记住固定姿态 |
| 1→3 适配器 | 连接单通道 CT 与三通道预训练编码器 | 输入通道不匹配或只能简单复制 |
| Overlap Patch Embed | 降采样并保留邻区连续性 | patch 边界更割裂 |
| PVT Attention | 建模远距离位置关系 | 难以利用全局器官布局 |
| Spatial Reduction | 降低早期注意力计算成本 | 高分辨率自注意力代价过高 |
| PVT MLP + DWConv | 融合通道并补充局部空间关系 | 全局关系与局部连续性结合不足 |
| PVT 残差/DropPath | 稳定深层训练并正则化 | 梯度更难传播、更易过拟合 |
| CAB | 选择重要特征通道 | 所有语义线索被同等对待 |
| SAB | 选择重要空间位置 | 前景与背景位置被同等对待 |
| MSDC | 同时提取多尺度局部模式 | 单一卷积核难兼顾大小器官和边界 |
| depth-wise conv | 低成本做空间卷积 | 普通大卷积参数和计算更多 |
| MSCB 扩张/投影 | 增加中间表达能力并恢复目标通道 | 轻量与容量难平衡 |
| channel shuffle | 促进分组后的通道交换 | 各通道组信息相对孤立 |
| MSCB 残差 | 保留原特征并帮助梯度传播 | 多次加工可能损坏有效信息 |
| EUCB | 逐级恢复空间尺寸并对齐通道 | 无法与下一层 skip 对齐 |
| LGAG | 过滤 skip 中的背景噪声 | 浅层无关纹理直接污染解码 |
| encoder skip | 找回精细边缘和定位 | 仅靠 7×7 深层特征难画准边界 |
| 四个预测头 | 给中间层直接监督 | 深层只能依赖很长的反传路径 |
| CE | 提高逐像素类别判别 | 类别竞争约束不足 |
| Dice loss | 直接优化区域重叠 | 小器官和区域级目标关注不足 |
| mutation supervision | 强化多头单独及组合的可用性 | 中间头约束较弱或协同不足 |
| softmax + argmax | 将 logits 变成最终类别 | 原始分数不能直接作为标签图 |
| 2D→3D 重组 | 按病例统计器官指标 | 只能得到零散切片结果 |

## 27. 最容易产生的十个误解

1. **“3 通道就是三个窗宽窗位”**：不是；当前是可学习 1×1 映射。
2. **“通道 5 就天然代表肝脏”**：中间特征通道没有固定器官语义；只有最终输出通道与标签类别固定对应。
3. **“feature map 是原图缩小版”**：不是；它是学习后的响应图。
4. **“注意力知道自己在看胃”**：不是；它只根据损失学习数值权重。
5. **“MSDC 的 add 控制 skip 融合”**：不是；它只控制多尺度分支聚合。
6. **“四个输出就是四个类别”**：不是；四个输出是四个解码尺度，每个都有 9 个类别通道。
7. **“logits 就是概率”**：不是；softmax 后才是多类概率。
8. **“训练用三维病例”**：不是；当前训练样本是独立二维切片。
9. **“测试堆成 3D 就使用了 3D 上下文”**：不是；只是把独立 2D 结果重组后算指标。
10. **“输入经过裁剪会丢器官”**：当前预处理的 `np.clip` 是灰度截断；活动增强路径是旋转、翻转、resize，没有随机空间 crop。

## 28. 阅读源码的推荐顺序

想把本文与代码逐句对应，建议按以下顺序阅读：

1. `train_synapse.py`：默认参数、模型构造和训练入口；
2. `utils/dataset_synapse.py`：单张训练切片怎样形成；
3. `lib/networks.py`：整网总装和四个输出；
4. `lib/pvtv2.py`：四级编码器内部；
5. `lib/decoders.py`：CAB、SAB、MSDC、MSCB、EUCB、LGAG 与 EMCAD；
6. `trainer.py`：四头监督、损失、反向传播和 checkpoint；
7. `utils/utils.py`：DiceLoss、病例逐切片推理、3D 重组和指标。

把握主线时，只需要始终追踪两件事：当前张量的 `[B,C,H,W]` 是多少，以及当前模块究竟是在改变通道、空间尺寸、数值权重，还是监督方式。这样就不会被大量类名和论文缩写打断。
