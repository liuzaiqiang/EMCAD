# 不确定性加权多尺度深监督

## 目标与监督策略

用户当前基线采用 `mutation`。它本身就是深监督：对四个输出 `[p4,p3,p2,p1]` 的所有非空子集计算损失，共 15 项。代码参数 `deep_supervision` 特指只有四个单头损失，并不是深监督的统称。此前将新模块限制在该四项模式的实现不符合用户基线，已经修正，不能为了新模块要求切换监督策略。

核心开关为 `USE_UNCERTAINTY_WEIGHTED_DS=0/1`，默认 `0`。关闭保持现有损失；开启只调整损失权重，保留组合内 logits 相加、全部监督项、基础损失和推理逻辑。Synapse/ACDC 支持 `mutation` 和 `deep_supervision`；其他十个二分类数据集还支持原有 `paper` 五项模式。`last_layer` 不支持多尺度权重。各脚本的原默认监督策略不变；当前实验明确传入 `SUPERVISION=mutation`。

## 核心机制

仅由训练 batch 的预测 logits 和本轮训练累计的熵 EMA 决定权重，不使用验证集或测试集标签。多分类熵为 `-sum(p*log(p))/log(C)`；二分类熵为 `-[p*log(p)+(1-p)*log(1-p)]/log(2)`。对 batch 和空间位置平均得到每个输出的尺度级熵，首次直接初始化，后续用 `0.9*旧值+0.1*当前值` 平滑。

```text
s = softmax(-EMA_entropy / 0.25)
w = 4 * (0.8 * [0.25,0.25,0.25,0.25] + 0.2 * s)
group_weight(S) = sum(w[i] for i in S) / len(S)
L = sum_S(group_weight(S) * original_loss(sum(logits[i] for i in S)))
```

四个尺度权重都在 `[0.8,1.6]` 内，总和为 4。共享映射实现为 `utils/supervision_weights.py`。各组仍先等权相加 logits，再计算原损失，最终乘组权重；不对 logits 本身加权。

- `mutation`：15 个组合保留，组权重取成员尺度权重均值，总和为 15；幂集空项跳过。
- `deep_supervision`：四个单头组直接对应四个尺度权重，总和为 4。
- `paper`：四个单头组加全体组，共五项；全体组权重为四头均值 1，总和为 5。

mutation 总权重不变的原因：长度为 k 的子集中，每个尺度出现 `C(3,k-1)` 次，每次贡献 `w_i/k`；所有长度合计，每个尺度贡献系数为 `1+3/2+3/3+1/4=15/4`。因此总和是 `(15/4)*sum(w)=15`，无需改学习率或除以组合数。各组损失不一样，所以实际损失数值仍会变化，不能把总权重不变误解为总损失不变。

Synapse/ACDC 保持 `0.3*CE+0.7*Dice`；其他十个数据集保持原 structure loss（加权 BCE + 加权 IoU）。熵用 float32，在 `torch.no_grad()` 下计算，权重不反向传播；梯度仍经原损失进入模型及 CAA。不改变数据划分、增强、预处理、随机种子、学习率、验证指标或 checkpoint 选择。

生活例子：四位老师各负责一个检查角度，mutation 既检查个人意见，也检查两人、三人和四人的联合意见，共 15 组。联合意见的监督权重取参与老师可靠性的平均值，所有讨论组保留。这是置信度代理，不代表预测一定正确：低熵也可能自信地漏掉器官，平均熵可能被大量背景主导，因此效果尚未验证。

本版不包含 MC dropout、跨随机前向方差、边界标签权重或额外预热机制。80% 均匀分配限制权重塌缩，20% 用于动态分配。Polyp/ISIC 每个训练输入 rate 都更新一次 EMA；BUSI/Cell 保持已有固定输入尺度设置。EMA 不写入模型 state_dict，未新增断点恢复 EMA 的支持。

## 当前 mutation 基线的配对运行

在服务器项目根目录运行，两组保持 `SUPERVISION=mutation`，只切换新开关：

```bash
# A：原有 CAA + mutation
SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=0 bash sh/run_seed_queue.sh synapse 2222 3333 8899
# B：CAA + mutation + 不确定性加权
SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=1 bash sh/run_seed_queue.sh synapse 2222 3333 8899
```

后台运行 B，保留控制台日志：

```bash
mkdir -p logs
nohup env SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=1 \
  bash sh/run_seed_queue.sh synapse 2222 3333 8899 \
  > logs/synapse_queue_console.log 2>&1 < /dev/null &
QUEUE_PID=$!
echo "$QUEUE_PID" > logs/synapse_seed_queue.pid
```

其余数据集使用相同开关与监督策略，更换启动器及 `DATASET_NAME`：

```bash
SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=1 bash sh/start_train_acdc.sh
DATASET_NAME=Kvasir SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=1 bash sh/start_train_polyp.sh
SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=1 bash sh/start_train_busi.sh
DATASET_NAME=ISIC2017 SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=1 bash sh/start_train_isic.sh
DATASET_NAME=EM SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_UNCERTAINTY_WEIGHTED_DS=1 bash sh/start_train_cell.sh
```

两组并行使用不同 GPU 并保持原 batch 设置；否则顺序运行。日志核对监督策略、CAA 和加权开关的实际值。模型和队列各有独立日志，启动错误也应保留日志。
