# 重新生成 SMTP 授权码后旧码仍能发邮件的原因

当前 Python 脚本使用的是 QQ 邮箱 SMTP（`smtp.qq.com:465`）。如果重新生成授权码后，旧授权码从一个全新的 Python 进程中仍然能够成功登录并发送邮件，说明 QQ 服务器目前仍接受这个旧凭据，不能简单解释为“缓存”。

## 可能原因

### 1. 生成新码不等于撤销旧码

有些邮箱的“生成授权码”是新增或刷新客户端凭据，不一定自动撤销此前生成的全部凭据。Gmail 的“应用专用密码”通常可以同时存在多个；其他邮箱的页面也可能把生成、查看、刷新和撤销设计成不同操作。

### 2. 测试的并非真正旧码

常见情况包括：

- 编辑器没有保存文件，Python 仍读取旧文件或另一个副本；
- Shell 中运行的不是预期的脚本路径；
- 授权码复制时混入空格、换行或复制了新码；
- 环境变量、配置文件或其他脚本覆盖了文件中的值；
- 测试的是已经登录成功后保持的进程，而不是新建 SMTP 连接。

### 3. 已建立的 SMTP 会话不会因后台重新生成而自动退出

SMTP 登录发生在连接建立时。邮箱后台生成新码，通常不会自动踢出已经认证成功的连接。当前 `sendEmail.py` 每次运行都会新建连接，因此只要彻底退出旧进程，再启动一次，才能验证旧码是否仍然有效。

### 4. 邮箱可能同时支持其他认证凭据

某些账户可能存在客户端专用密码、第三方客户端密码或设备授权。页面显示的“重新生成”未必撤销所有历史凭据。

## 可信验证方法

### 1. 确认脚本和密码来源

在运行脚本的同一目录执行：

```bash
pwd
readlink -f sendEmail.py
grep -n "SMTP_USER\|SMTP_PASSWORD" sendEmail.py
```

不要把最后一条命令的输出发到聊天、日志或群组，因为它会显示敏感凭据。

### 2. 确认没有旧 Python 进程

```bash
ps -ef | grep -E 'sendEmail.py|python' | grep -v grep
```

如果发现旧的发送进程，先结束它，再重新执行脚本。不要只重复点击运行按钮而不确认进程状态。

### 3. 用旧码做一次全新连接测试

将旧码临时放入一个只读测试副本，运行一次后立刻删除该副本。更安全的做法是让程序从环境变量读取密码，并且不要打印密码：

```bash
SMTP_PASSWORD='旧授权码' python -c 'import os, smtplib, ssl; s=smtplib.SMTP_SSL("smtp.qq.com",465,context=ssl.create_default_context(),timeout=20); s.login("你的QQ邮箱@qq.com",os.environ["SMTP_PASSWORD"]); print("old code accepted"); s.quit()'
```

这条命令使用全新的 SMTP_SSL 连接；如果它成功，说明服务器确实接受旧码，而不是复用了旧连接。

### 4. 测试新码

将环境变量值替换成新码，再执行同一条命令。记录两次结果，不要记录授权码本身。

## 彻底撤销旧凭据

在 QQ 邮箱网页版进入：

```text
设置 → 账户 → POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务
```

检查是否有以下按钮或入口：

- 撤销授权码；
- 删除客户端授权；
- 关闭 SMTP 服务；
- 关闭全部第三方客户端授权；
- 重新验证后生成新的授权码。

如果页面没有单独撤销旧码的选项，最稳妥的顺序是：

1. 关闭 SMTP/第三方客户端服务；
2. 保存并退出邮箱设置；
3. 修改邮箱登录密码，并完成安全验证；
4. 再次确认旧码不能登录；
5. 重新开启 SMTP 服务；
6. 生成新的授权码；
7. 只把新码配置到本地脚本或环境变量中。

具体撤销行为由邮箱服务商账户系统决定。如果关闭服务和修改密码后旧码仍能登录，应联系 QQ 邮箱官方客服确认该账户是否存在多个并行客户端凭据。

## 安全提醒

- 授权码一旦出现在聊天、截图、Git 历史或公开仓库中，应立即撤销并重新生成。
- 不要用 `grep`、`cat` 或调试日志把完整授权码输出到共享终端。
- 建议把 Python 脚本改成从环境变量读取 `SMTP_PASSWORD`，避免把密码写入源文件。
- “邮件发送成功”只说明 SMTP 服务器接受了投递请求，不代表邮件一定已到达收件箱；还要检查垃圾邮件、退信和投递状态。
