# CT、MRI、X 光：医院源头拍出来的数据到底是几维

## 先给结论

不能只按设备名称简单回答“几维”，要区分：

1. 设备采集的是单张图、连续切片还是随时间变化的序列；
2. 医院工作站重建后保存的是什么；
3. 送入深度学习模型前又被整理成了什么形状。

常见情况如下：

| 检查 | 最常见的数据形式 | 通常理解 |
|---|---|---|
| CT | 一组有顺序的二维切片 | 三维体数据 `[H,W,D]` |
| MRI | 一组二维切片或直接采集的三维体 | 三维体数据，也可能带时间/序列维 |
| X 光 | 单张二维投影图 | 二维数据 `[H,W]` |
| 连续 X 光/透视 | 多张二维图像随时间变化 | 三维数组 `[T,H,W]`，但不是空间三维 |
| 4D CT/MRI | 三维体随时间变化 | 四维数据 `[T,D,H,W]` |

最容易记住的版本是：

```text
单张 CT/MRI 切片：二维
一组有空间顺序的 CT/MRI 切片：三维
单张 X 光：二维
连续拍摄或动态序列：在原有维度上再加时间轴
```

## 一、二维、三维、四维分别是什么意思

### 1. 二维数据

二维数据只有两个空间方向：

```text
[H, W]
```

例如一张 X 光胸片，或者 CT 中的一张横断面切片：

```text
高度 H × 宽度 W
```

每个像素通常对应一个灰度或强度值。

### 2. 三维数据

三维数据有三个空间方向：

```text
[D, H, W]
```

其中：

- `H`：切片高度；
- `W`：切片宽度；
- `D`：切片数量或深度方向。

CT 的一组连续切片就是最典型的三维体数据。每张切片是二维的，但把它们按实际扫描顺序堆起来，就形成一个三维人体体积。

### 3. 四维数据

四维通常是在三维空间之外增加时间或动态相位：

```text
[T, D, H, W]
```

例如：

- 心脏动态 CT；
- 心脏电影 MRI；
- 呼吸相位 CT；
- 灌注 CT/MRI；
- 连续 X 光序列。

四维中的第 4 个维度通常是时间，不一定是第 4 个空间方向。

## 二、CT 源头数据通常是什么维度

### 1. CT 扫描器不是直接只拍一张图

CT 通过 X 射线管和探测器绕人体旋转，采集大量投影数据。设备软件经过重建后，生成一系列横断面图像。

医院通常把这些图像作为一个 DICOM 序列保存：

```text
一张 DICOM = 一张二维 CT 切片
很多张有顺序的 DICOM = 一个三维 CT 体
```

因此：

```text
单个 CT DICOM 文件：通常二维图像
同一检查的一组 CT DICOM：三维体数据
```

### 2. CT 的数组形式

转换成 NumPy 或 NIfTI 后，常见形状是：

```python
[D, H, W]
```

例如：

```text
[300, 512, 512]
```

表示这个病例大约有 300 张切片，每张切片为 512×512。

当前 EMCAD 的 Synapse 测试正是这种情况：H5 中保存完整病例，读取后通常是：

```text
image: [D, H, W]
label: [D, H, W]
```

但 EMCAD 当前网络是二维网络，所以测试时把三维体拆成 `D` 张二维切片逐张推理，再拼回三维结果。

### 3. CT 为什么必须关注 spacing

CT 的三个方向间距可能不同：

```text
x spacing：像素在左右方向的实际长度
y spacing：像素在前后方向的实际长度
z spacing：相邻切片之间的层间距
```

例如：

```text
数组 shape = [300, 512, 512]
spacing    = (0.8, 0.8, 5.0) mm
```

虽然数组是三维，但 z 方向的 5 mm 比面内 0.8 mm 粗很多。这会影响三维重建、器官体积和 HD95/ASD 等物理距离指标。

## 三、MRI 源头数据通常是什么维度

### 1. MRI 没有唯一固定维度

MRI 的维度取决于扫描序列和医院设置：

- 二维 MRI：逐层采集很多二维切片；
- 三维 MRI：一次采集体数据，再重建任意方向；
- 动态 MRI：三维或二维图像随时间变化；
- 多序列 MRI：同一病例有 T1、T2、FLAIR、DWI 等多个图像序列。

### 2. 常见 MRI 数据形状

单个三维序列：

```text
[D, H, W]
```

多模态或多序列合并后可能是：

```text
[C, D, H, W]
```

其中 `C` 不是颜色通道，而是 MRI 序列通道，例如：

```text
C=4：T1、T1ce、T2、FLAIR
```

动态 MRI 还可能是：

```text
[T, D, H, W]
```

或：

```text
[C, T, D, H, W]
```

### 3. MRI 与 CT 的主要区别

从“维度”角度看，MRI 和 CT 都可以是三维体数据；区别主要在：

- 成像物理机制不同；
- MRI 常有多个序列/模态；
- MRI 强度通常没有 CT 那样统一的 HU 物理单位；
- 不同序列可能需要配准和强度归一化。

所以不能说“CT 是三维，MRI 是二维”或反过来；二者都可能是二维、三维或四维，具体看扫描协议。

## 四、X 光源头数据通常是什么维度

### 1. 普通 X 光片是二维投影

普通胸片、骨骼片、牙片通常是：

```text
[H, W]
```

X 光从一个方向穿过人体，把三维结构压缩投影到二维探测器上。因此一张 X 光图不能直接提供完整深度信息。

例如胸片中肺、心脏、肋骨会叠加在同一二维平面上。

### 2. 连续透视是二维图像序列

如果设备连续采集，例如：

- 手术透视；
- 血管造影视频；
- 动态吞咽检查；

数据可能是：

```text
[T, H, W]
```

这里的 `T` 是时间，不是空间深度。因此它是“二维图像随时间变化”，不是普通 CT 那样的三维空间体。

### 3. X 光断层成像是例外

数字乳腺断层摄影（DBT）等技术可以从多个角度采集并重建近似三维数据。此时可以得到：

```text
[D, H, W]
```

但这不等于普通单张 X 光片。判断维度时必须知道检查类型。

## 五、医院文件格式与维度的关系

### 1. DICOM

DICOM 是医学影像文件格式和通信标准，不等于某一种固定维度。

- 一个 DICOM 文件可能是一张二维切片；
- 一个增强型 DICOM 也可能包含多帧；
- 同一检查的多个 DICOM 文件组合起来才是完整三维体。

不能看到 `.dcm` 就断言它是二维或三维，必须读取 header 和像素数组 shape。

### 2. NIfTI

NIfTI 常用于科研和深度学习：

```text
二维： [H, W]
三维： [D, H, W]
四维： [T, D, H, W] 或 [D, H, W, T]
```

不同软件的轴顺序可能不同，不能只看数字而忽略 affine、orientation 和 spacing。

### 3. PNG/JPEG

PNG/JPEG 通常只保存一张二维图像：

```text
[H, W]
```

即使它来自三维 CT，也只是从三维体中导出的单张切片或可视化图。

## 六、医院源头数据到深度学习输入的维度变化

以当前 Synapse CT 为例：

```text
医院 CT 扫描
    ↓
一组 DICOM 切片
    ↓
整理/重建为三维 NIfTI 或 H5
    ↓
保存为 [D,H,W]
    ↓
二维 EMCAD 测试时取 image[ind,:,:]
    ↓
得到 [H,W]
    ↓
增加 batch/channel 维
    ↓
送入网络 [1,1,H,W]
    ↓
逐张预测后拼回 [D,H,W]
```

因此模型输入维度不一定等于医院源头数据维度：

```text
医院原始病例：三维
二维网络单次输入：二维加 batch/channel
最终预测结果：重新拼回三维
```

## 七、判断一个文件到底几维的可靠方法

不要凭文件扩展名猜。直接读取数组 shape。

### NumPy/NPZ

```python
import numpy as np

with np.load("sample.npz") as data:
    for key in data.files:
        print(key, data[key].shape, data[key].dtype)
```

### NIfTI

```python
import nibabel as nib

nii = nib.load("sample.nii.gz")
print("shape:", nii.shape)
print("spacing:", nii.header.get_zooms())
```

### HDF5

```python
import h5py

with h5py.File("sample.npy.h5", "r") as f:
    for key in f.keys():
        print(key, f[key].shape, f[key].dtype)
```

输出的 `shape` 才是当前文件实际保存的数组维度。

## 八、最容易混淆的几个问题

### “一张 CT 图是二维还是三维？”

如果指单张切片，它是二维；如果指整个 CT 病例，它是三维。

### “DICOM 是二维还是三维？”

DICOM 是格式，不决定维度。一个文件可能是一张切片，也可能是多帧数据；一组 DICOM 通常需要合并成三维体。

### “X 光能不能做三维？”

普通单张 X 光是二维投影；CT、断层摄影或多角度重建可以得到三维信息。

### “MRI 一定是三维吗？”

不一定。很多 MRI 序列是逐层二维采集，也可以重建为三维；动态 MRI 还可能增加时间轴。

### “`[1,1,H,W]` 是不是三维？”

对二维网络来说，它是：

```text
batch=1、channel=1、空间二维 H×W
```

它有四个数组轴，但只有两个空间维度。数组维度数量和空间维度数量不是一回事。

## 最终记忆版

```text
CT：单张切片二维，一组切片三维，动态扫描可四维
MRI：可二维、三维，也可多序列或动态四维
普通 X 光：二维投影，连续拍摄是二维+时间
DICOM/NIfTI：是文件格式，不自动决定维度
判断实际维度：读取 shape，不看文件名猜
```
