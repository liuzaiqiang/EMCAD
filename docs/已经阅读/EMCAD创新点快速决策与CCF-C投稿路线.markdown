# EMCAD 创新点快速决策与 CCF-C 投稿路线

## 先说最重要的结论

你现在不要再要求自己“一次想出两个创新点”。对于基于已有模型的 CCF-C 小论文，最现实的目标是：

> 找到一个具体失败现象，提出一个只解决这个现象的机制，用严格消融证明它确实有效。

创新点不是凭空命名一个模块，而是下面这条链：

```text
EMCAD 的具体失败
    -> 一个明确假设
    -> 一个最小代码改动
    -> 一个对应消融
    -> 一个可重复的指标提升
```

如果这条链断了，模块名字再漂亮也不构成论文贡献。

## 一、不要从“我还能加什么模块”开始

错误问题：

```text
我能不能加注意力？
我能不能加 Transformer？
我能不能加边界损失？
我能不能加一个动态卷积？
```

这些问题会让你不断堆模块，却不知道为什么有效。

正确问题只有一个：

> 当前 EMCAD 在什么地方、对什么类型的器官、以什么方式失败？

然后才问：

> 哪个最小机制能直接改变这个失败？

## 二、当前 EMCAD 最容易形成论文的四个“代码槽位”

### 槽位 A：多尺度分支固定相加

当前 `lib/decoders.py` 的 MSCB/MSDC 使用多个深度卷积分支，再通过固定求和或 concat 合并。它默认所有空间位置都使用同一套尺度融合方式。

可形成的问题：

```text
器官内部需要较大上下文，边界和小器官需要更细局部信息；固定求和不能按位置选择尺度。
```

最适合的单一机制：

```text
用当前层预测熵和相邻解码层 JS 分歧生成 uncertainty map，
再按位置预测 1/3/5 分支权重。
```

当前仓库已经有参考实现：

```text
DG_EMCAD_reference/lib/dg_emcad.py
```

优先级：最高。原因是代码已经有 `equal/global/feature/disagreement` 四种模式，消融自然，改动边界清晰。

### 槽位 B：浅层 skip 把边缘和噪声一起带回解码器

当前 EMCAD 使用 LGAG 对 skip 做门控，但它本质上仍是一张单通道空间门控图。小器官边界可能被过度抑制，复杂纹理也可能被带入。

可形成的问题：

```text
空间门控只回答“这个位置要不要”，没有回答“哪些通道和哪些边界方向要保留”。
```

最小候选：

```text
在 LGAG 输出后增加一个轻量的通道-边界联合门控，
只在最高分辨率 skip 上使用，其他层保持不变。
```

优先级：中等。风险是容易变成常见的 CBAM/边界注意力拼接，原创性和增益都不稳定。

### 槽位 C：小器官类别在总 loss 中被大器官掩盖

当前 Synapse 是 9 类分割，训练 loss 对类别做平均。大器官像素多、梯度稳定，小器官和细长结构可能被优化目标掩盖。

可形成的问题：

```text
总体 Dice 不差，但 pancreas、gallbladder 等小器官 Dice 和 HD95 明显落后。
```

最小候选：

```text
根据训练集类别体积统计构造固定 class-aware Dice 权重，
权重只由训练集统计得到，不能使用验证/测试标签调权。
```

优先级：中等偏低。实现快，但 loss 改动类论文较多，需要跨数据集验证，否则容易被认为只是调权重。

### 槽位 D：同一个模型在不同计算预算下没有明确取舍

当前 EMCAD 的 kernel size、expansion factor、并行/串行模式会改变参数量和计算量，但代码没有形成“精度-效率”统一实验。

可形成的问题：

```text
医学分割模型不仅要提高 Dice，还要在显存、FLOPs 和推理时间上可部署。
```

最小候选：

```text
在分歧路由基础上加入 FLOPs budget 或稀疏路由，
让模型在困难区域使用大尺度、简单区域使用小尺度。
```

优先级：中等。结果如果只有“略慢但略好”，论文说服力不够；如果能在相近 FLOPs 下提高 Dice，价值会明显增加。

## 三、给你一个明确的优先顺序

### 第一选择：分歧引导自适应尺度路由

只做这一件事：

```text
固定多尺度融合 -> 位置自适应的分歧引导多尺度融合
```

核心实验：

```text
E0: 原始 EMCAD
E1: equal router
E2: global router
E3: feature router
E4: disagreement router
```

E1 是公平性检查；E2/E3 是必要消融；E4 才是候选方法。

### 第二选择：只做小器官/边界导向的轻量改动

只有当 E4 彻底无效，才考虑这个备选。不要同时保留两个主创新。

### 第三选择：效率论文

只有在你的显卡资源有限、能够稳定测量 Params/FLOPs/显存/推理速度，并且能做到“相近精度下明显更省”时才选择。仅仅报告多个 kernel size 的表格不够。

## 四、今天如何“想出”候选，而不是空想

### 第一步：先跑一个可靠 baseline

冻结：

- 代码 commit；
- train/validation/test 病例清单；
- `img_size`；
- `batch_size`；
- `base_lr`；
- supervision；
- 预训练权重；
- seed；
- 指标实现。

没有 baseline，就没有“提升”；只有一个最高分。

### 第二步：把 baseline 的失败拆成三类

你只需要看三张表：

1. 每个器官 Dice；
2. 每个器官 HD95/ASSD；
3. 每个病例的结果和可视化。

按现象归类：

| 现象 | 优先假设 | 对应代码槽位 |
|---|---|---|
| 小器官 Dice 低、边界断裂 | 固定尺度不适合细节 | 槽位 A |
| 器官边界毛刺、假阳性多 | skip 噪声或门控不足 | 槽位 B |
| 总体 Dice 尚可但小器官落后 | 类别梯度失衡 | 槽位 C |
| 精度提升伴随显存/时间暴涨 | 计算分配不合理 | 槽位 D |

### 第三步：只写一个可证伪假设

例如：

```text
H1：解码层的尺度间预测分歧在器官边界和小器官区域更高；
用该分歧引导尺度权重，可以比固定求和减少边界错误。
```

这个假设可以被反驳。如果分歧图与困难区域没有关系，或路由后 Dice/HD95 没改善，就停止。

### 第四步：给假设配一个最小消融

对于 H1，最小消融不是“再加一个边界 loss”，而是：

```text
固定相加 vs 全局权重 vs feature-only 权重 vs feature+disagreement 权重
```

如果 `feature+disagreement` 没有优于 `feature-only`，就不能把分歧写成有效贡献。

## 五、如何判断一个点够不够 CCF-C

不要用“听起来新不新”判断，使用下面五个问题：

1. 它是否解决了 EMCAD 的一个具体失败，而不是泛泛说“提升特征表达能力”？
2. 是否可以只改一个主要模块，其他训练设置保持不变？
3. 是否有一个强对照能证明提升来自该机制，而不是参数变多？
4. 是否能在第二个数据集上至少不崩溃？
5. 是否能报告逐类别、边界和效率结果，而不是只报一个 Dice？

五个问题有两个以上答不上来，就不要继续实现。

## 六、必须设置的止损线

每个候选最多经历三轮判断：

### 第一轮：实现和 shape 检查

- forward 能运行；
- backward 后新增模块梯度非零；
- `equal` 模式与原始固定融合接近；
- Params/FLOPs 增量符合预期。

### 第二轮：单 seed 完整开发实验

核心方法必须至少满足：

- 验证 Dice 相对 baseline 提升约 `0.3` 个百分点或更多；
- HD95/ASSD 至少一项同步改善；
- 不是只改善一个偶然病例；
- 没有测试集参与选模。

### 第三轮：多 seed/第二数据集

- 三个 seed 的平均方向为正；
- 第二个数据集没有明显退化；
- 参数量和时间增加可以解释；
- 消融结论与主结果一致。

第二轮不通过，就不要进入第三轮；第三轮不通过，就不要继续加模块。

## 七、论文不要写成“模块大杂烩”

建议论文结构：

```text
1 Introduction
  EMCAD 固定多尺度融合的具体问题
  本文的一个假设和一个方法

2 Related Work
  医学图像多尺度解码
  不确定性/分歧建模

3 Method
  原始 EMCAD
  uncertainty proxy
  disagreement-guided router
  复杂度分析

4 Experiments
  数据和病例级划分
  实现细节
  主结果
  E0-E4 消融
  逐器官和边界分析
  Params/FLOPs/时间/显存
  失败案例

5 Limitations
  计算代价、分歧 proxy 的局限、跨域泛化
```

贡献点最多写三条，但最好本质上是一个方法贡献加两个证据贡献：

```text
1. 提出一个分歧引导的自适应多尺度 EMCAD 解码机制。
2. 通过等权、全局权重和 feature-only 路由验证分歧信号的独立作用。
3. 在两个数据集上从区域、边界和计算成本三个方面进行评估。
```

不要把“重新实现训练脚本”“增加日志”“修复 resume”“统一指标”写成模型创新。它们是实验基础设施，必须做，但不应冒充贡献。

## 八、你现在最应该执行的命令级任务

### 任务 1：确认当前入口没有假生效参数

检查：

```bash
python train_synapse.py --help
```

如果没有显示：

```text
--adaptive_msdc
--dg_router_mode
```

就不要直接运行当前 shell 并把它称为自适应模型。

### 任务 2：做一次原始 EMCAD 记录

保存：

```text
baseline command
commit
seed
dataset split
best epoch
mean Dice
per-organ Dice
HD95
ASSD
Params
FLOPs/MACs
train time
test time
peak VRAM
```

### 任务 3：只跑五组路由消融

不要一开始跑 30 组组合。先跑 E0—E4；任何一组改变多个变量都作废。

### 任务 4：根据结果决定是否写论文

```text
E4 稳定优于 E0/E1 -> 继续第二数据集和多 seed
E4 只在单 seed 有效 -> 先修协议，不写结论
E4 与 E3 持平 -> 分歧信号不是独立贡献
E4 不如 E0 -> 放弃该方向，不再堆模块
```

## 九、现实的 CCF-C 目标管理

你可以把目标拆成三个层次：

### 必须达到

- 方法逻辑完整；
- baseline 和消融可信；
- 至少两个数据集或一个数据集加充分跨设置分析；
- 指标和代码可复现；
- 没有数据泄漏。

### 最好达到

- Dice 和 HD95 同时改善；
- 小器官或边界有明显收益；
- 参数/FLOPs 增长小；
- 三个 seed 均值稳定。

### 不要幻想必须达到

- 一定超过所有公开 SOTA；
- 一定达到某个固定 Dice 数字；
- 一定一次投稿录用；
- 一定靠一个小模块获得 CCF-C。

CCF-C 是投稿与评审结果，不是代码运行后自动产生的标签。你能控制的是问题是否具体、实验是否公平、证据是否完整。

## 十、最后给你的直接建议

现在停止“继续想新模块”。按下面顺序做：

1. 先把原始 EMCAD baseline 跑完整并记录；
2. 把 `DG_EMCAD_reference` 的 disagreement router 真正接入当前训练入口；
3. 只跑 `equal/global/feature/disagreement` 四种对照；
4. 只要 disagreement 没有稳定提升，就放弃它；
5. 如果有效，围绕一个方法写完两数据集、逐器官、边界和效率实验；
6. 用结果去匹配具体 CCF-C 投稿目标，而不是先假设一定能中。

你现在缺的不是“灵感”，而是一个能在三天内被证伪的候选和一套不允许自欺的实验门槛。
