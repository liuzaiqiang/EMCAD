# EMCAD 基础模型：读到什么程度就可以开始验证创新点

> 这份文档解决一个非常实际的问题：面对一个已经能运行的基础模型，研究者到底要先读懂多少代码，才可以开始验证一个 AI 提出的候选改进？
>
> 结论先写在前面：**不需要吃透整个 EMCAD，更不需要逐行读完 PVTv2、所有工具函数和每个初始化细节。你只需要达到“最小充分理解”——能够准确画出一次前向和训练闭环，知道候选改动插在哪里、输入输出形状是什么、如何公平比较、如何判断失败。达到这个阈值就应该开始实验。**

---

## 1. 你现在真正陷入的循环是什么

很多研究生在读基础模型时会经历下面的循环：

```text
想提出创新
  -> 发现一个没读懂的类
  -> 去读这个类
  -> 又遇到一个没读懂的函数
  -> 继续向下读
  -> 读完仍然不知道创新应该改哪里
  -> 回到“先把项目吃透”
```

这个循环没有自然终点，因为一个深度学习项目通常同时包含：

- 模型结构；
- 数据预处理；
- 数据集类；
- 损失函数；
- 训练循环；
- 验证和测试；
- 日志；
- checkpoint；
- 参数统计；
- 可视化；
- 兼容旧实验的历史代码；
- 与当前任务无关的其他数据集代码。

如果目标是“完全理解一切”，你很可能在真正做实验之前耗掉数周甚至数月。科研更合理的策略是把理解分成层次：

1. 先理解足以安全运行和解释一次实验的部分；
2. 开始验证一个清晰的候选假设；
3. 根据候选涉及的代码路径，再深入阅读相关模块；
4. 最后为了论文、消融和答辩，补齐更深层的理论和实现细节。

这不是偷懒，而是把阅读变成**问题驱动阅读**。

## 2. “看到什么程度”才可以开跑：三个门槛

不要用“我是否已经完全看懂”作为开跑标准。请使用下面三个门槛。

### 2.1 门槛 A：能跑（Engineering-Ready）

达到这个门槛，说明你知道怎样把项目启动起来，但还不一定能科学解释结果。你至少知道：

- 训练入口是什么；
- 数据路径在哪里；
- 使用哪个模型和 backbone；
- checkpoint 保存在哪里；
- 输出日志在哪里；
- GPU 和 Python 环境是否正常。

门槛 A 只能保证“程序可能运行”，不能保证“实验值得相信”。

### 2.2 门槛 B：能验证（Research-Experiment-Ready）

这是你现在应该追求的最低目标。达到门槛 B，就可以开始验证 AI 提出的候选创新点。你需要能回答：

1. 输入张量是什么形状、什么语义？
2. 输出张量是什么形状、什么语义？
3. 哪个模块是候选改动的插入位置？
4. 损失如何从输出传回模型？
5. checkpoint 依据什么指标选择？
6. 验证集和最终测试集是否分开？
7. baseline 和候选是否只改变一个核心变量？
8. 一次实验失败时，如何判断是代码错误、资源问题还是科学假设失败？
9. 结果用什么单位、什么 seed、什么病例列表计算？
10. 你能否把一次实验完整复现，而不是只记得一个 Dice 数字？

**门槛 B 达到后就可以开跑，不必等待门槛 C。**

### 2.3 门槛 C：能写论文（Publication-Ready）

这是后续目标，不能作为开始实验的前置条件。它还要求：

- 对候选机制有理论解释；
- 能说明与相近论文的差异；
- 有完整消融和参数匹配对照；
- 有多 seed、逐器官、逐病例、HD95 等结果；
- 能解释失败案例和局限；
- 能复现并回答审稿人的实现问题。

很多人把门槛 C 错当成开跑条件，于是一直读代码却没有实验数据。正确顺序是：

```text
先达到 B -> 开始小规模验证 -> 用实验问题推动深入阅读 -> 逐渐达到 C
```

## 3. EMCAD 的“最小充分理解”到底是什么

对当前 EMCAD 项目，达到门槛 B 只需要掌握五个契约：

### 契约 1：输入契约

Synapse 训练时，模型接收二维切片，典型形状是：

```text
image_batch: [B, 1, H, W]
label_batch: [B, H, W]
```

其中：

- `B` 是 batch size；
- `1` 是 CT 灰度通道；
- `H、W` 是输入尺寸，例如 224 或 256；
- label 中的整数通常是 `0..8`，0 为背景，1..8 为 8 个器官。

`lib/networks.py` 的 `EMCADNet.forward()` 会在输入通道为 1 时用一个可学习的 `1x1` 卷积变成 3 通道，再送入 ImageNet 风格的 backbone。你只需理解这个适配的目的和形状变化，不必此刻读完 `1x1` 卷积的底层实现。

### 契约 2：编码器输出契约

以默认 PVTv2-B2、224 x 224 为例，backbone 返回四级特征：

```text
x1: [B,  64, 56, 56]   # 最浅，空间细节多
x2: [B, 128, 28, 28]
x3: [B, 320, 14, 14]
x4: [B, 512,  7,  7]   # 最深，语义信息强
```

`lib/networks.py:237` 用：

```python
x1, x2, x3, x4 = self.backbone(x)
```

你必须知道：

- `x4` 是解码器主干起点；
- `x3、x2、x1` 是 skip connection；
- 深层特征通常语义强但分辨率低；
- 浅层特征通常边界细节多但背景噪声也多；
- 解码器要求通道数和空间尺寸对齐。

你暂时不必知道 PVT 每一个 attention head、patch embedding 和每一层权重初始化的细节。除非候选创新明确改 PVT 编码器，否则这些内容不是当前实验的阻塞项。

### 契约 3：解码器输出契约

`lib/decoders.py:884` 的 `EMCAD` 负责从最深层逐级恢复空间分辨率。主路径可以压缩成：

```text
x4
  -> CAB -> SAB -> MSCB -> d4
  -> EUCB 上采样/变换通道
  -> LGAG 门控 x3
  -> 与 d3 相加
  -> CAB -> SAB -> MSCB -> d3
  -> EUCB 上采样/变换通道
  -> LGAG 门控 x2
  -> 与 d2 相加
  -> CAB -> SAB -> MSCB -> d2
  -> EUCB 上采样/变换通道
  -> LGAG 门控 x1
  -> 与 d1 相加
  -> CAB -> SAB -> MSCB -> d1
```

在默认 PVTv2-B2 下，解码器内部特征大致是：

```text
d4: [B, 512,  7,  7]
d3: [B, 320, 14, 14]
d2: [B, 128, 28, 28]
d1: [B,  64, 56, 56]
```

这里有一个非常重要的阅读结论：

> **EMCAD 的真正研究接口主要在 `lib/decoders.py` 的四级解码路径，而不是整个项目的每个文件。**

如果 AI 提出的候选是“改善 skip 中的背景噪声”，你重点读 `LGAG` 及其调用位置；如果候选是“改善尺度建模”，你重点读 `MSCB/MSDC`；如果候选是“改善通道或空间选择”，你重点读 `CAB/SAB`。不需要先把所有模块都读成同样深度。

### 契约 4：分割头和输出契约

`lib/networks.py:211-217` 为四级解码特征各自建立一个 `1x1` 输出头：

```text
d4 -> p4: [B, 9, H/32, W/32] -> 放大到 [B, 9, H, W]
d3 -> p3: [B, 9, H/16, W/16] -> 放大到 [B, 9, H, W]
d2 -> p2: [B, 9, H/8,  W/8 ] -> 放大到 [B, 9, H, W]
d1 -> p1: [B, 9, H/4,  W/4 ] -> 放大到 [B, 9, H, W]
```

`EMCADNet.forward()` 最终返回：

```python
[p4, p3, p2, p1]
```

每个元素都是 9 通道的**原始 logits**，不是已经 softmax 的概率，也不是类别索引图。测试路径通常取列表最后一个 `p1` 作为最高分辨率输出。

你必须知道：

- 训练时不要在模型内部提前 `argmax`；
- `CrossEntropyLoss` 接收 logits 和整数 label；
- Dice loss 在连续概率上计算，通常先 softmax，再与 one-hot label 比较；
- 推理时才把概率 `argmax` 成类别索引图。

### 契约 5：训练、验证和指标契约

`trainer.py` 的核心训练逻辑是：

```text
读入切片
  -> model(image_batch)
  -> 得到 4 个 logits
  -> 按 supervision 规则组合输出
  -> 0.3 * Cross-Entropy + 0.7 * Dice
  -> loss.backward()
  -> AdamW.step()
```

当前代码中：

- `trainer.py:151` 使用 AdamW；
- `trainer.py:206-226` 使用 0.3 CE + 0.7 Dice；
- 默认 `mutation` supervision 会对 4 个输出的非空组合累计损失，实际有 15 个组合；
- 因此 mutation 的 loss 数值尺度不能直接与只监督最后一层的 loss 横向比较；
- 验证采用完整病例，逐切片推理后恢复到体数据，再按前景器官计算 Dice；
- 当前验证 Dice 是 0 到 1 的小数，例如 `0.8363`，论文表格通常写成 `83.63%`。

你至少要确认：

1. 当前 `test_vol` 代表开发验证集还是最终测试集；
2. `best.pth` 是依据哪一个集合选择的；
3. Dice 的单位和空类别规则；
4. 训练与验证是否使用同一评价实现；
5. 候选实验是否使用同一个病例级 split 和同一组 seed。

## 4. EMCAD 中哪些代码必须读，哪些代码可以后置

下面这张表是你真正需要的阅读边界。

| 文件/位置 | 现在必须读到什么程度 | 现在可以暂时跳过什么 |
|---|---|---|
| `train_synapse.py` | 参数来源、数据路径、模型构造、实验目录、seed、输入尺寸、batch size、监督方式 | argparse 的每个通用写法、历史注释 |
| `trainer.py` | DataLoader、前向调用、loss 组合、反向、验证调用、checkpoint、train/eval 状态 | TensorBoard 细枝末节、旧的未启用学习率代码 |
| `lib/networks.py` | 1->3 通道适配、backbone 返回四级特征、channels 列表、decoder 调用、四个输出头、输出顺序 | PVT 每层内部实现、所有预训练过滤细节 |
| `lib/decoders.py` 的 `EMCAD.forward` | d4->d3->d2->d1 的顺序、skip 对齐、LGAG、CAB/SAB/MSCB/EUCB 的位置和输入输出形状 | 暂时未涉及候选的模块内部初始化 |
| `lib/decoders.py` 的候选模块 | 候选涉及哪个模块，就读该模块的完整 forward 和参数形状 | 与候选无关的其他模块 |
| `utils/dataset_synapse.py` | train 读取 `.npz` 切片，非 train 读取 `.npy.h5` 病例，列表文件如何决定样本 | 不相关数据集分支 |
| `utils/utils.py` | `DiceLoss`、`val_single_volume`、指标空类别规则、argmax/resize 路径 | 息肉等不参与当前 Synapse 实验的工具 |
| `test_synapse.py` | checkpoint 加载、最终输出选择、测试指标汇总 | 与当前实验无关的兼容参数 |
| `lib/pvtv2.py` | 只需确认输出四级特征和通道数 | 具体 Transformer block，除非候选改 encoder |
| 其他旧脚本 | 只在当前命令实际调用它时阅读 | 不要为了“项目完整”全部通读 |

一句话概括：

> **先读调用链和张量契约，再按候选改动定向深入；不要按文件夹从上到下阅读。**

## 5. 达到实验就绪的 12 项检查表

下面 12 项全部能用自己的话回答，就可以开始验证候选创新。不是要求你能背代码，而是要求你能解释“发生了什么”。

### 模型与张量

- [ ] 我能说出输入是 `[B,1,H,W]`，label 是 `[B,H,W]`，9 类中包含背景。
- [ ] 我能说出 PVTv2-B2 的四级特征顺序是 `x1,x2,x3,x4`，以及大致通道和空间尺寸。
- [ ] 我知道 decoder 接收 `x4` 和 `[x3,x2,x1]`，顺序不能随意调换。
- [ ] 我知道 EMCAD 返回 `[p4,p3,p2,p1]`，每个是 9 通道 logits。
- [ ] 我知道当前最终预测通常使用列表最后的 `p1`，而不是直接使用 `d1`。

### 训练与评价

- [ ] 我能画出 `forward -> loss -> backward -> optimizer.step` 的链路。
- [ ] 我知道 CE、Dice、softmax、argmax 分别在哪个阶段出现。
- [ ] 我知道当前 supervision 是 mutation、deep supervision 还是 last layer，以及它会影响多少个输出。
- [ ] 我知道 checkpoint 依据什么 Dice、在哪个 split 上选择。
- [ ] 我知道训练集、开发验证集和最终测试集的病例清单，并确认没有病例级交叉。

### 实验控制

- [ ] 我能准确指出候选创新改哪个文件、哪个类/函数、哪个输入输出接口。
- [ ] 我能写出 baseline 和 candidate 两条命令，并保证除一个核心变量外一致。

如果 12 项中有 1-2 项只是“暂时不确定”，可以先做只读审计或小张量冒烟；如果以下红线项目不清楚，则不能进行完整创新实验：

- 数据划分是否泄漏；
- checkpoint 选择是否使用最终测试集；
- 输出和 loss 的形状是否匹配；
- 指标单位和计算方法；
- 候选的插入位置及输入输出形状；
- baseline 的精确 commit、命令和 seed。

## 6. 你不需要等待“完全吃透”的具体内容

以下内容很有价值，但不是开始第一个候选实验的前置条件：

### 6.1 不需要先读完 PVTv2

如果 AI 候选改的是 EMCAD decoder，你只需确认 PVT 输出四级特征的接口。你不需要先理解：

- 每个 Transformer block 的 attention 公式；
- patch embedding 的所有参数；
- PVT 预训练权重每个 key 的过滤过程；
- 每一个 stage 的内部残差路径。

只有当候选明确改变 backbone、输入 token、注意力窗口或 encoder feature fusion 时，才把 PVT 内部纳入本轮阅读范围。

### 6.2 不需要先读完所有 `utils.py`

当前 Synapse 候选首先需要知道：

- `DiceLoss` 如何把标签 one-hot；
- `val_single_volume` 如何逐切片推理；
- `calculate_dice_percase` 的空类别规则；
- resize 和 argmax 的顺序。

不参与本轮 Synapse 的息肉、皮肤、乳腺等工具代码可以后置。

### 6.3 不需要先理解每个初始化函数

只要候选不改初始化策略，你可以把初始化当成已知条件。记录“使用了什么初始化、是否加载预训练”即可。研究问题是候选机制是否有效，不是先复刻 PyTorch 的每一个 `named_apply`。

### 6.4 不需要先读完论文所有附录

开始验证前只需要掌握：

- 基线模型和数据集；
- 输入尺寸、batch size、epoch、优化器、损失；
- 评价指标和数据划分；
- 原论文已经做过哪些消融，避免把旧实验误称新颖。

更深的相关工作和附录消融可以在候选通过初筛后补读。

## 7. 当前 EMCAD 的三个“先修再跑”问题

你现在可以停止继续泛读，但不能跳过下面三个实验可信度问题。它们不是要求你把整个项目读完，而是要在真正比较创新前确认。

### 7.1 当前 `test_vol` 是否就是最终测试集

`trainer.py:53-56` 的 `inference()` 使用：

```python
Synapse_dataset(base_dir=args.volume_path, split="test_vol", ...)
```

训练循环每个 epoch 都会调用该函数，并用返回的 Dice 选择 `best.pth`。如果 `test_vol` 是最终测试病例，这会造成测试集参与模型选择。

你不需要先读完整代码，只要回答：

```text
test_vol.txt 里是什么病例？
它是不是论文最终测试集？
开发验证病例在哪里？
```

如果没有独立验证集，先修数据和训练入口，再谈创新效果。

### 7.2 验证后是否恢复 `model.train()`

当前 `inference()` 调用 `model.eval()`。训练函数只在 epoch 循环前调用一次 `model.train()`。如果下一 epoch 开始前没有再次调用，后续训练可能继续处于 eval 模式，影响 BatchNorm 和 Dropout 行为。

这是一个很小但很重要的阅读结论：你不必读懂整个 trainer，只需追踪模式切换即可。

### 7.3 checkpoint 是否真正支持 resume

当前保存逻辑主要是：

```python
torch.save(model.state_dict(), save_mode_path)
```

这不包含 optimizer、epoch、best metric 和随机数状态。你可以先做“权重加载推理”，但不能把它叫作完整断点续训。自动创新循环开始前，至少要区分：

- 从权重开始一个新训练；
- 从完整 optimizer/RNG 状态恢复原训练轨迹。

如果当前任务只做一次性完整训练，可以暂时不把 resume 作为候选创新；但服务器自动运行和中断恢复时必须补齐。

## 8. AI 给出的创新点，达到什么标准才值得你去跑

AI 生成的文字不是论文结论，只是一个候选假设。你不需要先证明它一定有效，但必须要求它在实验前说清楚下面 8 件事。

### 8.1 它针对什么具体问题

不能只说：

```text
加入一个新的注意力模块，可以提升特征表达能力。
```

至少要说成：

```text
浅层 skip 含有较多边界细节，但也带入背景噪声；候选机制试图利用解码器语义门控对浅层 skip 做位置可靠性筛选。
```

这是“问题假设”，不是已经证明的事实。最好有失败病例、逐器官结果、边界可视化或特征统计支持。

### 8.2 它改 EMCAD 的哪个真实接口

候选必须给出类似这样的定位：

```text
文件：lib/decoders.py
类：LGAG 或 EMCAD
函数：forward
位置：x3 = self.lgag3(g=d3, x=skips[0]) 之后、d3 = d3 + x3 之前
```

如果 AI 只说“在 decoder 中加入模块”，还没有达到可实验程度。

### 8.3 它的输入输出形状是什么

例如：

```text
输入 skip x3: [B,320,14,14]
输入 gate d3: [B,320,14,14]
候选输出 gated_x3: [B,320,14,14]
后续融合: d3 + gated_x3
```

只要形状没有说清楚，就容易出现：

- 通道不匹配；
- 空间尺寸不匹配；
- concat 后通道翻倍但后续卷积仍按原通道构造；
- 在错误的分辨率上计算昂贵模块。

### 8.4 它只改变一个核心变量吗

一次实验可以涉及多个文件，但科研变量应只有一个。例如：

```text
允许：在 LGAG 输出后增加一个边界可靠性重标定分支，并配套新增单元测试。
不允许：同时换 backbone、输入尺寸、loss、增强、优化器和 decoder，再称为一个创新点。
```

### 8.5 它怎样与 baseline 公平比较

候选说明必须写出：

- 同一 commit 起点；
- 同一数据清单；
- 同一预训练权重；
- 同一输入尺寸；
- 同一 batch size；
- 同一 epoch；
- 同一 optimizer 和 loss；
- 同一评价代码；
- 同一 seed 集合；
- 只有候选机制不同。

### 8.6 它如何被证伪

一个好的候选不只告诉你“怎样可能变好”，还要告诉你什么结果会否定它。例如：

```text
若两个预注册 seed 的验证 Dice 都没有提升，且边界指标没有改善，则该假设暂不支持；
若 Dice 提升但 HD95 明显恶化，则不能直接判定为成功；
若提升只发生在一个器官或一个 seed，需要追加分析而不能直接宣布有效。
```

### 8.7 它有没有重复 EMCAD 原论文的已知消融

EMCAD 原论文已经研究过：

- decoder 组件组合；
- 多尺度 kernel 组合；
- depth-wise convolution 的串行/并行；
- LGAG 与传统 AG；
- 预训练；
- deep supervision；
- 输入分辨率。

再次直接改变这些设置可以作为复现实验或扩展实验，但不能仅凭此声称新颖。

### 8.8 它的工程代价是否可接受

候选至少估计：

- 参数量；
- FLOPs；
- 峰值显存；
- 每 epoch 时间；
- 推理时间；
- 是否改变 checkpoint 兼容性；
- 是否需要新的依赖或数据标注。

如果创新只提高 0.1 个百分点，却让显存翻倍、速度降低 5 倍，你需要判断它是否符合论文目标，而不是只看 Dice。

## 9. “我现在能不能跑 AI 提供的创新点”：一张决策树

请按这个顺序判断，不要凭感觉。

```text
问题 1：我能画出输入、四级特征、四级输出和 loss 链路吗？
  否 -> 只补读 networks.py、EMCAD.forward、trainer.py 的对应段落
  是 -> 问题 2

问题 2：我知道候选改哪个类、哪个函数、哪一行附近吗？
  否 -> 要求 AI 给出精确文件、类、函数、形状和插入位置
  是 -> 问题 3

问题 3：我知道训练集、验证集、最终测试集的边界吗？
  否 -> 先核对 split，不能跑正式比较
  是 -> 问题 4

问题 4：我能用同一条命令复现 baseline，且知道 checkpoint 如何选择吗？
  否 -> 先建立 baseline 记录
  是 -> 问题 5

问题 5：候选是否只改变一个核心变量，并有失败判据？
  否 -> 退回候选设计
  是 -> 可以开始冒烟和代理实验
```

注意“可以开始”首先指：

1. 写候选说明；
2. 创建独立分支/worktree；
3. 做小张量前向、反向和 shape 检查；
4. 做固定预算的代理实验。

它不等于立刻提交 300 epoch、五个 seed 的完整训练。

## 10. 第一个候选应该怎样跑：四级实验阶梯

### 第 0 级：只读和基线确认

目标：确认不是路径、环境、数据或代码状态问题。

记录：

```text
Git commit：
Python/PyTorch/CUDA：
GPU：
数据清单哈希：
预训练权重哈希：
输入尺寸：
batch size：
epoch：
seed：
验证 split：
最终测试是否访问：必须为 false
```

### 第 1 级：小张量冒烟

建议至少检查：

- `[1,1,224,224]` 能否前向；
- 输出是否为 4 个 `[1,9,224,224]` logits；
- CE + Dice 是否为有限值；
- `loss.backward()` 是否有非零梯度；
- `model.train()` 和 `model.eval()` 是否按预期切换；
- 候选模块前后 shape 是否不变或按设计改变；
- 是否出现 NaN、Inf 或异常显存。

这一阶段不看 Dice，也不证明创新有效，只证明代码能工作。

### 第 2 级：固定代理实验

所有候选使用同一：

- 训练子集；
- 代理 epoch；
- batch size；
- 输入尺寸；
- 验证病例；
- seed；
- 资源上限。

代理实验只能淘汰明显无效或不稳定的候选。不能因为代理阶段领先就直接写论文。

### 第 3 级：完整开发实验

先使用一个预注册开发 seed 做完整训练。只有达到预设的相对 baseline 提升和资源约束，才跑第二个 seed。

建议比较：

```text
candidate_val_dice_percent(seed)
- baseline_val_dice_percent(same_seed)
= paired_delta_dice_pp
```

不要只比较候选的绝对分数，因为不同 seed 的训练波动可能掩盖真实差异。

### 第 4 级：双 seed 确认和冻结

同一候选 commit、同一配置、两个事先登记的不同 seed 都通过，才停止继续产生候选。然后冻结代码，再进行最终测试 seed。最终测试不能再成为搜索反馈。

## 13. “读代码”应该从被动阅读变成主动提问

每次打开一个类或函数，只问四个问题：

1. 它接收什么？
2. 它返回什么？
3. 它改变了哪个物理量或张量维度？
4. 它在训练、验证还是测试的哪个时间点被调用？

例如读 `LGAG.forward(g, x)` 时，不要先纠结每一层卷积的初始化；先写出：

```text
g：解码器上采样后的门控特征
x：编码器 skip 特征
输出：与 x 同空间尺寸、通常同通道数的门控 skip
作用：决定 skip 的哪些信息进入后续融合
调用位置：EMCAD.forward 中，与 d3/d2/d1 融合之前
```

这已经足够你判断“一个新的 skip 可靠性模块”应该放在哪里。若候选真的要改 LGAG 内部，再深入读卷积、分组和激活。

## 14. 什么时候必须暂停开跑，继续读代码或先修基础设施

下面任何一项成立，都不要做正式创新比较：

### 14.1 你不知道指标是怎么来的

如果你不知道 Dice 是对切片还是病例算、是否去掉背景、空类别怎样处理、是 0-1 还是百分数，那么任何“提升 0.5”都没有可靠含义。

### 14.2 你不知道 best checkpoint 用了哪个集合

如果训练每轮看最终测试集并选 best，必须先修。否则候选排名会混入测试集适应。

### 14.3 你不知道候选输出能否接到后续层

只要通道和空间尺寸还没有画清楚，就不能直接改 decoder。先做 shape ledger 和随机张量测试。

### 14.4 你无法复现 baseline

不能复现 baseline 时，候选和基线的差异可能来自环境、权重、split、seed 或旧文件覆盖，而不是创新点。

### 14.5 你需要同时改五六个超参数才能“让它工作”

这通常说明候选假设还没有被隔离。可以把配套改动写成一个机制，但必须重新建立同配置 baseline，不能只给候选特殊待遇。

### 14.6 你发现了用户未提交修改或不明来源文件

不要用 reset、clean、checkout 覆盖。先记录状态，确定文件归属后再继续。

## 15. 什么时候可以只做小实验，什么时候可以做完整训练

### 可以立刻做小实验的情况

- 输入输出契约已知；
- 候选插入点明确；
- 可以运行一个 batch 的前向和反向；
- 不会访问最终测试集；
- 有独立 worktree；
- 失败时可以删除整个候选 worktree 而不影响 baseline；
- 预算和日志目录已定义。

### 可以做单 seed 完整训练的情况

- baseline 已有可复现记录；
- validation split 已固定；
- 候选只改变一个核心变量；
- 冒烟测试通过；
- 代理实验没有明显 NaN、OOM 或退化；
- checkpoint 和 resume 行为已知；
- 有明确的淘汰规则。

### 可以做双 seed 确认的情况

- 第一个 seed 的提升不是由资源配置变化造成；
- 参数、FLOPs、HD95 等约束已检查；
- 第二个 seed 在候选开始前已经预注册；
- 代码 commit 和配置冻结；
- 两次之间没有根据结果调参。

### 可以做最终测试的情况

- 候选已经停止开发；
- Git commit、配置、评价代码和病例清单冻结；
- 最终测试 seed 已预注册；
- 测试结果不会再喂给搜索器；
- 你准备报告全部运行和失败病例。

## 17. 最后给你一条可以长期使用的原则

面对任何基础模型，都可以用下面这句话判断自己是否该停止泛读：

> **当我能够在不看代码的情况下，画出一次数据从输入到预测再到 loss 的路径；能够指出候选改动的精确插入点和张量形状；能够用固定 split、固定 seed 和固定 baseline 判断候选成败时，我就已经读到可以开始实验的程度。**

“完全吃透项目”是长期目标，不是实验启动条件。真正高效的科研节奏是：

```text
最小充分理解
  -> 小实验
  -> 观察具体问题
  -> 定向读代码
  -> 完整实验
  -> 消融和论文解释
```

你现在最应该做的不是再打开一个新文件继续通读，而是先完成 12 项检查表，建立一条可信 baseline，然后让第一个候选接受冒烟测试。只要候选失败，失败本身也会告诉你下一段代码应该读哪里；这比无目标地继续阅读更快，也更接近真正的研究。
