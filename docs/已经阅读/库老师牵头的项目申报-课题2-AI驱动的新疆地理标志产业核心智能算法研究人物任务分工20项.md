# 课题2人物任务分工建议（20项）

> 依据文件：`课题2-AI驱动的地理标志产业核心智能算法与数据协同计计算体系研究.docx`
>
> 设计原则：任务名称略作抽象，便于写入申报书、任务书或责任矩阵；每个名称均控制在10个汉字以内。20项任务合起来覆盖课题要求的需求分析、数据治理、AI感知、协同计算、可信溯源、风险预警、预测调度、系统集成、示范应用和成果验收。

## 二、人物与任务的责任边界

### 1. 库尔班·吾布力：课题技术与算法主牵引

建议重点负责：

- 总体架构统筹；
- 需求场景凝练；
- 多场景感知模型；
- 多源融合与模型优化；
- 产量预测、品质识别和市场需求预测；
- 风险特征建模；
- 调度算法与算法服务化；
- 跨单位研发成果汇总和技术验收。

定位是把课题目标转化为可训练、可评测、可部署的算法与服务，避免算法研究与业务应用脱节。

### 2. 吾守尔·斯拉木：总体技术、协同计算与标准支撑

建议重点负责：

- 总体技术路线和架构把关；
- 数据规范、接口规范和质量评价体系；
- 联邦学习、隐私计算和安全聚合方向指导；
- 可信存证、数据安全和分布式协同技术把关；
- 技术标准、科研条件和重大资源协调。

定位是保证课题的技术先进性、体系完整性和跨单位协同的规范性。

### 3. 张艺馨：业务数据与真实产业场景牵引

建议重点负责：

- 需求场景凝练；
- 数据资源盘点；
- 业务专题库协建；
- 产量、品质和市场数据提供；
- AI模型真实场景验证；
- 风险案例、市场需求和供应链运行反馈；
- 核心产区示范和应用推广。

定位是保证模型和系统有真实数据、有业务问题、有应用场景、有可核验效果。

### 4. 侯青兰：软件工程、平台集成与部署实施

建议重点负责：

- 可信溯源平台协同；
- 算法模型工程化封装；
- API、软件系统和调度系统开发；
- 部署、运维、性能优化和技术支持；
- 系统联调、兼容性测试和问题整改；
- 配合课题三完成平台集成。

定位是把算法和方法转化为稳定、可调用、可部署、可维护的软件组件。

### 5. 周晓诚：知识产权与标准成果保障

建议重点负责：

- 专利和软件著作权挖掘；
- 申请材料审查与流程推进；
- 技术标准和成果规范咨询；
- 核心技术秘密登记；
- 成果权益分配和知识产权风险审查；
- 验收阶段成果证明材料整理。

定位是保证技术成果能够形成权利化、标准化、可保护和可验收的成果包。

## 三、20项任务如何闭环完成课题要求

### 第一阶段：需求和数据底座

对应任务1—5，解决“做什么、用什么数据、按什么规范做”的问题：

```text
总体架构统筹
  -> 需求场景凝练
  -> 数据资源盘点
  -> 数据规范设计
  -> 业务专题库形成
```

主要支撑：课题一数据资产承接、业务专题库建设、统一数据契约和接口对接。

### 第二阶段：AI感知与协同计算

对应任务6—12，解决“如何识别、如何预测、如何在数据不出域条件下联合建模”的问题：

```text
感知模型研发
  -> 模型融合优化
  -> 产量与品质建模
  -> 风险特征构建
  -> 协同计算设计
  -> 隐私机制验证
```

主要支撑：不少于6类AI感知场景、平均准确率不低于90%、联邦学习、隐私计算、安全聚合、权限控制、模型审计和异常更新识别。

### 第三阶段：可信溯源与智能决策

对应任务13—16，解决“如何留存可信证据、识别产业链风险并优化供需决策”的问题：

```text
可信存证设计
  -> 溯源平台协同
  -> 风险识别与预警支撑
  -> 需求预测建模
  -> 调度策略优化
```

主要支撑：不少于5类关键数据哈希上链、可信查询、供应链风险预警准确率不低于80%、市场需求预测准确率不低于75%、调度成本优化不低于15%。

### 第四阶段：工程化、示范与验收

对应任务17—20，解决“能否部署、能否验证、能否推广、能否形成成果”的问题：

```text
系统工程实现
  -> 联调测试验证
  -> 示范应用推广
  -> 成果知识产权
```

主要支撑：课题三平台集成、核心产区示范、软件系统交付、测试报告、专利、软件著作权、技术规范和终期验收。
