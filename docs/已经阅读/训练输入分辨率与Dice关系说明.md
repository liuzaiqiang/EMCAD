# 训练输入分辨率与 Dice 关系说明

## 结论

在当前 EMCAD-Synapse 实现中，`img_size=256` 的 Dice 高于 `img_size=224` 是合理且常见的现象，但不能据此得出“输入越大一定越好”，也不能单独证明某个新增模块有效。

这里的 `img_size` 同时影响训练、验证和最终测试，实际上形成了两套不同的实验协议：

- EMCAD-224：训练缩放到 224，验证缩放到 224，测试缩放到 224。
- EMCAD-256：训练缩放到 256，验证缩放到 256，测试缩放到 256。

主比较必须使用同一分辨率，例如 `DG-224` 只能和 `EMCAD-224` 比，不能拿 `DG-256` 和 `EMCAD-224` 直接比较。

## 代码依据

1. 训练参数在 [`train_synapse.py`](../train_synapse.py) 中由 `--img_size` 读取。
2. 训练数据的 `RandomGenerator(output_size=[args.img_size, args.img_size])` 位于 [`trainer.py`](../trainer.py) 第 119-122 行，最终调用 [`utils/dataset_synapse.py`](../utils/dataset_synapse.py) 第 74-90 行：图像使用三次插值缩放，标签使用最近邻插值缩放。
3. 验证调用 [`trainer.py`](../trainer.py) 第 80-85 行，把 `args.img_size` 传入 `val_single_volume`。
4. 最终测试调用 [`test_synapse.py`](../test_synapse.py) 第 206-209 行，把 `patch_size=[args.img_size,args.img_size]` 传入 `test_single_volume`。
5. 测试函数在 [`utils/utils.py`](../utils/utils.py) 第 531-535 行把原始切片缩放到网络输入大小，前向后在第 561-565 行用最近邻插值恢复到原切片大小，再计算病例指标。

因此，测试脚本的 `img_size` 也必须与训练该 checkpoint 时的 `img_size` 一致，才是标准的同分布评估。

## 为什么 256 可能更高

### 1. 小目标和边界保留了更多像素

如果原始 Synapse 切片大于 256，缩放到 224 会比缩放到 256 更强地下采样。小器官、细长结构和边界在 224 网格中可能只剩少量像素，容易出现边界量化误差；256 通常能保留更多可用空间信息。

### 2. EMCAD 的层级特征图也变大

PVTv2-B2 的四级特征大约是输入的 `1/4、1/8、1/16、1/32`。因此，理想整除情况下：

| 输入 | 1/4 特征 | 1/8 特征 | 1/16 特征 | 1/32 特征 |
|---|---:|---:|---:|---:|
| 224 | 56x56 | 28x28 | 14x14 | 7x7 |
| 256 | 64x64 | 32x32 | 16x16 | 8x8 |

EMCAD 解码器从这些特征逐级恢复。256 在浅层解码阶段有更密集的 64x64 网格，边界定位通常更有利；224 的最深特征只有 7x7，空间量化更粗。

### 3. 但 256 不会创造新的医学信息

代码只是对同一原始切片进行插值。若原始图像本身分辨率不足，256 可能主要是插值后的像素，并不等于获得了新的解剖细节。因此收益来自更合适的采样网格和网络表示能力，而不是凭空增加信息。

### 4. Dice 对边界误差很敏感

Synapse 中部分器官面积较小。少量边界像素的错分会显著改变 Dice。更大的输入网格有时能减少边界错分，所以平均 Dice 上升；但不同器官的变化可能不一致，必须查看逐器官 Dice、HD95 和 ASD。

## 计算和训练代价

从 224 到 256，二维像素数比例为：

`(256 / 224)^2 ≈ 1.306`

所以单次前向的空间计算量和激活显存通常会增加约 30% 左右，实际增幅还取决于 PVT 注意力和实现细节。训练速度可能下降，显存不足时可能被迫减小 batch size。若 224 和 256 的 batch size 不同，结果不能简单归因于分辨率。

## 公平实验规则

对 EMCAD 基线和改进模型分别做完整配对：

```text
EMCAD-224: train 224 -> val 224 -> test 224
改进模型-224: train 224 -> val 224 -> test 224

EMCAD-256: train 256 -> val 256 -> test 256
改进模型-256: train 256 -> val 256 -> test 256
```

除 `img_size` 或“是否加入该单一模块”外，固定：数据划分、预训练权重、seed、epoch、优化器、初始学习率、weight decay、监督方式、类别数和 checkpoint 选择规则。至少报告 3 个 seed 的均值和标准差。

真正评价模块的量应为：

```text
模块收益@224 = 改进模型-224 - EMCAD-224
模块收益@256 = 改进模型-256 - EMCAD-256
```

不能使用 `改进模型-256 - EMCAD-224` 作为模块收益，因为其中混入了分辨率收益。

## 如何解释你当前观察到的结果

- 如果 `EMCAD-256 > EMCAD-224`，说明当前数据和配置对更大输入网格更友好，这是分辨率效应。
- 如果 `DG-256 > EMCAD-256`，才说明在 256 协议下模块可能有额外收益。
- 如果 `DG-224 > EMCAD-224`，说明模块在 224 协议下也有效。
- 如果只有一次运行或只看某一轮的 `mean_dice`，不能下结论。应比较两次运行各自验证集上的 `best_dice`，并确认验证集、checkpoint、epoch 数和测试协议完全一致。
- 若训练用 224、测试脚本却传 256，程序通常可以运行，但这是跨分辨率测试，不应作为 224 模型的标准最终指标。

## 建议记录的指标

每个配置记录：`best Dice`、最终测试 Dice、IoU/Jaccard、HD95、ASD、每器官 Dice、参数量、FLOPs、单病例推理时间、峰值显存、batch size 和实际有效 optimizer steps。论文中把“分辨率对比”和“模块消融”分成两个表，避免把两种因素混在一起。
