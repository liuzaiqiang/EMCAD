# ACDC 与 Synapse 的创新点验证顺序建议

## 直接结论

建议采用：

```text
ACDC：快速筛查、检查代码和训练稳定性
Synapse：主要科学结论和论文核心对比
```

因此，可以先在 ACDC 上验证，不必一开始就等待完整 Synapse 实验结束。但 ACDC 上的结果只能说明模块“能够运行并在该数据集上有初步表现”，不能证明它一定适用于 Synapse。

## 为什么先用 ACDC 合理

ACDC 的训练切片数量较少，通常比 Synapse 更快完成一个短实验，适合提前发现：

- 模块导入、forward 和反向传播错误；
- 输入输出通道或空间尺寸不匹配；
- loss 为 NaN、梯度爆炸或显存溢出；
- 加入模块后模型是否仍能正常下降；
- 参数量、显存和每 batch 时间增加多少；
- 模块是否完全没有学习作用。

这些问题如果直接在 Synapse 上发现，会浪费更长的训练时间。

## ACDC 不能替代 Synapse 的原因

两个数据集的任务并不相同：

| 项目 | ACDC | Synapse |
|---|---|---|
| 任务 | 心脏 MRI 三个前景结构分割 | 腹部 CT 多器官分割 |
| 类别数 | 4 类，含背景 | 9 类，含背景 |
| 结构特点 | RV、MYO、LV，形态和切片变化不同 | 多器官、尺度差异和边界关系不同 |
| 论文用途 | 快速筛查或跨数据集补充 | EMCAD 主实验更适合使用的核心数据集 |

例如，自适应多尺度解码模块在 ACDC 上表现一般，不一定说明它在 Synapse 的小器官、细边界或多尺度器官场景中无效；反过来，ACDC 上有效也不能保证 Synapse 上有效。

## 推荐的三阶段流程

### 阶段 0：单 batch 检查

先分别对 EMCAD baseline 和 EMCAD+模块执行极短训练，确认：

- 能完成至少一个 forward、loss、backward 和 optimizer.step；
- 输出通道为数据集要求的类别数；
- loss 是有限值；
- 没有显存溢出；
- 日志明确显示当前模型和实验目录。

### 阶段 1：ACDC 快速筛查

固定 baseline 和改进模型的：

- 数据划分；
- seed；
- `img_size`；
- batch size；
- learning rate、weight decay、监督策略；
- 验证频率和 checkpoint 选择方式。

只跑短实验，例如固定 5--20 个 epoch，或使用明确记录的 `max_train_batches`。此阶段主要观察训练是否稳定、loss 是否下降、验证 Dice 是否有合理趋势，以及资源开销是否可接受。

不要用短跑的最终 Dice 宣布“论文创新成功”或“创新失败”。短跑结果受随机初始化、学习率和尚未收敛影响很大。

### 阶段 2：Synapse 主验证

如果 ACDC 阶段没有结构性问题，再使用 Synapse 做完整公平对比。Synapse 的 baseline 与改进模型必须使用同一套训练和测试协议，并记录：

- best Dice、IoU/Jaccard、HD95、ASD；
- 参数量和 FLOPs；
- 单病例推理时间和显存峰值；
- 最佳 epoch；
- 完整配置和 checkpoint 路径。

Synapse 上的完整结果才是判断该模块是否值得作为论文主贡献的主要依据。

## 如何判断 ACDC 阶段是否值得继续

满足以下条件时继续 Synapse：

- baseline 和改进模型都能完整训练；
- 改进模型没有 NaN、崩溃或明显异常过拟合；
- 改进模型资源开销在可接受范围；
- 验证 Dice 至少没有明显、稳定地劣于 baseline；
- 模块的机制与 Synapse 的目标问题仍有明确关系。

若 ACDC 短跑略低于 baseline，不应立即判定失败；应先完成一次同参数的较长 ACDC 对比或直接进入 Synapse 小规模筛查。若多个固定 seed、较长训练和完整评估都稳定劣于 baseline，才有较强证据说明模块不适合继续。

## 论文中的正确定位

最稳妥的论文实验安排是：

```text
Synapse：EMCAD 与 EMCAD+模块的主结果、消融和资源分析
ACDC：跨数据集泛化实验或补充实验（有预算时加入）
```

如果论文只报告 ACDC 而你的创新动机、主要比较对象和 EMCAD 复现实验都围绕 Synapse，审稿人可能会认为验证范围不足。ACDC 适合省时间地筛掉明显不可行的实现，不适合替代最终目标数据集。
