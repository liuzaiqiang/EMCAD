# 模型训练时已经在调参，验证阶段还要调参吗？

## 一句话结论

训练阶段主要是用训练集更新模型参数；验证阶段通常不直接更新模型参数，而是用一份没有参与梯度更新的数据，判断当前模型是否泛化得更好，并据此选择超参数、保存 `best.pth`、决定是否早停。

所以，“验证阶段会不会调参”的准确答案是：

> **验证循环本身通常不反向传播、不修改权重；但验证结果会被用来调整超参数和选择模型。**

这两件事必须区分：

- 模型参数：网络通过反向传播学到的卷积核、权重、偏置；
- 超参数：学习率、batch size、weight decay、网络深度、数据增强、损失权重、训练轮数等；
- 模型选择：在不同 epoch 保存的权重中选择验证集表现最好的一份。

## 一、训练阶段到底在调什么参数

### 1. 模型参数

例如 EMCAD 网络中的卷积核、线性层权重和偏置。训练步骤通常是：

```text
训练集 batch
  -> 前向传播
  -> 计算 loss
  -> 反向传播得到梯度
  -> optimizer.step() 更新模型参数
```

这一过程的目标是让训练集上的损失下降。模型参数由训练集直接提供梯度信号。

### 2. 超参数

超参数不是通过普通反向传播自动学出来的，通常由研究者在多轮实验中设定或搜索，例如：

- 初始学习率 `base_lr`；
- `weight_decay`；
- batch size；
- 训练 epoch 数；
- 学习率调度器；
- 数据增强强度；
- Dice、CE 或其他损失项的权重；
- 输入尺寸；
- 网络宽度、深度和模块开关；
- DataLoader worker 数和缓存策略。

“训练时调参”在严格意义上通常不是每个 batch 临时改学习率，而是运行多个训练实验，用验证集结果比较不同超参数组合。

## 二、验证阶段到底在做什么

验证阶段通常执行以下动作：

1. 切换到 `model.eval()`；
2. 关闭梯度计算，例如使用 `torch.no_grad()`；
3. 把验证图像送入模型；
4. 计算 Dice、IoU、HD95、Sensitivity 等指标；
5. 记录本轮验证结果；
6. 和历史最好结果比较；
7. 必要时保存 `best.pth` 或触发早停。

验证阶段的核心问题不是“模型还能不能继续记住训练集”，而是：

> **当前权重在没有参与本轮梯度更新的数据上，表现是否更好？**

## 三、为什么验证时不应该正常更新权重

如果把验证集也用于反向传播，模型就会逐渐适应验证集。此时验证分数会越来越好，但这个分数不再代表真正未见数据上的泛化能力。

典型正确写法是：

```python
model.eval()
with torch.no_grad():
    for images, labels in val_loader:
        logits = model(images)
        metric = dice_score(logits, labels)
```

这里 `no_grad()` 的作用是节省显存并防止构建反向传播图；`eval()` 的作用是让 Dropout 关闭、BatchNorm 使用已经累积的统计量。它们都不等于“模型没有任何状态变化”的绝对保证，因此仍要留意自定义层是否在 forward 中修改状态。

验证集上的 loss 或 Dice 可以被读取、记录和比较，但不能像训练 batch 一样调用 `loss.backward()` 和 `optimizer.step()`。

## 四、验证结果会参与哪些“调参”

### 4.1 选择当前训练过程中的最佳 epoch

例如：

| Epoch | Train loss | Val Dice | 是否保存 |
|---:|---:|---:|---|
| 1 | 0.42 | 0.71 | 保存 `best.pth` |
| 10 | 0.21 | 0.79 | 覆盖 `best.pth` |
| 20 | 0.12 | 0.78 | 不覆盖 |
| 30 | 0.08 | 0.76 | 不覆盖 |

最终使用 epoch 10 的权重，而不是最后一个 epoch 的权重。这叫 **checkpoint selection**，不是验证阶段反向调权重。

### 4.2 早停

如果验证 Dice 连续若干轮没有提升，可以停止训练：

```text
best_val_dice = 0.80
连续 30 个 epoch 没有超过 0.80
-> 停止训练
-> 恢复 best.pth
```

早停中的“耐心值” `patience` 是超参数，需要通过实验确定，不能因为某一次验证波动就随意停止。

### 4.3 比较不同超参数实验

例如分别运行：

```text
实验 A：lr=1e-4，weight_decay=1e-4
实验 B：lr=3e-4，weight_decay=1e-4
实验 C：lr=1e-4，weight_decay=1e-5
```

每个实验内部都只用训练集更新模型，用验证集比较泛化性能。验证集结果帮助研究者选择下一轮超参数，但验证循环本身不修改模型权重。

### 4.4 调整决策阈值或后处理

二分类分割中可能要选择 sigmoid 阈值 0.3、0.5 或 0.7；还可能比较去除小连通域、孔洞填充或 CRF 等后处理。只要这些选择依据验证集完成，就仍然属于模型选择或超参数选择。

## 五、验证集、测试集和训练集的分工

| 数据集 | 是否参与梯度更新 | 是否可以反复比较 | 主要用途 |
|---|---|---|---|
| 训练集 | 是 | 是 | 学习模型参数 |
| 验证集 | 否 | 可以，但要有记录和边界 | 选超参数、选 epoch、早停、调阈值 |
| 测试集 | 否 | 原则上只在最终阶段使用一次 | 报告最终泛化性能 |

### 关键边界

验证集虽然不参与反向传播，但它参与模型选择，所以也不是“完全没用过的数据”。如果反复根据验证集改网络、改增强、改损失，最终验证分数可能也会被逐渐过拟合。

因此研究中常见做法是：

1. 固定训练/验证/测试划分；
2. 只在训练和验证阶段开发；
3. 方案冻结后，用测试集做最终一次评估；
4. 测试集结果不要反过来指导已经完成的方案。

## 六、什么叫验证集泄漏

以下行为会污染测试结论：

- 每个 epoch 用官方测试集选择 `best.pth`；
- 看完测试集 Dice 后继续改网络和超参数；
- 先在多个测试集结果中挑最高的一个再报告；
- 根据测试集失败病例修改数据预处理后重新测试；
- 把同一患者的不同切片拆到训练集和测试集；
- 先用全数据计算归一化统计量，再划分数据。

这里的“泄漏”不一定是把标签直接放进训练代码。只要测试集结果影响了模型或实验决策，测试集就已经参与模型选择。

## 七、当前 EMCAD 仓库里的具体情况

### 7.1 `train_acdc.py`

该脚本的代码路径是：

```text
训练 DataLoader
  -> model.train()
  -> 前向、loss、backward、optimizer.step()
  -> validate(...)
  -> model.eval() + no_grad()
  -> 计算病例级 mean Dice
  -> mean_dice >= best_dice 时保存 best.pth
```

代码中 `validate_every` 控制验证频率，`best_dice` 用于选择最佳 checkpoint，并把验证明细写入 `validation_metrics.csv`。这属于规范的“验证选模型”流程。

### 7.2 `train_polyp.py`

该脚本也维护 `best_dice` 和 `best_epoch`，在验证 Dice 提升时保存 `best.pth`，同时写入 `best_validation.json`。它还允许通过 `validate_every` 控制每隔多少 epoch 验证一次。

### 7.3 `trainer.py` 的重要风险

`trainer.py` 中的 `inference()` 使用：

```python
Synapse_dataset(..., split="test_vol", ...)
```

然后每个 epoch 计算宏平均 Dice，并用它决定是否覆盖 `best.pth`。代码注释已经指出：`test_vol` 到底是验证集还是官方测试集，取决于你的实际列表划分。

- 如果 `test_vol` 实际存放的是验证病例：可以把它理解为验证流程；
- 如果 `test_vol` 是官方测试集：每个 epoch 用它选 `best.pth`，会造成测试集参与模型选择，最终测试结果偏乐观。

因此不能只看变量名 `test_vol` 就断言它是测试集，也不能只看日志里写了 `val model` 就断言它是验证集。必须检查 `list_dir` 下的病例清单和论文/数据集划分说明。

## 八、一个完整实验应该怎样调参

### 阶段 A：固定数据划分

- 按患者或病例划分，而不是随机切片划分；
- 固定 `train.txt`、`val.txt`、`test.txt` 或等价 manifest；
- 记录每份清单的 SHA256；
- 测试集完全封存。

### 阶段 B：小规模筛选

先用少量 epoch、固定随机种子和固定预算比较学习率、batch size、损失权重等。此时只根据验证集做选择。

### 阶段 C：完整训练

对筛选出的少数方案使用完整 epoch 和完整训练集，保存：

- 配置文件；
- commit 或代码版本；
- 随机种子；
- 训练日志；
- 每 epoch 验证指标；
- `best_epoch` 和 `best_val_dice`；
- 最终 checkpoint。

### 阶段 D：冻结方案后测试

只选择已经确定的 `best.pth`，在测试集上运行一次完整评估，报告 Dice、HD95、每病例结果和置信区间。测试集结果不再用来修改方案。

## 九、常见误解

### 误解 1：验证集不训练，所以验证集不重要

错误。验证集决定你选哪一个 epoch、哪组超参数和哪种后处理，是实验决策的核心数据。

### 误解 2：验证 Dice 最高的模型一定是真实最强模型

不一定。验证集有限，存在随机波动和过拟合。应固定划分、报告多次运行或置信区间，并最终用独立测试集评估。

### 误解 3：最后一个 epoch 一定比 best epoch 好

不一定。训练集 loss 继续下降时，验证集性能可能已经下降，这就是过拟合。科研实验通常保留 `best.pth` 和 `last.pth`，分别表示最佳验证模型和训练终点模型。

### 误解 4：只要用了 `model.eval()` 就完成了验证

不够。还要确认没有梯度更新、数据划分正确、指标计算正确、病例级聚合方式合理，并且没有把测试集拿来选模型。

### 误解 5：验证阶段可以随便改学习率

可以设计动态策略，但必须说清楚它是什么：例如 ReduceLROnPlateau 根据验证指标调整学习率。这种情况下，验证指标会间接影响后续训练，但仍然不是在验证 batch 上反向传播更新网络权重。它还会增加超参数和实验记录要求。

## 十、给你的实际记忆框架

可以把训练过程记成下面这句话：

> **训练集负责“学”，验证集负责“选”，测试集负责“验”。**

更严格一点：

- 训练集：更新模型参数；
- 验证集：选择 epoch、超参数、阈值和后处理；
- 测试集：在方案冻结后估计最终泛化性能。

如果你在验证集上反复改方案，验证集也会逐渐被“用熟”；如果你用测试集选模型，测试集就已经不是真正独立的最终检验。
