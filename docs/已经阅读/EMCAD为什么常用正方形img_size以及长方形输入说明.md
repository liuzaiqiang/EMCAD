# EMCAD 为什么常用正方形 `img_size`，长方形输入是否可行

## 1. 直接结论

**长方形输入不是原理上不行。** EMCAD、PVTv2 编码器、卷积、注意力和上采样等主要模块都能处理形如 `(H, W)` 且 `H != W` 的特征图。

但是，当前仓库把 `img_size` 定义成了一个整数，并在数据预处理和测试代码中反复写成：

```python
(img_size, img_size)
```

或：

```python
[args.img_size, args.img_size]
```

因此，**当前训练和测试入口在工程实现上默认只提供正方形输入**。要使用 `224×320` 等长方形尺寸，需要同时修改参数定义、数据预处理和测试恢复逻辑，不能只把命令行写成两个数。

此外，本项目网络输出使用固定的 `4、8、16、32` 倍上采样。为了避免预测图和标签尺寸错位，长方形输入的**高度和宽度最好都能被 32 整除**，例如：

```text
224 × 320：可以考虑，224 和 320 都能被 32 整除
256 × 320：可以考虑，256 和 320 都能被 32 整除
192 × 320：可以考虑，192 和 320 都能被 32 整除
224 × 300：当前实现不推荐，300 不能被 32 整除
```

## 2. `img_size=224` 在当前代码中是什么意思

以 Synapse 和 ACDC 为例，参数定义类似：

```python
parser.add_argument('--img_size', type=int, default=224,
                    help='input patch size of network input')
```

这里的 `type=int` 表示命令行只接收一个整数。后续代码再把这个整数复制两次：

```python
RandomGenerator(output_size=[args.img_size, args.img_size])
```

于是：

```text
--img_size 224 → output_size=[224, 224]
--img_size 256 → output_size=[256, 256]
```

因此代码中的 `img_size=224` 实际等价于：

```text
输入高度 H = 224
输入宽度 W = 224
```

它并不代表网络数学上只能处理正方形，只是当前参数接口用一个数同时控制两个方向。

## 3. 为什么研究代码普遍喜欢 `224×224、256×256、352×352`

### 3.1 一个整数配置更简单

只需要记录：

```bash
--img_size 224
```

数据加载、显存估算、batch 拼接、实验命名和模型复杂度统计都更方便。如果允许任意长宽，就需要分别管理 `img_height` 和 `img_width`。

### 3.2 同一个 batch 中的张量必须能堆叠

PyTorch 的普通 DataLoader 要把多张图像组成：

```text
(B, C, H, W)
```

同一批图像必须具有相同的 `H、W`。统一缩放成固定正方形，是最简单的批处理方案。

注意：这并不意味着固定尺寸必须是正方形。统一成固定的 `224×320` 也能组成 batch，只是当前代码没有提供这个接口。

### 3.3 与常见预训练设置和论文基准保持一致

许多 ImageNet 预训练模型和视觉论文习惯使用 `224×224`，医学分割论文也常选 `224×224、256×256、352×352` 等统一尺寸。这样更容易：

- 加载预训练权重；
- 复现原论文；
- 比较参数量、FLOPs、速度和显存；
- 与其他方法进行公平对照。

PVTv2 本身并不是只能接受 `224×224`。仓库 `lib/pvtv2.py` 中实际前向过程会根据输入张量得到当前的 `H、W`；构造函数里的 `img_size=224` 更多是元数据和原始实现习惯。

### 3.4 正方形适合随机旋转增强

当前 Synapse、ACDC 等数据增强包含 `90°` 倍数旋转。正方形旋转 90° 后形状仍然是：

```text
224 × 224 → 224 × 224
```

长方形旋转 90° 后则会交换长宽：

```text
224 × 320 → 320 × 224
```

虽然之后还可以重新缩放、裁剪或填充，但增强流程会更复杂；如果直接强制拉回 `224×320`，还可能产生新的几何变形。

### 3.5 多级下采样对规则尺寸更友好

PVTv2 编码器会逐级下采样，最深层大致达到输入的 `1/32`。正方形不是关键，真正关键的是高、宽要与多级步幅兼容。

例如：

```text
224 × 224 → 112 → 56 → 28 → 14 → 7（概念上逐级缩小）
256 × 256 → 128 → 64 → 32 → 16 → 8
224 × 320 → 最深层约为 7 × 10
```

`224×320` 虽然是长方形，但两个方向都能被 32 整除，所以各级特征更容易严格对齐。

## 4. 当前 EMCAD 模型本身能不能接收长方形

从主体结构看，可以。

### 4.1 卷积不要求高宽相等

`Conv2d` 接收的是：

```text
(B, C, H, W)
```

并没有要求 `H == W`。因此 `224×320`、`256×384` 等形状都能进行卷积。

### 4.2 PVTv2 前向会使用实际的 H 和 W

PVTv2 在前向传播中会根据卷积输出获得当前特征图高、宽，再将 token 恢复为空间特征。它不是只能处理固定的 `224×224`。

### 4.3 EMCAD 解码器也不要求正方形

EUCB 的两倍上采样会同时把高、宽扩大两倍：

```text
7 × 10 → 14 × 20
```

LGAG、CAB、SAB、MSCB 等模块主要要求相互融合的特征尺寸能够对应，并不要求高宽相等。

所以，限制主要来自当前的数据管线和尺寸对齐写法，而不是“EMCAD 理论上只能看正方形”。

## 5. 为什么高和宽最好都能被 32 整除

当前 `lib/networks.py` 中四个预测头使用：

```python
p4 = F.interpolate(p4, scale_factor=32, mode='bilinear')
p3 = F.interpolate(p3, scale_factor=16, mode='bilinear')
p2 = F.interpolate(p2, scale_factor=8, mode='bilinear')
p1 = F.interpolate(p1, scale_factor=4, mode='bilinear')
```

这里没有直接指定：

```python
size=x.shape[-2:]
```

而是把低分辨率特征固定放大若干倍。因此代码隐含假设：编码器下采样后的尺寸乘回 `4、8、16、32`，能够精确恢复输入高度和宽度。

如果输入是 `224×320`：

```text
224 / 32 = 7
320 / 32 = 10
最深层约为 7×10
7×32=224，10×32=320
```

可以精确还原。

如果输入是 `224×300`，宽度经过带步幅卷积和取整后，最深层宽度不一定满足：

```text
最深层宽度 × 32 = 300
```

固定放大后可能得到 320 或其他尺寸，进而导致：

- 预测和标签形状不同；
- 计算 loss 时 size mismatch；
- 解码器特征与跳跃连接无法相加；
- 测试结果恢复到原图时产生额外插值偏差。

因此，在不修改模型上采样逻辑的情况下，建议：

```text
H % 32 == 0
W % 32 == 0
```

## 6. 为什么把原始长方形直接缩放成正方形可能有问题

假设原图是：

```text
512 × 768，宽高比为 1.5
```

当前代码如果直接 `Resize((224, 224))`，会把宽高比变成 1，图像被横向压缩或纵向拉伸。器官、病灶和边界的几何形态也会一起变形。

分割任务中，这种变形可能影响：

- 器官的真实形态比例；
- 小病灶面积；
- 边界曲率；
- HD95 等距离指标；
- 模型对真实临床图像比例的泛化能力。

不过，如果原论文和基线都统一使用相同的正方形预处理，那么复现实验仍应优先保持一致。不能只为一个创新实验改成长方形，再直接与原正方形基线比较，否则输入信息量和预处理策略都发生了变化。

## 7. 长方形输入的三种处理方式

### 方案一：直接缩放到固定长方形

例如统一为：

```text
224 × 320
```

优点：

- 实现相对简单；
- 可以组成固定 batch；
- 如果目标比例接近原图，形变小于强制正方形。

缺点：

- 不同原图比例仍可能发生变形；
- 需要修改当前单整数 `img_size` 接口；
- 90° 旋转增强需要重新考虑。

### 方案二：保持宽高比缩放，再 padding

把原图按比例缩放到目标框内，不足区域补零或补背景：

```text
保持比例缩放 → 放入 224×320 画布 → 空白区域 padding
```

优点：

- 不会拉伸器官和病灶；
- 固定输出尺寸，仍可批处理。

缺点：

- padding 区域可能占用较多计算；
- mask 必须使用背景类别填充；
- 预测恢复时要先去掉 padding，再缩放回原尺寸。

这通常比无条件拉伸更符合医学图像的几何真实性。

### 方案三：裁剪或滑动窗口

保持原始分辨率或比例，裁成固定 patch，例如：

```text
224 × 320 patch
```

测试时使用重叠滑动窗口并融合预测。

优点：

- 保留更多局部细节；
- 适合大尺寸图像和小病灶。

缺点：

- 可能丢失全局上下文；
- 测试与拼接逻辑更复杂；
- patch 重叠区域需要平均或加权融合。

## 8. 当前仓库要支持长方形，需要改哪些地方

不能只改一处。至少需要系统检查以下位置。

### 8.1 参数定义

可把一个参数拆成两个参数：

```python
parser.add_argument('--img_height', type=int, default=224)
parser.add_argument('--img_width', type=int, default=320)
```

或者让 `img_size` 接收两个整数：

```python
parser.add_argument('--img_size', type=int, nargs=2,
                    default=[224, 320])
```

### 8.2 训练数据预处理

把：

```python
[args.img_size, args.img_size]
```

改为：

```python
[args.img_size[0], args.img_size[1]]
```

Polyp、ISIC、BUSI 的 `Resize` 也要把 `height` 和 `width` 分开传递。

### 8.3 标签插值方式

连续图像可以使用双线性或三次插值，离散类别 mask 应使用最近邻插值，避免产生不存在的类别值。

### 8.4 模型最终输出尺寸

更稳健的做法是记录模型输入尺寸：

```python
input_size = x.shape[-2:]
```

最后将所有预测头显式恢复到：

```python
F.interpolate(pred, size=input_size, mode='bilinear', align_corners=False)
```

这样比依赖固定 `scale_factor` 更能兼容任意长宽。不过解码器内部的 skip 对齐仍需检查，必要时也应按目标特征的实际 `H、W` 插值。

### 8.5 训练和测试必须使用相同尺寸策略

如果训练使用 `224×320`，测试也应使用相同的输入尺寸和预处理方法。仅保证 checkpoint 能加载还不够，输入分布、缩放、padding 和恢复策略也必须一致。

## 9. 对当前 EMCAD 实验的建议

### 如果目标是复现原论文或建立可靠 baseline

继续使用该实验原本规定的正方形尺寸，例如 `224×224`。先确保训练、验证、测试和论文基准一致。

### 如果原始图像明显是长方形，而且拉伸变形严重

可以把长方形输入或等比例 padding 作为一个独立实验变量，例如：

```text
Baseline：224×224，直接 Resize
实验 A：224×320，直接 Resize
实验 B：224×320，保持比例 + padding
```

但三组实验需要保持：

- 相同数据划分；
- 相同随机种子；
- 相同训练轮数；
- 相同优化器和学习率策略；
- 相同模型结构参数；
- 相同 checkpoint 选择规则；
- 测试预测都恢复到原始图像尺寸后再计算指标。

还应注意：`224×320` 的像素数为 71680，而 `224×224` 为 50176，前者多约 42.9%。显存、FLOPs 和推理时间都会增加，因此这不是完全等计算量的比较。

## 10. 一句话记忆

> **EMCAD 并不要求图像必须是正方形；当前仓库使用正方形，是因为一个 `img_size` 同时控制高和宽、方便批处理和复现实验。长方形可以支持，但要成套修改数据管线和尺寸恢复代码，并优先让高、宽都能被 32 整除。**

## 11. 本次仓库核对依据

- `train_synapse.py`、`train_acdc.py`：`img_size` 被定义为单个整数。
- `utils/dataset_synapse.py`、`utils/dataset_ACDC.py`：变换器本身能接收 `[H,W]`，但调用方通常传 `[img_size,img_size]`。
- `utils/dataloader.py`、`utils/dataloader_polyp.py`：图像和 mask 被明确 Resize 到相同的正方形边长。
- `utils/acdc_utils.py`：测试切片被插值到 `(img_size,img_size)`，再将 logits 恢复到原始 `(height,width)`。
- `lib/networks.py`：四个预测头使用固定 `scale_factor=32/16/8/4` 恢复分辨率。
- `lib/pvtv2.py`：PVTv2 前向使用实际特征图的 `H、W`，并非只能接收正方形。
