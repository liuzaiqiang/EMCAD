# 像素级可靠性多头融合恢复与12数据集接入说明

## 1. 本次恢复的范围和依据

本次以修改前的 `7871f52` 为基线，恢复历史 `1f205a1`（try5）的像素级可靠性多头融合公式和多分类辅助监督。当前分支已有的内容感知抗混叠上采样（CAA）继续使用原实现。

用户报告早期融合、CAA 及其组合均能涨点；本次仅确认代码与所检查历史实现的一致性。尚未拿到那次成功运行的完整配置、环境和逐病例结果，因此不能把代码恢复等同于完全复现成功实验。本次版本的 Dice/HD95 效果尚未验证。

本次没有修改 `lib/decoders.py`、编码器、原有 `forward()`、四个分割输出头、数据划分、预处理、基础损失、优化器、调度器、随机种子、指标公式或 checkpoint 选择规则。融合打开时增加融合头、辅助损失，并在原验证/测试流程中使用融合 logits；这是该功能本身的预期变化。

## 2. 核心机制

原模型仍返回 `[p4,p3,p2,p1]`，四个张量均为已经双线性上采样到输入尺寸的 `[B,K,H,W]` logits。可靠性头读取这些 logits，**不读取解码特征**。

对每个头分别使用一个 `Conv2d(K,1,1)`：

```text
r_i = reliability_head_i(p_i)             # [B,1,H,W]
w = softmax(cat(r4,r3,r2,r1), dim=1)       # [B,4,H,W]
fused = w4*p4 + w3*p3 + w2*p2 + w1*p1    # [B,K,H,W]
```

每个像素的四个权重之和为1。同一位置不同类别共享该头的一个权重，不是每类另学一个权重。新增参数仅为 `4*(K+1)`：二分类8、ACDC20、Synapse40。

一个生活中的具体例子：四个人共同描图，每个人在不同位置擅长程度不同。融合头针对每个位置分配话语权；训练标签用来告诉每个人这个位置是否描对，推理时不再需要标签。

历史行为保持如下：

- 可靠性头使用普通随机卷积初始化，添加在全部原有层之后；没有零初始化、温度缩放、熵加权、权重上下限或额外平滑。
- 多分类正确性标签是各头的 argmax 是否等于训练真值；二分类是 sigmoid>=0.5 是否等于二值真值。
- 正确性标签停止梯度，但可靠性头输入 logits **不停止梯度**，BCE 会同时更新可靠性头和原分割网络。
- 验证、测试只计算预测可靠性与融合，不使用标签决定权重。验证标签仍只用于原指标和 checkpoint 选择流程。

## 3. 损失和历史版本差异

```text
L_total = L_original_supervision
          + FUSION_LOSS_WEIGHT * (L_fused_seg
              + RELIABILITY_LOSS_WEIGHT * L_correctness_BCE)
```

`mutation` 仍然计算原始四头15个非空子集的监督项，不替换成四项深监督、不归一化、不重加权。融合辅助项在原监督汇总后追加。

多分类融合辅助分割损失为 `0.3*CE + 0.7*Dice`。检查到的早期 try5 对融合辅助 Dice 直接传入原始 logits，后续版本曾改为 `softmax=True`。这两种代码的损失和梯度确实不同，但没有证据证明该差异就是后来不涨点的原因。

本次通过 `FUSION_DICE_SOFTMAX=0/1` 独立控制**融合辅助多分类 Dice**，默认0恢复早期 try5 的 raw-logit 行为。原基础 Dice 的概率化方式保持不变。raw-logit Dice 不是概率 Dice；保留它是为了复现实验，而非宣称它在理论上更优。

二分类融合辅助项使用 `0.3*BCEWithLogits + 0.7*sigmoid Dice`，Dice 分母为预测与标签的平方和，平滑项 `1e-5`。二分类基础 `structure_loss` 保持原样。二分类不受 `FUSION_DICE_SOFTMAX` 影响。

## 4. 参数隔离

| Shell参数 | 默认值 | 含义 |
|---|---|---|
| `USE_PIXEL_RELIABILITY_FUSION` | `0` | 核心融合开关，0关闭、1开启 |
| `USE_CONTENT_AWARE_ANTIALIAS` | 各脚本原值 | 独立CAA开关，0关闭、1开启 |
| `FUSION_MODE` | `pixel_reliability` | 开启后的融合方法 |
| `FUSION_LOSS_WEIGHT` | `1` | 整个融合辅助损失的系数 |
| `RELIABILITY_LOSS_WEIGHT` | `1` | 正确性BCE的系数 |
| `FUSION_DICE_SOFTMAX` | `0` | 多分类融合辅助Dice是否softmax |

核心开关为0时，Shell强制 `FUSION_MODE=p1`、辅助系数0；直接Python入口也通过核心开关强制使用p1。此时不创建融合参数，不消耗融合初始化随机数，仍选择最后一个原始输出p1。

CAA默认值未修改：Synapse/ACDC默认0，其余二分类共用启动链路默认1。为了避免混淆，实验时始终显式写两个开关。Polyp/BUSI/ISIC原Shell遗留的融合开关默认1，本次改为0，因为原当前模型没有融合功能；接入后默认0才能保持原当前分支的实际行为。

模式 `fixed_sum`（四头logits直接相加）、`global_scalar`（四个全局可学习权重）供融合消融使用，主方法是 `pixel_reliability`。模式为p1时没有融合辅助损失。打开像素融合却把 `FUSION_LOSS_WEIGHT=0` 会留下未受辅助训练的可靠性头，不是CAA基线；CAA基线必须使用核心开关0。

对应Python参数是 `--use_pixel_reliability_fusion`、`--fusion_mode`、`--fusion_loss_weight`、`--reliability_loss_weight`、`--fusion_dice_softmax`。

## 6. 服务器启动

保留原服务器环境、数据路径和已有运行参数。Synapse原脚本固定mutation；其他脚本如果你的已有实验使用mutation，继续显式传入 `SUPERVISION=mutation`。二分类脚本原默认为paper（四个单头+四头总和，共5项），它不等于mutation，本次没有改变该默认值。

```bash
# A：基础模型+CAA
USE_CONTENT_AWARE_ANTIALIAS=1 USE_PIXEL_RELIABILITY_FUSION=0 \
bash sh/start_train_synapse.sh

# B：基础模型+CAA+像素级可靠性多头融合，早期try5辅助Dice
USE_CONTENT_AWARE_ANTIALIAS=1 USE_PIXEL_RELIABILITY_FUSION=1 \
FUSION_DICE_SOFTMAX=0 FUSION_LOSS_WEIGHT=1 RELIABILITY_LOSS_WEIGHT=1 \
bash sh/start_train_synapse.sh

# ACDC：同样两个开关；0/1任选对应对照组
SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_PIXEL_RELIABILITY_FUSION=1 \
bash sh/start_train_acdc.sh

# 5个息肉数据集：依次替换ClinicDB为Kvasir、ColonDB、ETIS、BKAI
DATASET_NAME=ClinicDB SUPERVISION=mutation \
USE_CONTENT_AWARE_ANTIALIAS=1 USE_PIXEL_RELIABILITY_FUSION=1 \
bash sh/start_train_polyp.sh

SUPERVISION=mutation USE_CONTENT_AWARE_ANTIALIAS=1 USE_PIXEL_RELIABILITY_FUSION=1 \
bash sh/start_train_busi.sh

# ISIC2017 / ISIC2018
DATASET_NAME=ISIC2018 SUPERVISION=mutation \
USE_CONTENT_AWARE_ANTIALIAS=1 USE_PIXEL_RELIABILITY_FUSION=1 \
bash sh/start_train_isic.sh

# DSB18 / EM
DATASET_NAME=DSB18 SUPERVISION=mutation \
USE_CONTENT_AWARE_ANTIALIAS=1 USE_PIXEL_RELIABILITY_FUSION=1 \
bash sh/start_train_cell.sh
```

测试继续使用已有 `sh/start_test_<任务>.sh` 和 `CKPT=/绝对路径/best.pth`。`config.json` 必须与checkpoint一起保留；Shell测试入口通过原Python配置恢复流程自动恢复融合开关、模式和参数，也恢复原CAA选项。BUSI/ISIC最终进入 `test_polyp.main()`，在建模前恢复配置。Synapse直接调用Python时须像原Shell一样传入 `--train_config`。

显式Python测试参数若与保存的融合配置冲突会报错，不允许悄悄改变推理方式。旧配置有 `fusion_mode` 但无核心开关时按模式恢复；没有融合字段的旧配置按关闭处理。历史配置如果没有 `fusion_dice_softmax`，采用当前默认0；**无法仅凭缺失字段推断历史实际损失**，对旧实验的精确复现仍需查看当时代码。
